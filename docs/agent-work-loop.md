# 角色事项与歌唱执行闭环

实现日期：2026-09-10～11。依据 [Unity 日志评估](reviews/2026-09-10-singing-self-loop-review.md)。

9 月 11 日补充了完整听觉证据保留、任务来源核验、待审核发声控制及相同失败停止。最新实现与验证见 [说话转唱歌和复读修复](reviews/2026-09-11-speech-song-loop-fix.md)。

## 行为变化

角色提出检查或演唱后，后续决策持续接收最新工具事实和用户要求。歌唱录音目标在执行前接受独立语义审核，再由程序核对实际素材身份、顺序、范围和版本；播放结束只记录实际发生的结果。用户要求补回内容时，播完并不直接标记内容已经满足。

没有开放任意工程文件、脚本、凭据或反射写入权限。允许的素材变更继续经过已有 clip 修订与 sing 接口。独立审核仍是 LLM 的判断，结构检查与程序执行事实不能保证模型永远正确理解自然语言。

## 观察交付

- `BuildPerceptionFrame` 不再消费工具结果、修订结果和待交付通知。
- 正式流式、非流式、工具反馈和 continue 都附带新的观察与事项上下文。ChatQW 的反馈续接放在历史末尾，不制造一条新的用户发言。
- 正式请求持有本次观察的回执。只有有效的当前请求完成回复，且 user epoch 未变化，才确认对应结果已交付。新产生的同类结果不会被旧回执清掉。
- 每个回调只允许完成一次；continue 共用语音流水线时，旧一节的重复回调和迟到 delta 不会执行旧动作。
- 空生成、传输失败与角色显式选择 `<silent/>` 分开。自检交付连续失败最多尝试三次，保留结果并停止自动重试，状态为 blocked。
- 歌曲记忆的最终确认也保留结果至有效回执。异步结果保留原用户轮次，旧结果可作为新轮次的观察，但不会插入新对话强制确认；用户讲话或内部预判进行时先等待。非 Agent 模式保留结果，且不自动重复请求。
- 已有 provider 若未实现专用 feedback continuation，仍按其兼容回退行为处理历史；本项目的 ChatQW 已实现真实反馈消息路径。

## 歌唱目标

角色通过 `sing_goal` 声明草案，程序不会从 `reason` 或用户关键词补猜动作参数。目标包含 refs 顺序、range、输入 revisions、intent、完成条件以及必要的用户反馈引用。窗口目标另含原录音 start/end。

草案先登记为 pending。独立进度请求对照最新完整用户语句、前目标和真实播放事实，返回 approved / revise / waiting_user / cancelled。只有 approved 才允许根据目标演唱或准备目标素材范围；在同一回复中登记后立即发 sing 会被暂停，而不是先播放再核对。

审核还须独立返回 `singing_goal_expected`：origin、request_quote、有序 refs、range，以及精确窗口才需要的起止坐标。用户任务须有真实请求引文；自主提议按独立边界审核，用户演唱不自动建立回唱任务。程序将预期目标与实际草案及素材版本比较，口头 approved 但字段不一致时改为 revise。角色台词或审核理由里声称“expanded”不能代替字段核对。自然语言理解仍依赖模型。

独立审核不会仅因为草案和动作参数相同就通过。原用户事项和角色自主提议具有不同的归属；用户事项耗尽预算后不能改称自主提议继续尝试。

真正 sing 前校验：

1. 本用户轮目标已独立通过。
2. refs 顺序和实际 range/window 与目标一致。
3. 输入素材版本仍是审核时的版本。
4. 与用户明确否定的方案比较，避免原样重试。单纯改写 reason、intent 或增加 revision 不能充当内容修复。

这次目标校验覆盖录音 `clip` 的统一 sing 路径；曲库 `song` 与旧兼容执行入口没有因此获得完整的同类目标验收。不能将此实现描述成所有身体动作都已有统一目标检查。

内容修复比较音频身份与原录音窗口；音乐参数修复另比较实际音高/速度/表达参数，避免把合法调音封死。明确的新用户重唱请求，经独立核验后仍可重复演唱。

每个真实用户轮保留前目标和最近播放事实，用于理解“为什么”“检查技能”等追问；最新完整修正优先。新会话清除旧目标、审核与播放归属。角色在闲聊期间自主发起目标时走独立有限审核，不重新打开已结束的用户事项。

目标归属在同一真实用户轮内保持锁定；因此已有用户歌唱目标的轮次不会自动改成新的自主歌唱事项。新的真实用户输入重置该归属。这是当前保守边界。

## 结果与能力证据

来源确认、范围改变、排队、播放完成是不同事实。确认反馈不再用无作用域的 `played=false` 暗示历史从未播放。

`requestSubmitted` 表示角色提交过执行尝试，包括随后被校验拒绝的尝试；目标 pending 时暂停的动作只算等待，不设置该标记。它不能证明后台受理或正在播放。是否执行要同时看实际工作状态与失败结果。

播放回调记录实际 refs、revision 和 raw 窗口，再与准备时的目标窗口核对。播放错范围会留下不匹配状态。匹配时仍区分程序播完、内容待验收和用户明确认可；不能由角色自己声称成功来代替用户反馈。

runtime 自检还返回语音组件绑定、语音模式、歌唱开关与权限、详细 Skill 加载状态、是否提交请求、当前工作状态、最近播放和既有服务观察。健康观察带有时间/范围；没有观察值是 unknown，不是断线。读取快照不会启动服务或重新探测网络。

## 调度与诊断

- 进度审查使用独立 1024 token 预算和八字段 JSON schema（包含结构化预期目标），不再共用 128 token 的临时草稿预算。
- Local 使用已有 JSON schema 模式；Cloud 使用 JSON object 模式并验证相同字段约束。
- 缺字段、错误类型、截断、HTTP/传输失败不授予目标审批，走有限恢复。
- 进度日志记录返回状态、finish_reason、验证结果与耗时，不记录审核原文。
- 自检交付和目标审查使用直接定时，不被闲聊疲劳拉长。关闭闲聊预判也不会跳过必要的目标审核。
- 新用户输入、实际语音输出、在飞工具和关闭会话仍有取消与防重入保护。

将真实回复保存到隔离工程的 `Tools/MotionAdapter/reports/public-model-review.json` 后，`AgentSingingGoalRegression.ValidatePublicModelReviewBatch` 会验证导出文件 SHA、案例完整性、生产 schema 和实际目标比较结果。原始误批与程序纠正后的结果分开记录，缺字段或截断不能算作成功纠正。

可使用 `Tools/MotionAdapter/run_agent_work_loop_regressions.ps1 -RunName <新的记录名>` 在已准备的隔离工程统一运行上述回归，保存每组日志、报告和源码 SHA256；记录名不能复用覆盖。运行前须保证没有其他 Unity 进程占用验证工程。此脚本不启动真实模型回放，公开模型检查另行执行。

隔离测试的播放完成回调不等于用户实际听到声音；完整麦克风、真实 SVC 歌声输出和私有角色场景仍需在实际使用中确认。本次未重新运行完整 SkillRoutingRegression；其已知的旧反射参数问题仍见首次自检文档，不能把本次相关回归通过扩大为整个项目测试全绿。
