# 台词语言协议

角色生成台词时声明要使用的语言，GPT-SoVITS 使用该声明选择 `text_lang`。
程序不通过词表改写角色的话，也不把纯汉字短句一律当成中文。

```text
<lang code="zh"/>听到哦。<lang code="ja"/>了解。アントネーワです。
```

用户看到的正文是「听到哦。了解。アントネーワです。」；第一段以 `zh`
合成，后两句以 `ja` 合成。标签不显示、不朗读，也不作为工具执行。

- 当前声明接受 `zh`、`ja`、`en`。每次新模型请求（包括 continuation）重新声明，
  同一请求内声明持续至下一次切换。同语种连续句子无需重复标记。
- 语言切换可以发生在完整句子之间，也可以用于确实需要另一语种朗读的引用片段。
  分句器不会把不同语言的片段合并到同一次合成请求；原有句内切分继续工作。
- `<thought>` 内和 `<silent/>` 后的语言标记不能改变外部发言的语种或解除静默。
  普通正文仍是发言，兼容的 `<say>` 不是必需包装。
- 无声明或非法声明进入兼容路径；非法声明结束之前的语言作用域，不沿用旧值。
  该路径仍使用原有字符检测，因此无声明的「了解。」仍可能误判。LLM 日志标记
  `invalid` / `undeclared`，TTS 日志显示 `source=auto-fallback`。
- 正常声明显示 `source=declared`；用户手动固定 TTS 语种仍优先，显示 `source=fixed`。
  声明不会修改其他排队请求的语言。预合成命中检查实际合成语种、文字和轮次。
- 内部短开场的 JSON 草稿通过独立的 `language` 字段传递同样的语言信息，正文不塞标签。
- 当前 GPT-SoVITS 实现完整使用显式语言。其他 TTS provider 保留旧接口兼容行为，
  接入显式语种时需实现 `SpeechText` 重载，不能假设它们已经支持这一功能。

## 实现位置

`RoleOutputChannels` 增量解析声明，输出带语言的 `SpeechText`。
`ChatQW` 的 typed speech API 在清理标签时保留这份元信息。
`ChatSample` 使用 `SpeechTextBuffer` 保留暂缓发送的文本及语言范围，队列携带语言码。
TTS 流式播放、完整 WAV 和预合成共用请求构造，字幕与已听到文本只接收正文。

模型生成质量另行通过 `language.txt`、`persona.txt` 和 `behavior.txt` 约束。
正式回复和 continuation 还在当前用户输入前收到简短的 `SpeechText.OutputContract`
提醒，以免长行为/技能提示淹没语种约定。它不进入会话历史，也不发给内部 JSON 任务。
语言声明解决语种传递问题，不保证模型生成的词汇、语法或专名读音永远正确。
这一流程不增加第二次模型调用；仅增加声明所需的输出 token。

## 验证

- Unity 菜单 `Tools > NeEEvA > Run Speech Language Regression`，或无界面调用
  `SpeechLanguageRegression.RunBatch`。覆盖任意拆包、语种切换、纯汉字、私有通道、
  暂缓发送、非流式收集、请求参数、预合成与轮次隔离，并复用现有输出通道回归。
- `python -X utf8 Tools/check_speech_language.py`：对空闲的本地 LLM 运行真实角色提示词，
  不播放音频、不执行返回工具、不写入会话或记忆。检查语言声明与已知错误场景，
  原始结果写入 `Logs/speech-language-check/generation.json`。这是有限场景评估，
  不代表通用的中日文质量检测器；仍需检查自然度以及实际听音。

修改提示词后重新进入 Play，确保本轮使用新 system prompt。
