# 首答失败后的语音状态恢复（2026-09-15）

本次处理用户截图中 `FirstReply route=Failed → <silent/>` 后停止语音、自主流程长期等待的问题。截图中的 `<silent/>` 来自客户端失败处理；并非模型主动决定长期沉默。

## 日志证据与原因

冻结日志保存在 `Server/ARDY/runtime/silent-recovery-20260915/Editor.log`，来源与哈希见同目录 `source.json`。以下行号按原始 LF 分隔，避免 Windows CRCRLF 导致行号翻倍。

| 失败诊断行 | 原始输出行 | `<say>` 开启/关闭次数 | 诊断 |
| --- | --- | --- | --- |
| 6365 | 6342 | 34 / 33 | `first-reply-incomplete-output` |
| 11557 | 11534 | 47 / 46 | 同上，截图对应轮 |
| 15548 | 15525 | 34 / 33 | 同上 |

三次均有公开文本送出。截图对应轮先播放了前缀，失败后仅剩周期性的记忆日志，没有正常“回复播完”收尾。旧诊断中的 `speechCharacters=0` 来自失败结果没有保存候选文本快照，不能解释为没说过话。旧日志没有记录具体 `finish_reason` 和 completion token 数，因此不能据此断言一定耗尽了 768 token。

两层问题叠加：

1. 原首答 grammar 允许无限追加语言段，却不允许正文结束后的普通换行。模型在 `</say>` 后选择换行，就被迫继续另一段，实际出现大量重复和混合语言输出。
2. 已输出公开文本的失败分支把整轮加入静音集合。播放器因此提前退出，未走自然收尾；完成回调又发现 `IsAISpeaking=true`，继续等待已退出的播放器。这就是挂死。若失败发生在首 PCM 前，还有队列暂空被误认作“已无语音”、提前收尾的竞态。

## 最终行为

- 首答允许正常结束和少量尾部空白，最多三个语言段。同语言连续句放在一个段落；完整长回答仍可交回原完整回复流程。
- 不按单段字符数强制截句。整体 16,384 字符保护、原 768 token 请求预算以及非正常结束判失败仍保留。
- 公开文本已经送出后若失败，撤销缓冲区和排队的尾部，允许播放器已接手的有效句完成，再统一释放语音、Agent 和等待回复状态。合成失败、没有产生音频时也会释放一次。
- 失败收尾归属当前 generation，取消/换轮时失效；用户打断和迟到回调不能结束下一轮。失败不会自动重放原始输出或重复执行工具。
- 诊断增加结束原因、生成 token 和候选文本计数；候选文本与实际已播放记录继续区分。

改动集中在 `ChatSample.FirstReply.cs`、`ChatSample.cs`、`FirstReplyProtocol.cs`、`ChatQW.FirstReply.cs` 以及 `ChatQW.CompletionPerformance`。没有调整房间、动作、角色资源、服务部署或 prepared-boundary 默认关闭设置。

## 验证记录

所有 Unity 验证均在既有 `unity-naturalness-validation` 隔离项目，使用隐藏测试进程，未打开或保存用户场景。音频通过真实 AudioSource/DSP 推进，输出静音；不代表麦克风或人耳听测。

- `controlled-before`：隔离项目采用本轮开始前的两个 ChatSample 源文件，新回归在首 PCM 前失败的场景复现提前完成，作为失败对照保留。
- `controlled-after-r1`：新增失败恢复回归 24 个场景、158 项检查通过。覆盖 PCM/WAV、首音前/播放中/已播完等待模型、无音合成失败、打断、重复和旧代回调，以及每次之后正常新一轮播放。
- `live-r1`：实际 Qwen 和 TTS 的四轮都结束并播放完成，但初版 160 字符限制把英文末句强制截断，因此该版本未交付。保留 `live-r1-review.json`；最终版本已删除单段字符硬上限，并加入超过 160 字符且自然结尾的英文回归。

最终复验：

- `controlled-final`：Unity 编译及集成通过；新增恢复测试仍为 24 场景 / 158 检查。首答解析与 SSE/请求回归共 5,969 检查通过（包含 4,183 项生产解析器检查）；既有公开边界、音频衔接、工具回退和歌唱任务回归通过。
- `live-final`：实际 Qwen＋TTS 连续四轮均为 `finishReason=stop`，42–96 个生成 token，均完成播放且后续输入可继续，没有失败静音挂死或英文半句硬截断。
- `delivery-source-manifest.json`：11 个本轮变更代码/元数据文件的 SHA-256 与实际验证的隔离副本一致；`turn-changes.patch` 仅比较本轮开始前的基线，未混入此前批次的修改。

## 使用与范围

等待 Unity 脚本编译完成后重新进入 Play，连续对话即可验证恢复。`<silent/>` 仍是合法的内部结束表示，修复的是失败后的状态交接。

这批目标是消除挂死与重复续写诱因。有限样本不保证模型永不重复、不保证任意回答质量，也不证明端到端首音已稳定达到 1.5 秒。
