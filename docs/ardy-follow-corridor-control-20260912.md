# 房间连续跟随：路线控制、姿态证据与验证记录

本轮重点是让连续跟随的路线、速度与实际角色状态保持一致，并把失败定位到具体阶段。动作自然度仍需继续观察：固定条件的后仰实验一例改善、一例变差，不能宣称已经修好异常走姿。

本文记录 9 月 12 日开始、13 日凌晨继续的修复与验证。所有人工观察继续使用现有房间。

证据根目录：[follow-corridor-control-20260912](../Server/ARDY/runtime/follow-corridor-control-20260912/)。其中每轮日志、请求/回复和失败报告均保留。

## 已确认的问题

先前保存的两份走姿录制能将已播放 Core27 帧与实际 Humanoid 对齐：明显后仰已经出现在生成的源骨架中，不能归因于 Unity 骨骼映射或返待机过渡。证据见[姿态分析](../Server/ARDY/runtime/follow-capture-review-20260912-2234/pose-analysis.md)。

房间移动失败则存在另一条链路：路线规划可以成功，但后续控制目标或 ARDY 实际生成的根轨迹仍可能碰到矮桌等几何体。必须分别审核路线、输入模型的目标与真正准备播放的短段；“规划成功”不能替代后两步。

## 本轮控制实现

1. **统一角色根位置与模型骨盆坐标。** 导航从实际 character root 出发，控制生成时保留角色中立骨盆的水平偏移、当前朝向、anchor 和缩放；写入 ARDY 的是对应骨盆目标。路线起点与解码后的实际根位置不一致时明确拒绝。
2. **保留跨请求的前方几何。** 一个 native session 内维护 `PathState`，沿已经接纳的 8 帧进度继续使用前方路线和圆角，避免每 0.4 秒重建圆角而不断缩小转弯半径。按承诺时间切取旧几何，再根据实际根点和朝向作局部刚体校正，保留原有曲率和制动距离；不把模型超前的位移直接算作已经走完的规划距离。校正后的每段及连接到新目标的路线都仍须通过同一房间检查。
3. **提前减速并留出余量。** 正常速度规划采用 60°/s 转向与 0.8 m/s² 减速；可行性硬边界仍是 80°/s 与 1.2 m/s²，加速上限 1.25 m/s²。较低正常目标逐渐生效，不把真实初速瞬间重置为较低值。空间或曲率不足时保留明确拒绝。
4. **正确延续瞬时速度。** 新请求接续前一段第 8 帧时刻的规划瞬时速度。相邻两个目标点差得到的是一帧平均速度，在减速时会高估接续初速。起步时则从同一段已验证历史中的实际 avatar root 测速度，骨盆待机摇摆仍保留在姿态历史中。
5. **保持几何查询有界。** 每次路线候选构造最多 96 次 guard 查询；长连接段拆成不超过 0.25 m 的小段调用现有检查。0.25 m 是本次细分长度，原 live guard 的最大步长仍为 0.5 m。预算耗尽或其中一步失败就拒绝该候选连接。
6. **抵达时消费已确认前缀。** 用户已停下且前缀的最后确认根点已在目标 5 cm 内时，先播完剩余安全动作，不为最后一两厘米反复生成转向。实际角色也进入 `ArrivalTolerance` 才允许平滑停止。用户移动或目标变化使前缀不再到达时，立即退出此等待；未确认预测尾不能用作到达依据。停止后保留跟随任务，避免在同一个近目标反复起步。

实现入口：[ArdyRoomStreamTrajectory.cs](../Assets/AIChatTookit/Scripts/Motion/ArdyRoomStreamTrajectory.cs)、[ArdyRoomLocomotionController.Stream.cs](../Assets/AIChatTookit/Scripts/Motion/ArdyRoomLocomotionController.Stream.cs)。`PathState` 按 native session 管理，取消或拒绝后的状态不能继续作为旧动作的有效延续。

## 生成与播放的检查边界

发送 HTTP 前，完整 40 帧控制目标先接受房间几何检查；未来用户位置未知，此阶段不假设用户会一直站在当前点。ARDY 回复后，仅审核、接纳并准备播放前 8 帧；未确认的其余预测尾不能进入实际播放或下一步已执行历史。

8 帧审核包含源骨盆高度、根位移连续性、关节连续性、房间路径与当时用户净距。开始播放前及实际移动期间仍检查状态和路线，用户 Stop、所有权改变、障碍拒绝不能被自动恢复逻辑绕过。

源动作通过连续性与几何检查只能说明满足这些约束，不代表挥臂、身体倾斜、脚接触已经自然。

## 失败证据与历史分类

`pose-history` 现在保留具体原因：样本不足、0.75 秒历史窗口不完整、最新样本过期、采样间隔过大、父节点或缩放改变、根位置/高度/朝向跳变，以及源骨盆高度异常。历史取自实际渲染姿态，拒绝原因不会混称服务连接失败。

拒绝证据区分 `control-corridor`、`control-target` 和 `committed-prefix`：前两类可能发生在 HTTP 发送之前，因此不会伪造“服务已返回候选”。记录包含 operation/wire/session/request/control 标识、具体目标或候选帧、实际根位置、路线角点、anchor/偏移/缩放以及当次导航检查结果。

只有标识匹配的原始 request/response 才能附入记录。没有匹配项时写明缺失，不借用上一条回复。保存上限为最近 4 次拒绝、原始 JSON 合计 4 MiB、单个 payload 1 MiB；超过限额保留原因和元数据。记录器导出同一份有界证据，便于在现有房间保存异常。

实现：[Diagnostics.cs](../Assets/AIChatTookit/Scripts/Motion/ArdyRoomLocomotionController.Diagnostics.cs)。额外 guard 如果只提供文字，不会推测或虚构碰撞物名称、采样点。

## 后仰实验：可信的混合结果

原控制固定 history/seed 回放成功复现两段峰值。第一轮密集目标点折线导致两个控制候选在生成前被拒绝：时间采样点被当成路线角点形成很短的切向接入曲线，因此这个 surrogate 拒绝不能解释成原房间没有减速空间。

第二个预先声明的实验保留原起点、原终点、初始姿态/速度和 seed，将近似直线的目标点简化后调用生产控制生成。最大横向简化偏差为 2.16 / 5.23 mm，低于固定 2 cm 门槛。两组前缀根位置差为 0，旋转最大差约 0.000003°，36 次请求均首候选通过，没有额外换 seed。

| 只计确认的 8 帧 / 0.4 秒 | 原控制 | 新控制 |
|---|---:|---:|
| Case 1 最大胸后仰 | 34.94° | 29.50° |
| Case 2 最大胸后仰 | 25.72° | 27.95° |

一例改善、一例变差，骨盆后仰及明显后仰持续时间也没有实质改善。分支前身体已经后仰，实验只改晚期单窗口，并未重建跨请求 `PathState`；不能用它声称完整控制改进已经解决自然度，也不能单独归因于减速度参数。

详细结果：[final-braking-comparison.md](../Server/ARDY/runtime/follow-corridor-control-20260912/final-braking-comparison.md)、[comparison.json](../Server/ARDY/runtime/follow-corridor-control-20260912/braking-linear-replay-r5/comparison.json)。原始拒绝限制：[surrogate-limitations.md](../Server/ARDY/runtime/follow-corridor-control-20260912/surrogate-limitations.md)。

现在可在原房间继续体验，并继续用“保存异常走姿”保留有问题的时间段。上述通过说明所测控制、路线和生命周期成立，并不覆盖所有房间位置、所有生成姿态或主观自然度。突然反向仍可能先沿安全的旧方向走约 0.4 m 再停转，这是当前保守续段策略的响应限制。

自然度下一步应使用预先固定的多速度、多转弯和多起始姿态样本集评估，避免继续围绕单一样本调参寻找好看的结果。
