# 增量倾听、心里话与 ASR＋Jev 技能准备评估

日期：2026-09-28。范围：当前源码、主场景配置、16:45–17:06 Unity 固定日志、官方公开文档。没有修改生产代码、部署模型或调用推理服务。本报告讨论的是用户澄清后的 ASR 增量文本 → Jev 类判断模型方案，不要求 Jev 本身直接听音频。

## 结论

方案有价值：将录音中的计算用于意图候选、技能准备、已知素材定位和分段证据准备，在最终输入到达时校验并采纳，可以减少等待。当前系统已经有部分增量判断和静默准备，但正式 Fast 路径没有完整消费普通倾听候选；可见心里话的撤销条件也不足以识别追加文本造成的语义反转。

ASR＋Jev 能辅助区别唱前介绍、歌词内容、唱后要求。它不能单凭文本保证这些话在声学上是说出还是唱出，也不能凭缺少时间戳的混合段产生精确裁剪坐标。要解决本场口语混入回唱，仍需把语义区间、原始 PCM 与局部声学/对齐证据连接起来，并对不确定边界保留细化路径。

## 已有机制核查

### 同一次倾听请求的不同输出

PreparedListeningProtocol 生成 quiet_boundary、observed_mode、inner_reaction、draft 等字段。普通倾听由 ChatSample.PreparedTurnBoundary.cs 发请求；歌唱候选由 ChatSample.cs 的 RequestSingingDraftAfterDelay 发请求。不是每个字段都对应独立模型调用。

- inner_reaction：面向用户展示的角色短反应，不是模型隐藏推理。ChatSample.ThoughtPreview.cs 发布，CompanionThoughtBubble.cs 展示。不直接发声或执行，也不直接写正式历史。部分后续路径会把它作为可撤销的临时上下文，因此不能说它永远不参与后续输入。
- draft：私有候选台词，可静默合成，在最终采用相同内容且来源兼容时复用；不会显示成心里话。
- quiet_boundary：假设当前快照后没有改动且静音成熟时，语义能否闭合的条件准备。直接复用默认关闭，当前不是看到 closed 就停止录音。
- observed_mode：同一请求的模态判断，可参与后续说话/歌唱证据处理。可见文本本身没有动作权限，不等于整份请求只有展示作用。
- ActorSpeech 的私有 TTS 是另一个阶段：正式 Fast 已生成完整草稿后，与行动审核并行合成，不是在用户讲话时预测其完整问题。

### 过早下判断的具体原因

PreparedListeningPolicy 普通路径最少2个字符、0.20秒调度稳定期即可准备；每个 capture 最多3次，后续刷新受1秒/4秒节流约束。这些是输入变化与预算条件，不是语义完整证明。主场景仍序列化着旧的4字符/0.55秒设置，普通准备实际走上述新策略，不能只读 Inspector 数值下结论。

InnerReactionInstruction 明确允许输入未完时产生反应。ThoughtPreview 发布检查请求、输入、capture 和展示 epoch，也检查原文是否仍兼容，但没有独立的语义完整/未完纠正门槛。兼容主要是归一化长度不缩短、TranscriptContinuity 至少0.55。

因此“我想让你唱……不对，先别唱，我还没示范完”这类追加更正可能保留旧文本而改变意图，字面连续不能证明原判断仍有效。示例是机制解释，不冒充本场原始发言。已有心里话最长约7秒，后续文字增加时不一定立即撤回；3次预算也可能在长句前半段耗尽。把显示时长统一缩短或继续追加禁止误判提示词都不足以补足这个条件。

本场真实例子：c3 的首次快照是“有看。”（固定日志 LF202693），LF202862 的 inner_reaction 与 draft 均为“既然看到了，那接下来想做什么”；后续原文成为“有看到桌上的小装饰灯吗？”（LF202992）。c42 的快照“那说了。”（LF301647）得到心里话“看来小优已经说完了”（LF301755），随后仍继续形成完整开灯请求。这些证明部分 ASR 快照可能不完整甚至尚待修正，当前确实生成了过早定性的可展示字段；本次未采集逐帧 UI，不据日志宣称每一条必然呈现在屏幕上。

## 本场提前计算的实际收益边界

专门审计发现52次录音中条件准备 HTTP：22次完成，中位约1.919秒；30次客户端取消，中位约0.523秒。12份候选短回复触发12次静默合成，但未见“最终复用临时准备作为本轮提示”的日志。22份返回的条件边界均被拒：11份原文已经变化、11份仍为open；没有 ready/hit/shadow-hit。

普通首轮先走 Fast。当前 BuildFastLoopTurnContext 只在恢复输入条件下显式加入 TransientContext；常规 Fast context 没有完整 prepared draft 字段。Legacy handoff 等路径仍可能接收临时上下文，正式原样选句也有音频复用入口，不能据此声称全系统完全无法复用。

另有6次正式 ActorSpeech 准备，2次采用4次丢弃，这是后置并行。TTS首PCM本场中位仅0.124秒；提前1秒多生成PCM不等于净省了1秒多，不能把重叠时间当实际收益。

这些证据支持优先补“准备结果如何被正式执行消费”，不是继续增加提前调用次数。客户端取消也不证明服务端没有付出推理成本；本次没有服务端排队与取消计量，不能反向断言每笔取消都持续运行。

## 建议的 ASR＋Jev 结构

录音从开始保留原始 PCM 和时间线，现有低成本声学观测持续工作。ASR 每次更新提供稳定前缀和仍可能修改的尾部。Jev 类路由依据文本、近期已确认对话、当前任务和少量声学摘要，提出可撤销的意图与技能候选。

候选可以提前准备录唱上下文、定位 lastPlayback、取档案索引、启动局部边界分析，并保持服务常驻。这里的启用 skill 是准备能力和材料，不是宣布用户已经唱歌，更不是立即回唱。用户唱了也不自动意味着角色必须回唱，正式角色选择仍保留。

音频侧与语义侧并行：文本模型把已经听到的片段标为介绍/内容/请求/纠正/不确定，声学侧给说话/歌唱/哼唱/噪音/不确定的时间证据。局部文本或音素对齐将片段定位到原PCM样本区间。语义结果用片段ID或原文跨度表示；秒数计算、坐标映射和裁剪归代码负责，不让判断模型猜时间。

结束后只检查准备所依赖的事实是否仍成立：输入语义、素材来源、边界版本、尾部取消/更正、当前任务。通过则采纳已有准备；改变则仅废弃依赖该事实的部分。已完成且不受更正影响的原始音频分析和素材索引可复用。

### 需要的工程约束

1. 准备、展示、正式执行分别设门槛。允许早准备，谨慎展示结论；禁止把显示出来的散文反向当作已批准执行意图。
2. 候选携带 capture、ASR版本、依赖文本跨度、素材/边界版本、任务引用与不确定项。ASR更正或追加否定后撤回对应候选；字面相似度不能替代语义复核。
3. “是否涉及歌唱”不是声学分析唯一入口。直接开唱、歌词转写失败也应能由声学候选唤起专用处理；缓冲可回看起点，避免上级漏判导致整段丢失。
4. 不需要每个 skill 运行一个常驻大模型。优先共享小判断服务和分领域问题；同一证据上的独立问题可合并，真实数据依赖才串行。
5. 正式请求优先，增量更新合并、限流、淘汰旧任务。服务器取消是否有效需测量；不能把 Unity 协程并行等同于 GPU 推理没有争用。
6. 保留语义不确定和边界不确定状态。仅仅出现歌词、唱歌这个词，或者模型高置信度，不足以把粗 clean 区间认证为纯歌声。

## Jev 及本地替代的定位

官方 Jev 当前版本为 jev-1.13.0，支持文本/结构化状态，输出 Choice、Score、Noul；适合本方案的 ASR 文本路由。官方说明英语表现最好，中文/日文需在本项目数据上验证。它无需直接接收音频就能有价值，但也不能从ASR中恢复已经丢失的发声方式和精确时序。

官方支持同请求中独立问题并行。多个问题无需因为概念上属于父/子判断，就强制变成两个网络往返。若先取出了新的歌唱局部证据，后续专用判断才是真实的数据依赖。

open-alternative-jev 是在现有开放权重语言模型上读取受限选项概率的推理库，可作为本地对照；不是新训练好的声学分割模型，也不默认具备领域校准。其仓库明确提示小模型、问题拼接、选项顺序会影响结果，不能直接把发布者的硬件耗时或其他任务成绩套到DGX Spark。

当前 Qwen 保留为语义基线；先统一候选接口与采纳路径，再离线/旁路比较官方Jev和本地小分类器。若要训练，优先利用本项目中文、日文、改口、引用歌词、无词哼唱、外放回声等标注，微调小语义分类器或音频分类头；不需要先重训完整对话模型。

## 能保证什么，以及如何验收

工程可以保证：同一执行不重复；已确认排除区间不进入音频；未产生实际裁剪结果不宣称完成；过期候选不发布；已知素材的修剪请求不重新搜索未知来源。

任意自然录音的全自动语义/声学边界不能承诺永远正确。纯ASR文本存在不可区分情况：同一句歌词可以被念出，也可以被唱出；“接下来唱第二段”表示未来意图，不表示这句话已经在演唱。对齐本身也可能在拖音和混合语言上失败，需保留原PCM、边界不确定和局部细化机制。

验收应按原PCM增量回放，只给模型当时已经到达的文本和音频，不能把final全文泄漏给早期决策。用人工听音标注说话/歌唱切换，按录音/场次分开开发与留出集，防止相邻窗口混入两边。指标包括：技能提前命中与误触发、否定/改口撤回、口语泄漏秒数、歌声首尾误裁秒数、边界延迟、候选真正采纳率、取消/排队负担，以及从真实停说到有效首音的P50/P95。不能只看分类准确率、HTTP耗时或填充语首音。

优先顺序：先接通版本化准备与正式采纳、收紧心里话结论展示；并行补 lastPlayback 修剪及细粒度边界；再以增量回放选择更快的判断后端。提前准备和精确裁剪需要同时完成，才能兼顾速度与正确性。
