# 最新房间测试与下一批优先级（2026-09-14）

结论：物件识别、走近、到达后重认、转身和登记灯控已有实际成功依据，可以进入下一阶段。下一批建议让角色更快回应，并能为了看全／看清同一个目标主动调整观察站位。随后建立空间经历记忆，再扩大跨高度活动与身体接触能力。

本轮只读日志和实现，未修改运行代码、启动服务或执行新模型／Unity 测试。

**统计范围。** 原始日志副本为 `Server/ARDY/runtime/scene-next-stage-review-20260914-0139/user-editor.log`，SHA256 为 `42d84cc982bcf07e9e02d3502f77640be535330b66c623eb3f20ed4044640ffe`。其中含两次 Play；本报告只使用最新一轮第 30536–73447 行。行号按 UTF-8 文本的 LF 分隔，与 rg 一致。结构化摘要和分项分析保存在同一目录。

最新轮有 7 次 `approach-object/arrived`，全部记录了实际地面到达和新图中的同实体重认；6 次 `turn-in-place/observed`；6 次物件档案观察；2 次注视观察；开灯、关灯各一次。另有 2 次物件接近因导航站位拒绝，还有 3 次结构化决策在提交动作前仍未通过校验。以上是执行事实计数，不是整体成功率，也不证明图中文字识别全部正确。

**后退看屏幕失败的具体原因。**

1. 日志 72792 行的识别原话包含“稍微向后退一两步，应该才能看清楚”，没有漏掉后退要求。
2. 72957 行的决策却是 `approach-object + observe-closer`，即靠近观察，并带上非待续接状态的观察任务 ID，被 `observation-goal-reference-not-pending` 拒绝。
3. 73011 行的一次修复变成 `inspect-object`，仍沿用该 ID；73024 行为 `intent=unresolved dispatch=decision-unavailable action=`，没有提交空间动作。
4. 正文模型草稿虽然说“稍微后退”，但 73241 行显示该候选未获放行。实际交给 TTS 的是“我还没确认这次的移动意图，暂时没有提交新的动作。”不能把未放行草稿当成实际说出或执行的内容。

因此存在两个层次：决策误选现有操作并引用无效任务；应用协议尚不能表达“保持朝向屏幕、向后移动以扩大视野”。只修正任务 ID 仍不能让 `approach-object` 变成倒走。本次没有 ARDY 倒走生成请求，不能据此判定模型不会倒走。

**用户列出的工作优先级。**

| 顺序 | 工作 | 建议范围及理由 |
| --- | --- | --- |
| 1 | 角色回应延迟 | 下一批主项。减少重复动态事实和串行模型等待，补实际 HTTP 发送、首 token、决策、审核和首音的统一时序；保留执行结果真实性。早期确认与实质回答分别统计。 |
| 2 | 时间／观察节奏 | 与下一批同行。复用已有时间事实和事件时钟，改善动作后复查、用户插话优先级，并补“为看清而调整站位”。不重造连续高频思考系统。 |
| 3 | 地点／物件记忆 | 下一批之后优先。记录亲眼见过的实体、最后位置／时间、实际到过的观察位与路线结果；把旧知识和当前可见分开，搬动或换场景后重认。 |
| 4 | 跨高度上下台阶 | 扩大原房间活动空间，符合长期目标。需要可通行支撑面、台阶连接、根高度与足部落点，不能只放宽 NavMesh 参数。 |
| 5 | 身体与物件交互 | 先静态大表面伸手轻触并收回，再坐下／起身，再抓取／放回。每一步增加真实接触或支撑状态，分别验收。 |

当前空间记忆的实际基础是内存中的 16 个已见实体快照和通用持久化文本记忆；尚无可靠的跨 Play 地点／路线图。运行时实体 GUID 也不能直接当持久身份。上述第 3 项应先做小型空间经历记录，保持场景稳定键、当前实例绑定、观测时刻和场景版本的区分。

跨高度目前同时受到 Unity 导航、服务路径 y=0 和全身播放器平面高度约束；坐下、伸手、抓取尚无完整的支撑／接触执行器。视觉和物件命名可以提出行动假设，实际可走、可坐、可碰仍要由对应能力和几何结果证实。远程灯控成功不等于已经支持用手按开关。

**下一批建议的边界与验收。**

只聚焦两项主交付：缩短正式回应的等待；支持为了观察而调整同层站位。观察目标应保留“同一个物件”和“看全／看清局部／避开遮挡”的目的，移动方向、身体朝向和注视方向可以分别规划。完整看屏幕可能需要退远，阅读小字可能需要靠近，不能把两种目的都改写为走近。

- 在原房间完成“看全屏幕→靠近读局部→再次退远／侧移观察”，每段用新图评估目标是否仍正确、观察目的是否达成。
- 用户明确要求保持面向目标倒走时，实际执行倒走；生成能力或身后空间不支持时反馈真实限制，不把转身正走冒充倒走。
- 无效观察任务 ID 能在一次修复内去掉或正确重建；过期目的不阻塞当前的新请求，也不能绕过有效性校验。
- 保留移动取消、净距、碰撞、平滑回待机以及已通过的接近／跟随；无需额外测试场。
- 使用同一口径比较 EOU→正式首音的中位数和 p90，并分别呈现提前确认、实际动作开始和最终回答；不以一句快速开场替代实质延迟改善。

完成这些后再进入空间经历记忆与跨高度。完整的证据、逐轮延迟和代码能力依据分别见本次 runtime 目录的 `summary.json`、`latency-assessment.json`、`latency-assessment.md` 和 `capability-assessment.md`。
