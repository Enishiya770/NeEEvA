# 连续跟随：导航边界与同步走姿记录（2026-09-12）

本轮针对原房间中两项反馈：连续跟随时的异常姿态，以及角色停在地毯附近后反复报告用户周围无站位。此前证据和具体卡点见 `ardy-follow-pose-navigation-review-20260912.md`。

## 实现

- 规划起点、规划路径采样、生成轨迹审核和实际逐帧移动共用导航准入判断。保留原同层支撑、胶囊碰撞、NavMesh 查询半径和投影容差。防止实际移动进入物理检查允许、下一次规划却拒绝的位置。
- 走近规划先检查角色起点。已知卡点会直接给出 `start / navmesh-boundary`，不再枚举 24 个用户站位后报告泛化的“用户附近无可达站位”。
- 对已经位于导航边缘的角色，每个明确任务最多尝试一次恢复。恢复凭据绑定当前导航实例、构建版本、参数和原始起点；最大范围 12 cm、走廊半径 3.5 cm、单步 3.5 cm，沿途保持物理支撑与身体净距。普通路线不能借此跳过守卫。
- 恢复使用实际姿态历史与真实 ARDY 候选，保留朝向，并逐步审核到达前缀。到达后平滑释放身体，再检查实际位置是否重新满足普通规划；成功后才恢复同一个跟随任务。取消、外部动作接管、候选拒绝均不会自动复活旧任务。没有直接吸附或手动改写角色根位置。
- 新增只读走姿记录器，默认保留最近约 10 秒、最多 200 个观测。记录 Core27 实际应用帧、控制和请求身份、映射基准、最终 Humanoid 骨骼、速度及运行状态。记录位于 `PostLateUpdate` 末尾，停止回归阶段单独标记。
- 原始动作请求/响应另有 2 MiB / 32 段预算。未播放的候选尾帧不当作已播放证据。正常运行只存内存，用户点击后才导出。

## 已知限制

这是导航一致性修复及异常姿态的观测工具，不是对异常走姿原因的最终归因，也没有改变模型权重或降低动作质量、碰撞门槛。

真实 ARDY 的微小边缘恢复尚未验证成功：本轮一次原房间测试中，候选第 0 帧偏离允许的向内走廊，审核拒绝，实际位移为零。保留该失败结果，未增加随机重试或放宽守卫。新边界检查用于预防再次进入这类卡点；已经卡住时的自动恢复仍可能明确失败。

## 使用

Unity 编译完成后重新进入 Play，使用原房间的空间会话和连续跟随。若再次看到奇怪走姿，及时在房间会话窗口点击“保存最近异常走姿”。导出位置为项目内 `Server/ARDY/runtime/room-pose-captures/<时间>/capture.json`，窗口显示完整路径。后续可以将同一时刻的源姿态与实际骨骼对照，判断异常产生于生成、映射还是动作交接。

## 验证证据

本轮结果存于 `Server/ARDY/runtime/follow-boundary-recording-20260912/`，逐次源文件哈希见 `source-manifest-*.json`。测试均在已有隔离 Unity 项目进行，原房间场景文件未保存修改。

- `navigation-final/boundary-recovery.json`：41 项真实房间几何检查通过，包含原卡点、防止进入、凭据重复审核、越界/反向/跨高差/动态障碍/导航重建拒绝。纯环境场景 SHA256 前后一致。
- `recorder-final/pose-recorder.json`：最终源文件 7432 项检查通过，实际 VRM ControlRig + Animator + 既有真实 ARDY 动作；记录前后骨骼位置与旋转差均为零，确认源时钟超前但被守卫拒绝时不会误报已播放。每渲染帧重复检查的数量随运行帧数变化；首轮同样通过。
- `lifecycle-final/report.json`：337 项跟随、停止检查及 58 项任务身份检查通过；注入控制器结果的检查不冒充原生动作生成成功。
- `ownership-r1/boundary-recovery-ownership.json`：24 项恢复取消与动作接管检查通过；实际配置的控制器和原房间几何，能力请求同帧取消、旧迭代器不复活、播放器与手势的版本变化被拒绝。此检查没有请求原生动作候选。
- `soak-r1/stream-runtime.json`：45747 项检查通过。连续变速、转弯 60.004 秒，实际行走 36.67 米，零动作断供；停止根位移为零，约 0.416 秒完成动画回归。动态障碍拦截和服务不可用时明确失败也通过。此为已有隔离回归夹具，未增加用户测试场。
- `stop-final/smooth-stop.json`：364 项停止过渡检查通过。
- `native-r1/boundary-recovery-runtime.json`：真实 ARDY 一次候选被拒绝，角色未移动，姿态控制已释放。使用相同原房间卡点、全新待机历史和受控 90° 根朝向，没有声称还原上次未记录的行走姿态。

首次 `navigation-r1` 存在新文件导入过程的编译错误，不作为干净编译证明。随后重新同步并通过无 C# 编译错误的独立运行；启动器现会拒绝把带编译错误但退出码为零的运行标为通过。

60 秒回归之后仅补充候选证据的 `auditedFrames` 字段，避免将微小恢复未审核的尾帧标为已接受；最终记录器和生命周期回归再次通过。最终 172 个同步源文件的哈希全部一致，未通过重复采样掩盖前述原生恢复失败。
