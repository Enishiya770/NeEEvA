# ARDY 房间移动

2026-09-11。本阶段把房间几何规划、当前角色全身姿态、现有单份 ARDY 服务和 Unity 全身播放连接起来。没有训练新模型，也没有另载 Llama。后续已接入[聊天呼唤与面向用户](ardy-room-dialogue.md)，其配置及本阶段之后的验证记录见该文档。自动跟随和上下楼仍是后续能力。

## 使用

1. 启动现有 Qwen 动作特征服务及 `Server/ARDY/start_motion_service.ps1`。全身路径接口和已有聊天手势共用本机 8093 服务。
2. 在实际房间的编辑模式打开 **Tools → NeEEvA → ARDY Room Locomotion**。
3. 选择场景中的实际 VRM、对应的 `Assets/Model/NeEEvA.vrm` 或 `NeEEvAA.vrm`，以及包含地面和家具的环境根节点。当前房子的环境根名为 `===＝オブジェクト===＝`。
4. 点击 **准备房间几何**。它增加可撤销的原始网格引用组件；不关闭静态合批、不改变模型导入设置，也不自动保存场景。保存该组件可以保留以后的准备结果；调整房间网格后应重新准备。
5. 使用 **已核实的 SailingMoon 水面配置**。这里排除的是已核实的巨大透明水面；普通家具继续阻挡，真实 Collider 不会因为视觉排除而消失。
6. 进入 Play 模式，点击 **构建导航并绑定角色**。成功后窗口会出现 **在 Scene 视图选择地面目标** 按钮；点击该按钮，再到 Scene 视图用鼠标左键单击同层的空旷地面（不按 Alt）。青色显示规划路径，橙色显示实际生成路径。按 Esc 可以取消选点；也可以停止移动、改选目标，或关闭窗口释放本次运行的临时控制。

当前聊天场景的 `NEVA` 使用禁用完整 VRM 更新的 Humanoid 配置，以保留独立眼球和尾巴控制。只需角色 GameObject 处于激活状态，不要为了绑定手动启用 `Vrm10Instance`。窗口、历史采集、生成等待和逐帧移动均接受该配置；运行期间改变绑定时的 VRM 更新模式，或停用角色对象，仍会中止并显示具体原因。更新脚本后退出 Play、等待编译，再重新进入并重新绑定。

窗口不会保存房间场景。角色需要已经正确放在地面上；不会把角色吸附到另一层或自动矫正起始高度。单次目标需要能在十秒内完成，较远目标会要求先选择近处。过窄或不可达的位置会给出具体原因。

几何准备是必要步骤：实际 Play Mode 中，Unity 将原本 152 顶点的地毯网格替换成 62569 顶点的合批网格。导航使用准备组件保留的原始网格，渲染继续使用合批结果。缺少相应引用时会明确拒绝构建，不把整批模型当成地毯。

## 实际房屋的处理

实际房子是 `Private/SailingMoon/Scenes/NeEEvA_SailingMoon_Day_Chat.unity`。地形验证使用它对应的纯环境 `NeEEvA_SailingMoon_Day.unity` 的隔离副本。

- 下沉客厅的实际地板 Y≈−0.7298，一楼 Y≈0。约 73 厘米的高差不属于平地移动能力，跨越路线会拒绝。
- 茶几没有 Collider。没有可靠碰撞覆盖的可见家具使用临时保守包围盒参与规划和执行碰撞；可能把复杂家具间隙判得偏窄，但不修改模型资产。
- 地毯顶部比地板高约 2.6 厘米。宽、薄的真实网格必须逐点证实下方有原始地板，才可作为薄覆盖物；不能用同一规则将悬空板或厚门槛变成可走地面。
- 名为“水面”的原场景视觉对象覆盖约 200×200 米，位于客厅地板上方约 7 厘米，材质为透明 Water，且没有 Collider。该房屋配置明确排除它的视觉代理，不能把这个个案泛化为忽略所有薄平面。
- 原场景主楼的一个“階段壁”引用了源 FBX 中不存在的 mesh fileID；审计报告保留不完整标记，没有猜测并替换为别的墙。楼梯区域未开放，本阶段的验收范围是下沉客厅。

默认实际身体胶囊半径 0.30 米，规划额外留 0.05 米净距，窗口按导入角色身高确定净空。路线每不超过 6 厘米检查地面中心及周围八点，同时检查身体净空和连续胶囊扫掠。允许原始地面坡度最高 3°、原始局部高差 2.5 厘米、相对起点的总高度变化 4 厘米；经过严格验证的薄覆盖物额外允许最高 3 厘米表面差，微小倒角仍受下方真实平地及高度范围约束。

播放前会检查完整生成轨迹，播放每一帧前再检查实际根位移；真实障碍突然挡路、地板消失或输出偏离可走区域都会停止。该胶囊检查不是逐手指/衣服碰撞，也没有添加脚底 IK、步态上下台阶或沿坡面修改根高度。薄地毯容差不代表脚底已经精确贴合地毯。

## 生成与控制权

每个新目标采集约 0.75 秒、16 帧实际显示的 Humanoid 姿态，包含骨盆与双腿。缺失的 Core 中间关节由相邻骨骼投影；手部末端跟随手腕，不是假装测到手指。目标和历史都转换为同一源骨架尺度及坐标，首段朝向从实际骨盆朝向连续转到路径方向。

保存的聊天场景中，`NEVA` 的实际世界位置为 `(-2.6, -0.72, -4.6)`、朝向 90°、缩放 1；父 Chat Rig 的位置 `(-2.9, -0.72, -4.6)` 不等于角色位置。复现点选移动时应使用实际角色变换。曾出现“已规划路径，但立即显示已取消移动”的问题，原因是移动控制器将禁用的 VRM 更新组件误当成停用的角色对象；该问题发生在动作生成前，已统一修正对象与运行模式检查。

服务使用原生 ARDY XZ/heading 约束，每窗生成 40 帧并保留最后 16 帧完整历史，返回最多 200 帧后才开始播放。上下半身接口共用同一个后端锁，取消请求不会提前释放正在推理的锁。角色修订号阻止旧响应启动，等待期间角色移动或被其他系统接管会丢弃结果。

完整生成和实际播放时长分开处理。原协议保留至少 1 秒终点约束，并向上补齐 40 帧（20 FPS 下每档 2 秒），因此到点后可能还播放约 1–3 秒的已有动作尾部；这段轻微活动不是等待新的模型计算。房间移动现在从最终位置和朝向持续不变的目标段开始，在已生成的位移与朝向稳定时立即进入平滑待机过渡，额外等待为 0 秒（前一版为 0.25 秒）。完整响应和整条轨迹审核仍保留。

提前结束只由房间行走策略显式选择。候选点需在目标 5 厘米内（若当前到达容差更小，使用更小值），最近 0.15 秒根移动速度不超过 0.12 米/秒、转向不超过 20°/秒；剩余生成尾部也必须保持目标附近且没有明显继续转向。无法满足时完整播放。中途暂停、绕行后经过终点、尚未完成的终点转身，不以“距离很近”为由直接结束。其他全身动作默认完整播放，保留有意停住姿势的动作语义；足接触预测不单独作为提前结束依据。

行走取得显式身体控制权，暂停当前骨骼动画。自然到达后，先保留生成动作的末帧，再用约 0.4 秒过渡到当前正在推进的 Animator 姿态，过渡期间不移动已到达的角色根节点。Animator 在过渡期间先恢复，其他身体动作控制器等交接结束后再恢复；不再瞬间写回走路前保存的旧姿势。地形阻断、角色停用、外部接管等中断仍优先释放控制。

这项交接由全身播放器的 `ReturnToAnimation(seconds)` 提供，适用于自然完成的全身生成动作，不包含行走专属姿势。调用方等待 `ReturnedToAnimation` 后结束动作；`IsReturningToAnimation` 期间仍持有骨骼控制，避免提前开始另一份身体动作。现有上半身生成使用 `ArdyMotionPlayer` 的动态淡出，两者都接向当前 Animator。骨骼姿态过渡本身不等同于已经解决任意两段动作之间的落脚、接触和惯性连续性。

当前不是一边播放一边无缝追踪移动目标的连续流；新的目的地会取消旧动作，从实际当前位置重新采集和生成。呼唤/跟随应建立在这个可停止、可验证的执行层上。
