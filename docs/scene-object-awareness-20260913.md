# 关注物件、读取局部资料与灯具开关

实施日期：2026-09-13。本批接续[场景时间状态与主动改变视野](scene-active-time-20260913.md)，让角色将图像中的关注点关联到局部物件，并在确认明确能力后操作一个已登记的小灯。实现、隔离自动回归与一轮真实 Qwen 自主观察已完成，可以回到原房间 Play 体验。真实自由开关与长期自主行为质量仍需后续观察，不能由受控开关回归推定已经稳定。

仍使用现有角色、房间、Qwen 和动作链。进入原房间 Play 后，已有场景动作绑定会在建立角色视觉时显式注册符合核实结构的灯具，不需要往主场景手工添加组件或修改材质资产。此注册要求场景动作与物件感知已开启，并且房间环境根明确绑定在当前聊天场景中；注册失败会记录 `[Vision/Object] no lamp capability installed`，不会根据相近名字猜一个物件替代。

## 先看到局部，再关联物件

[SceneVisionGrounding.cs](../Assets/AIChatTookit/Scripts/Perception/SceneVisionGrounding.cs) 继续使用角色 RGB 相机同帧的本地深度及渲染标识。新增加的物件观测与原有可行走目标定位是两个用途不同的结果：

| 结果 | 可以据此做什么 | 不能据此声称什么 |
|---|---|---|
| 已确认可见的不透明刚性部件 | 关联本帧物件身份，转头确认新图，读取该物件的局部资料。带 Animator 的刚性网格也可进入此观测路径。 | 不能把捕获时的点当作持续有效的世界坐标或可落脚位置。 |
| 透明、变形或未验证渲染的候选 | 保留本地候选；若同一实体在同帧还有可靠可见的不透明部件，可据该部件确认实体。 | 候选本身不导出场景标签，不证明已经看清实体，也不能穿过它识别被遮挡物件。 |
| 仅图像区域的关注方向 | `look-at` 可对光亮区域或未解析的像素方向实际转头，随后采集新图。 | 不能把这次转头写成物件已识别、设备可操作、三维位置已测得或已经走近。 |

物件身份由 [SceneObjectIdentity.cs](../Assets/AIChatTookit/Scripts/Perception/SceneObjectIdentity.cs) 提供。明确登记的组合根让其可见子部件归属同一运行时实体；一个灯的塑料底座、透明罩及发光子件不必被理解成三个互不相关的东西。`entityId` 是本次运行中的实体标识，不是可跨 Play 持久使用的资产标识。

`桌面装饰灯` 是本地登记的**场景标注**，`identitySource=scene-authored` 明确记录来源。这不是模型从像素独立辨认出的名称。没有明确登记的物件仍可有匿名的渲染器会话标识，标签为空；不会把整个 Hierarchy、Inspector 或隐藏物件名称导出给模型。局部父子关系只说明部件属于哪个实体，不证明“放在某家具上”、接触关系或物体用途。

对于这盏灯，点击/关注发光处或玻璃罩后，如果同帧还能找到**同一实体**可靠可见的不透明底座，就可以改用底座确认实体。若底座也被挡住、仅露出轮廓、像素太少或没有可靠不透明部件，则实体仍未确认。这个范围内的回查不等于穿透玻璃获得完整内部视觉，也不会换成另一盏灯。

## 局部档案与动作链

[ChatSample.SceneObjects.cs](../Assets/AIChatTookit/Scripts/Chat/ChatSample.SceneObjects.cs) 保存最近关注物件与最多八条观测摘要。档案包含实体标识、场景标注及来源、采图标识和 UTC 时间、捕获时坐标、已登记能力，以及观测之后读取的设备状态。设备局部结构仅暴露登记发光部件和 Light 节点，明确标记为引擎资料。

这些是带时间的快照，不是持续看见或全屋物件清单。图像外观仍需由真实图像解释；设备状态来自真实组件读取，两者的来源不会合并成“角色亲眼看到了全部属性”。

| 意图 | 当前行为 |
|---|---|
| `look-at` | 关注当前图像区域；若能确认实体，则记入局部档案，否则只记录实际视向和新图。 |
| `inspect-object` | 从当前图像选定局部实体，实际转头、取得新图并确认同一实体后，读取局部档案；不走动、不改变灯具状态。 |
| `set-object-state` + `on` / `off` | 只对当前可见、同一房间、距离范围内且具有明确登记能力的灯具执行运行时开关，之后再采集新图。 |
| `approach-object` | 沿用既有严格表面定位与导航审核。新增物件身份不能放宽地面、碰撞、高差或路径要求。 |

模型需要引用当前真实图像的 `captureId` 和归一化像素坐标，不能直接给出世界坐标、组件路径或任意属性赋值。缺少明确能力资料时先检查物件，不凭发光或名字推定能开关。用户指令和私人自主意图使用同一动作协议；没有固定“看到灯就开关”的规则。自主反向切换还受 30 秒冷却约束。

默认设备操作距离上限为 2.5 米，使用角色根与灯具根的实际三维距离；不是手臂触及范围。跟随或其他身体任务占用时，物件动作让出控制权。图像过期、视觉来源或角色/房间绑定改变、目标消失、距离超限、没有开关能力等情况会拒绝操作，不能借新身份绕过这些条件。

玻璃灯及其 Animator 部件因此可能“可以被关注或操作已登记设备能力”，但仍不适合作为 `approach-object` 的严格表面目标。需要先基于已经验证的邻近固定表面和合法地面靠近；本批没有扩大可行走区域，也没有启用跨高度移动。

## 一盏真实登记灯的开关范围

[SceneObjectLampCatalog.cs](../Assets/AIChatTookit/Scripts/Perception/SceneObjectLampCatalog.cs) 仅接受核实的 SailingMoon `1階家具/standlight (4)` 组合结构，并检查子件、网格、原始 Autodesk Interactive 材质、Standlight Animator 和 lightmotion 动画配置。同名歧义、近似名字、配置改变或已禁用的能力都不自动接管。

Shader 行为核查使用 [Unity 2022.3.22f1 官方内置 shader 包](https://download.unity3d.com/download_unity/887be4894c44/builtin_shaders-2022.3.22f1.zip)，[下载来源与文件哈希](../Server/ARDY/runtime/scene-object-protocol-20260913/autodesk-shader-review/source.json) 保留在验证目录。该 shader 的发光路径受 `_EMISSION` 和 `_EmissionColor` 控制。物件感知仅对符合已核实不透明条件的 Autodesk Interactive 子材质开放观测支持；透明玻璃及与透明关键词矛盾的状态仍保留为候选，严格行走表面规则没有因此放宽。

[SceneObjectLightSwitch.cs](../Assets/AIChatTookit/Scripts/Perception/SceneObjectLightSwitch.cs) 实际改变两项：

- 该灯发光子件的独立运行时材质实例：关闭发光颜色及关键词，开启时恢复原有发光配置。
- 该灯自身 `Light.enabled`。

原始共享材质资产与主场景文件不参与写入。组件停用、退出所属对象生命周期或显式释放时，只恢复仍由该组件持有且未被外部修改的状态。若其他逻辑或用户改了材质引用、材质属性、Light 开关或配置，则后续操作会拒绝，恢复时也保留外部更改，不覆盖新的手工设置。

**房间原灯是 Baked Light。** 关闭发光体和 Light 组件不会清除房间原有的烘焙照明。`bakedLightingResidualUncontrolled` 和结果范围说明会保留这项限制；小灯发光状态改变后，墙面或房间仍然明亮并不自动意味着失败。本批没有运行时重烘焙、整场景熄灯、调光、任意材质编辑或通用 Inspector 编辑接口。

房间资产没有为这盏灯建模实体开关。本批行为是 Unity 设备能力控制，**没有让角色伸手触摸或按下开关**，也没有新增手指动画。台词不能把设备调用描写成已经用手按过。

## 执行过的事实不会因后续取消被抹掉

每次操作都记录 `actionId`、请求开关方向、真实状态是否变化、完成或部分失败状态及实际组件回读。组件保留最近 32 个动作标识；该记录范围内的同一动作重试不会重复改变状态，旧操作也不能重新覆盖后续操作。外层同时使用会话、回复代次和动作所有权拦截过期异步流程，这不是持久化设备事务日志。

实际灯控完成后先保存结果，再等待异步新图。若此时用户讲话、停止、绑定变化或采图失败，已经发生的修改仍被保留；结果会标记为新视觉尚未确认或操作后被打断，不改写成“没有做过”，也不盲目回滚覆盖新的状态。异常发生在部分修改之后时保留 `partial` 和实际回读，不把部分结果当成完整完成。

`performed` 需要实际设备状态发生本次要求的变化、操作之后的当前新图确认同一实体，且当前状态未被其他逻辑改变。原本状态已符合要求时记录为 `already-satisfied`，不假报又切换了一次。新图确认同一实体并不等于已经计算过画面亮度差，更不证明移除了烘焙照明。组件回读、是否真实发生本次变化、是否得到新图分别提供给台词审核；已过期或失效的状态快照不能作为当前设备状态的依据。

## 在原房间中查看与试用

使用现有启动流程和原房间进入 Play，等待角色聊天、房间绑定及视觉就绪。打开 `Tools > NeEEvA > Character Scene Vision`，点击“查找当前角色视觉”。新增加的“最近关注的物件（观测快照）”是只读档案，可查看场景标注、身份来源、观测时间、已登记能力与开关结果/视觉确认。该窗口不直接控制灯具，也不会因为预览刷新就替角色执行识别或主脑思考。

在角色能看见电视柜附近该小灯、距离合适且未被行走/跟随占用时，可以依次使用以下原话；具体语言理解和像素选择仍由现有 Qwen 决定，下面是体验步骤而不是固定口令映射：

1. “关注一下电视柜上那个发光的小摆件。”查看是否实际改变视向，窗口是否出现新图；未确认实体时只应表达对亮区的关注。
2. “查看一下这盏台灯，了解一下它。”查看是否出现“桌面装饰灯”的场景标注、`scene-authored` 来源及局部能力；这句话本身不应开关灯。
3. “把这盏小灯关掉。”观察发光子件、只读设备结果及动作后新图；允许房间仍有烘焙余光，不应出现虚构的伸手按键描述。
4. “再把这盏小灯打开。”检查是否真实恢复发光。同方向重复请求应说明原本状态，不假报又发生了一次切换。
5. 让角色关注旁边一个未登记物件，或在较远处请求开关。无能力或距离不满足时应说明实际限制，不操作其他物件替代。

也可以安静等待自主轮，观察角色是否依据当前兴趣主动关注或检查物件。接口允许自主发起，不保证每次等待都会选灯、执行操作或持续探索；自主选择质量需要实际长时间 Play 日志和画面共同评估。

若出现异常，请保留时间点、用户原话和当时视觉窗口。日志中的 `[Vision/Object]` 局部档案、`[Vision/Action]` 阶段、`objectContext.stateResult` 与 `captureId` 可以区分：未找到物件、仅有候选、距离/能力被拒绝、实际状态已改但新图失败、以及完整完成。不要只根据角色台词推断哪个环节成功。
