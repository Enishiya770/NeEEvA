# 观察站位调整与回复延迟：2026-09-14

本批实现同层的目标朝向与行进方向分离，以及空间动作回复的请求上下文精简。没有新增测试场、第二份语言模型、台阶能力或任意场景编辑接口。

## 已实现的行为

- `reposition-view`：以当前图像中确认的物件为参照，前移、后移、左移、右移 0.2–1.2 米，目的为看全、看细节或避开遮挡。普通“走到物件附近”继续使用 `approach-object`。
- 新位置必须通过原房间导航、身体空间、用户距离及支撑面审核；不能借此走上物件、跨台阶或偷偷换一个方向绕行。薄地毯的实际地面高度继续由原导航核定。
- ARDY 同时接收逐帧平面位置与独立身体朝向。Unity 核对生成路径、实际身体朝向、实际位移和最终朝向；小距离请求采用更小的到达容差。
- 途中维持原关注区域，完成后重新采集角色实际图像、确认同一实体，记录前后可见像素范围、实际位移和观察目的。抵达位置、再次看见实体与“已经看全/读清”是不同结果。
- 新用户输入、取消、过期图片、旧动作回包和关闭输出沿用现有的所有权与执行检查。

## 理解层验证

固定六个真实原房间图像请求，不根据回答挑选样本。初轮按生产解析语义通过 4/6，发现：旧契约把物件目的强制归为靠近；当前新目标可能误引用最近关注的小灯。

修正的是一般规则：按本轮目的区分接近与观察站位调整，先辨认当前目标再选择相符实体 ID。保留原图、旧灯事实和语义确认，并未清空记忆来规避干扰。

第二轮六个请求各执行一次，6/6 通过，2.03–3.03 秒：灯的远近与侧移、屏幕后退、仅询问不移动、旧观察任务 ID 修复。屏幕选点由同帧的真实不透明实体像素检查，而不是仅凭矩形范围。有限样本通过不等于所有场景都能正确泛化。

证据目录：`Server/ARDY/runtime/scene-view-position-20260914/` 中的 `unity-r3`、`qwen-r1`、`qwen-r2`。初轮错误与评估规范化修正均保留。

## 回复延迟

已决定的空间动作，正式回复保留本轮客观执行事实，省去无关的完整自由动作语法与重复导航诊断。普通聊天、未准备的动作和不匹配轮次仍提供自由动作入口。重复场景事实只在发送时按精确内容共享引用；不同时间、实体或结果不合并，任何不能无损保留的数值整段保留原文。

本地结构化决策仍提交完整语法，但提示文本只定义字段一次；当前不存在的观察任务 ID 不进入可选语法。运行时身份、归属和取消检查继续独立执行。

四次固定 ABBA 使用相同真实观察、用户输入、图像与生成参数，两侧都已有事实去重。此配对只度量空间回复上下文精简：

| 指标 | 原完整动作上下文 | 空间回复上下文 |
|---|---:|---:|
| Prompt token | 14,658 | 7,326 |
| 未命中缓存的服务端预处理 | 2.427 / 2.176 秒 | 1.141 秒 |

第二次精简请求命中了缓存，不能把其 0.155 秒首正文当作精简本身的额外收益。这份配对未经过完整发声契约、语音审核和 TTS，不是主场景 4.5 万 token 人设长对话的首音结果。下一次 Play 应用新 `[LLM/HttpTiming]` 与既有录音/决策/首音日志共同评价。

首次 20 厘米后退实际移动约 21.7 厘米且面向目标，但原始 ARDY 候选后半段出现严重下蹲。路径通过并不代表步态通过，因此保留该反例并补充独立步态审核。

普通房间步行动作现复用连续跟随已有的站立高度、根节点步进与关节突变检查；完整窗口最多采样三个原生候选，拒绝的候选不推进历史，也不被改姿势后放行。三次均失败会带具体指标返回失败。原始反例重放正确被拒绝。

后端 39 项回归通过，覆盖原跟随流程、保留历史、完整窗口尾部异常、取消、无部分路线泄漏及失败原因传递。已有原生物件走近实测通过，见 `approach-regression-r1`。

这证明当前原房间里这些受控输入可以执行；不是任意姿态、任意距离或任意地形的自然度保证。特定小距离仍可能生成异常候选并被拒绝，拒绝原因会保留，角色不能据此声称完成。
