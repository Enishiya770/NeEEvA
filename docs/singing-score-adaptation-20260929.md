# 轻量歌唱判别器：首次拟合与开发评估

本轮已完成实际拟合，导出三个可复用的离线模型。**PANNs 加九特征线性判别器值得进入下一阶段；完整裁剪仍未通过，当前不接入角色回唱执行。** 所有声学底座保持冻结，只训练已有分类分数上的小型判别器，没有调用 LLM 或重新跑声学主模型。

## c9 起点更新

用户在第一次实际拟合前补充“c9精确唱点在3.7秒左右，你可以看波形图核对”。原PCM约3.72秒开始起振，3.74–3.75秒幅度明显上升，与3.7秒左右相容。声音属于歌唱的依据是用户确认，波形仅核对时序。

另存v3标注，将c9起点设为3.7秒，沿用原标注明确填写的±50ms容差，即3.65–3.75秒；未声称精确到单个采样。此前3.00–3.41秒环境音确认仍保留。c9恢复参与训练与完整边界评价，七份原始用户JSON、v1/v2更正和旧实验定义全部保留。

## 实际做了什么

- 从三个底座已保存的分数提取固定9维特征：讲话、歌唱、两者家族最大值、Music、Humming、Rapping的logit，以及两个歌唱/讲话分数差。不使用ASR、语种、录音ID、时间位置或人工边界作为输入特征。
- 加权标准化与L2 logistic分类只读每折训练数据。正则固定0.1，阈值固定0.5/0.8/0.95；不从外层结果选最佳参数，不做平滑、拼洞或片段拼接。
- c8/c9共享的3.41秒始终同折，两份各取0.5物理样本权重；每个训练父录音来源组总权重相同。先在整数半样本单位累计，再换算秒，避免浮点累计导致纯正样本软标签略大于1。
- 六折父录音来源诊断与四折内容组诊断。内容组把第二段的所有重唱放在一起，测试该组时训练里没有其它第二段重唱。两种仍是同人、相近歌曲内容的开发评估。
- 严格歌曲组审计将所有歌唱保守归到一组；留出该组会没有训练正例。因此没有执行这个不完整的歌曲验证，也没有宣称新歌曲泛化。
- 共33次拟合：每底座6+4个开发折、1个全部开发数据拟合。保存42份逐录音的折外预测和三个全开发模型；训练集上的分数没有用来充当验证成绩。

PANNs原来低歌唱分数并不代表其它声学线索不可用。小判别器综合了多个类别，而不是只对原始Singing设一个阈值；这批数据上取得了明确改善。但它们仍主要是日语歌唱与中文讲话，不能排除语音内容、语言或设备特征的捷径。当前结果不能作为跨语言、跨歌曲或跨设备上线验收。

## 剩下的失败已经具体化

PANNs内容组、阈值0.5：

|---|---|---|---|
| c9 | 3.70–14.00秒 | 4.16–13.76秒 | 起点晚0.46秒，终点早0.24秒 |
| c15 | 0–11.601秒 | 0–8.00；8.64–11.52秒 | 中间漏0.64秒，尾部偏早 |
| previous-c13 | 3.136–13.360秒 | 3.84–9.28；10.56–13.44秒 | 漏开头与中间1.28秒 |
| c6 | 0–9.541秒 | 0–4.80；5.44–8.00；8.32–9.60秒 | 中间两处断开 |

0.039375秒容差外非歌唱误收来自c6末尾0.0094375秒与previous-c13末尾0.0299375秒；明确speech区间、明确环境音、三份无歌唱录音均为0误收。它不是已合成音频的实际讲话污染率，容差内区间也未被宣称全是歌唱。

![人工范围与轻量判别器输出](../work/singing-subsystem-20260929/segmentation/score-adaptation-20260929/adaptation-boundaries.png)

PANNs原生时间单元为320ms。即使分类改善，也无法凭重复成10ms的输出获得精细边界。现有结果会漏字音、打断中间歌句；简单把碎段从头包到尾，又可能跨过真实讲话。下一阶段要验证连续歌句建模与局部边界细化，不能靠改变显示精度或无条件填洞处理。

## 速度与导出

在本机CPU上，对已生成的c15特征矩阵运行小判别器100次，三个头的中位耗时约 **0.100–0.127ms**。这是特征矩阵到分数的额外计算，不包含声学底座、录音、网络、ASR、TTS或Unity首音；没有因此宣称端到端延迟已经改善。三个全开发头均收敛，拟合5–6次Newton迭代。
