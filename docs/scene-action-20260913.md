## 运行链路

角色自己的新画面先进入自主预判。预判形成的 `intent` 会作为 `autonomousIntention` 进入空间决定；没有新用户指令时，也可以选择关注目标或走近。`proceed=false`、安静观察和停留都是允许的结果，程序不强制每次自主检查都移动或说话。

空间协议新增两个选择：

| 意图 | 实际含义 |
|---|---|
| `look-at` | 看向当前图像里的可见表面，取得新画面确认，然后平滑交回头部控制。 |
| `approach-object` | 先完成上述观察，再尝试走到目标附近的合法地面并面向目标；到达后取得新观察。 |

模型输出 `captureId`、图像内归一化坐标 `x/y` 和简短 `label`。坐标采用左上 `(0,0)`、右下 `(1,1)`。模型不输出世界位置；`label` 只是图像解释，例如是否真是电视、书架或设备，仍可能判断错误。程序没有把完整场景对象名称表、深度图或预设目的地列表交给模型作为“看见”。

Unity 在同一画面对应的相机位姿下，附加本地 GPU 深度与表面 ID 渲染。它将选中的像素还原为当时可见的静态表面点，再验证图像身份、时效、遮挡以及目标几何是否改变。转头后的新画面必须再次确认同一表面；第一次定位本身不代表已经看清或已经能走过去。没有 Collider 的已支持不透明电视表面也可以定位，不把电视显示的虚拟景物当成房间内的落脚点。

若当前像素无法可靠定位，而且头部、根节点和正式回复尚未开始产生副作用，生产层允许一次重新观察。它将原决定、真实定位失败原因和新截图作为 `visualCorrection` 交回同一模型，由模型在原目的下重选可见实体点，或者放弃；最多一次。程序不自动选择附近像素、不替模型换目标，也不放宽透明/未知材质的定位规则。闭眼、用户打断、轮次失效或身体被其他任务占用时，这次重选不再继续。

走近时，以可见表面周围的同层地面为候选，审核完整路线、身体空间与用户净距。默认在约 0.8 米及更外一圈的范围内检查最多 24 个候选，选择通过审核的站位；不会把柜顶、桌面等被看见的表面直接当成脚下目的地。候选均失败，只能说明这次有限搜索没有找到可用站位，不能据此宣称整个房间绝对不可达。

## 控制权与事实

`NevaSceneAttention` 使用已经校准的 `HeadFrameRotation` 做小幅头部转动，同时让眼睛临时看向同一个世界点。它不转动或平移角色根节点，也不改变用户相机。默认范围为左右 50°、向上 25°、向下 30°；超出范围会拒绝，尚不会为了看背后的目标自行转身。

原来的用户注视配置保持有效，关注结束后恢复。ARDY 动作、全身移动和完整 VRM 骨骼更新有更高优先级；观察组件让出控制，正常走近流程先等头部平滑释放再启动移动。已经修复一个更新顺序问题：在 `Update` 中临时还原头部，会让协程把刚拍摄的转头画面误判为视点已变化；现在只在下一次自身 `LateUpdate` 写入前移除旧偏移，检查不再读到这个未显示的中立姿态。

`captureId → actionId → confirmedCaptureId → 实际结果 → resultCaptureId` 串起每次行动。日志区分 `grounded`、`looking`、`confirmed`、`submitted` 与真正的到达；“已经定位”“已经提交”都不能作为已到达的依据。物体目标的结果单独记录，也不把“接近物体”误报成“已经走到用户身边”。

闭眼、聊天关闭、用户打断、响应失效、目标销毁或几何改变均有对应的取消和失效检查。旧请求完成回调不能恢复已取消动作，也不能取消后来接管的新动作。自主重复尝试同一意图、同一表面设有间隔，防止围绕同一个失败目标循环重试；这不是禁止角色先观察、再决定靠近。

目标变化检查同时保存对象自身 `Transform` 矩阵和 Renderer 的渲染矩阵/边界。实测发现同帧改变物体 Transform 时，仅检查 Renderer 数据可能漏掉变化，因此增加独立 Transform 连续性检查。静态合批或渲染数据更新时间是可能因素，尚未证实具体成因；修复后的实际目标移动中止已通过。

## 实际 Qwen：自主关注已验证，走近仍受目标定位限制

`live-qwen-r12` 的真实模型首轮使用新采集画面与现有角色提示词，输入 13,995 tokens，耗时约 2.928 秒，输出 47 tokens，`finish_reason=stop`。模型返回了带语言/发声标签的日语台词，而不是预判要求的 JSON。正常结束只说明没有被输出上限截断，不能据此判定它符合自主决定协议；该探针未把这些台词作为有效决定继续执行。

该缺口在于原通用 ephemeral 请求没有单独的 system 私有格式边界和 JSON schema，角色公开表达格式可能进入本应私有的预判结果。现在使用显式 `PostAutonomyIntentMsg` 链路，使这一内部步骤采用自己的格式契约，同时保留角色提示词，不强制 `proceed=true`。

`live-qwen-r13` 已取得新的真实模型结果：预判输入 14,387 tokens、输出 82 tokens，约 1.916 秒返回 `proceed=true`，产生观察“发光装置”的动机；随后空间决定输入 3,405 tokens、输出 155 tokens，约 1.572 秒选择 `approach-object`，像素为 `(0.5, 0.75)`。这次格式有效，但该像素的实际 GPU 定位属于透明/未知材质，生产执行正确返回 `rejected`。没有转头或行走，也没有自主到达结果；标签“发光装置”本身仍是模型解释。

`live-qwen-r14` 已完成一次真实重观察与重选。三次 HTTP 分别约 3.122、1.580、1.688 秒；初始像素 `(0.5, 0.75)` 被拒绝后，生产层采集新图，把原目的及实际失败交给同一模型，模型改选 `(0.53, 0.72)`，仍因透明/未知材质被拒绝。探针整体运行通过，最终行为是 `rejected`，没有头部或根节点动作。这证明重观察、模型重选和有限停止按规则工作，尚未解决该小型发光目标的可靠定位。

`live-qwen-second-view-r16` 的另一初始视角取得真实自主关注的成功案例。测试先用原生 ARDY 做目标偏航 -55° 的原地转向准备，实际根位置位移约 0.007016 米、朝向误差约 2.105°；这是测试准备，不是 Qwen 自主转身。随后真实 Qwen 根据新视野产生观察书架及窗外景色的目的，空间决定自主选择墙内书架像素 `(0.55, 0.45)` 的 `look-at`。实际头部转动后，新 `confirmedCaptureId` 对应画面准确确认同一表面，终态为 `observed`。模型这一轮选择观察，没有选择或执行走路。复测按任务终态确认原生准备已完成，不把暂时 `IsBusy=false` 当作完成。

探针上限仍是三次 HTTP：一次真实角色预判、一次原空间决定，以及至多一次由生产层请求的空间修正，总计不超过 60 秒；保留预判 128 token、空间决定 240 token、新输入文本 10,000 字符上限。第三次请求必须来自生产层新建的待处理请求，包含一次修正范围、原决定和真实失败原因，使用新的当前采集 ID，并原样发送生产请求。不会把第一次拒绝提前收为最终结果，也不会为了通过测试编造替代目标。以上继续使用现有同一份 Qwen，生成参数未因复测而改变。模型选择不行动时如实记录；历史格式失败不能归类为“角色选择了不行动”。

## 当前试用入口

1. 使用项目根目录 [start_all.cmd](../start_all.cmd) 启动服务。当前脚本先启动/复用远端共享 Qwen 的动作特征模式，再启动 ARDY，最后启动语音服务；任一步失败会停在对应提示。无需另加一个视觉模型服务。
2. 沿用已有房间聊天场景进入 Play 并开启角色会话。场景已有自动连接配置时沿用它；需要核查连接时，打开 `Tools → NeEEvA → ARDY Room Dialogue`，点击“查找当前场景配置”，Play 中可使用“连接本次运行的聊天呼唤”。
3. 打开 `Tools → NeEEvA → Character Scene Vision`，点击“查找当前角色视觉”。可以查看实际角色视野、采集 ID、图像年龄、视觉目标动作阶段和实际反馈。这个预览窗口不替角色决定目标，也不会为闭眼角色自动睁眼。
4. 留意角色无指令时是否形成关注动机；允许安静等待。手动说“看看那里”只能验证用户触发路径，不能替代自主行为验收。检查结果时同时看真实动作和窗口中的阶段，不只看语音描述。

当前代码默认启用视觉目标动作，但仍要求角色会话已运行、眼睛开启、房间动作通道连接、眼位已校准，且没有正在占用身体的任务。这里没有新增“让角色必定去某物体”的测试按钮。

本轮试用重点是无指令时的自主关注是否合适，以及模型是否能选择可定位、可走近的目标并实际到达。已有自主关注成功案例；真实模型自主走近仍待实际 Play 评估，不应仅因台词合理或受控行走测试通过就判定成功。

## 本批范围与后续

本批定位只接纳已支持材质的静态不透明表面。透明/裁切/未知材质会保守遮挡定位，蒙皮变形、LOD、Terrain 等未覆盖几何也不能算通过。图像可被主脑看见，与该像素可被引擎可靠定位是两种不同能力。动态目标追踪、抓取、设备操作、自动大幅转身和长时间自主探索尚未验收。

移动继续限制在已核实的同层地面，保留台阶、斜坡和落差拒绝。视觉解释“像台阶”不等于身体已经能踩阶；下一批跨高度仍需真实支撑、落脚、净空和上下中止能力。共享 Qwen 的新动作特征排队延迟也仍需监测，本批没有提高视觉调用频率来掩盖它。
