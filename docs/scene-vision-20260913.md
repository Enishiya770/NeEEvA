# 角色场景视觉第一批实现（2026-09-13）

本批把角色的视觉来源改为自己的 Unity 房间视角，并让实际图像进入自主预判、空间决定和正式回复。仍使用同一份 Qwen；房间电视继续显示桌面，聊天链路不再直接附加桌面截图。

后续更新：5090 已恢复连接，单图理解、真实自主预判回放及短程行走并发已完成验证，详见 [远端验证结果](scene-vision-remote-20260913.md)。完整提示词期间的新动作特征请求曾等待约 2.7 秒，不能把本次通过理解为所有请求都可即时响应。

## 行为与使用

在原房间 Chat 场景进入 Play，启动实时聊天。视觉默认随会话开眼；角色使用房间动作桥绑定的 VRM 和已校准的头部参考。无需新增或修改用户相机。`Tools → NeEEvA → Character Scene Vision` 可以找到运行中的视觉源，检查角色实际收到的图片、采集时间和观察身份。视觉组件在首次观察请求时建立，因此刚进 Play、尚未启动聊天时可能没有可选源。

预览更新只触发相机采集，不会独立调用 Qwen，也不会主动转头。先检查预览是否对应角色的当前位置和朝向，再询问当前能看见什么；没有用户新指令时，已有自主检查也会收到新画面，可以选择关注或保持安静。闭眼/停用会清除当前像素，保留的历史文字不能冒充实时视野。电视背面、被遮挡的电视或过小的屏幕文字均不应被当成可读桌面。

## 实现边界

- 相机位于角色校准眼位，跟随实际头部参考朝向。独立离屏渲染，不使用主相机、音频监听或 XR 跟踪。初版为 Built-in 渲染管线，960×540、65° 视场、JPEG 80，最多每秒 2 次按需采集；不是每帧模型推理。
- 通过独立网格代理移除第一人称头部/头发遮挡，保留可见身体。原 renderer 的临时隐藏只包围该相机的 Render，并在 finally 恢复；不修改用户视角中的层、骨骼或原始网格。
- GPU 像素异步读回；首次绑定仍有同步网格准备成本，不能称为全流程无主线程开销。关闭、销毁、换场景和晚到读回均有身份隔离，回调和待处理数量有上限。
- 每张图有不可变 `captureId`、采集时间/帧号、场景身份、相机位姿/FOV及尺寸。同一次自主预判继续执行时复用该图，空间决定与正式表达带相同的身份。新的移动决定若图像已过期或视点变化，旧决定失效，最多重新观察并规划一次。
- 正式回复最终发送前再次解析本轮视觉所有权，防止等待空间决定期间关闭视觉却仍发出旧图。历史图片像素归档；不在无图轮偷偷重发过去的画面。
- 用户“停下”保留提前语音准备；没有可复用提前准备时，在等相机期间并行进行只允许停止当前任务的文本准备。走向/跟随等新移动不会借此跳过视觉与实际路径检查。
- 修复空白启动音源：首次安装回声采样组件前，规范化没有 clip 的 play-on-awake 音源，避免没有真实语音时被判断为持续播放、压住自主观察。不会在正常运行中据空 clip 擅自停止流式 PCM。
- 电视显示 shader 改为背面剔除，沿用现有 Quad、UV 和安装方向；后端停止更新时屏幕仍可能显示最后一帧。角色看到的是电视当时实际显示的画面，角色截图时间并非桌面帧更新时间。

## 下一批

本批尚未新增自主转头/转身、可见物体的空间定位协议，或“自己选一件看见的东西并走过去”。现有走近用户、跟随、停止仍沿用房间控制器；不能把模型说出了物体名称当成已能定位并走到物体旁。

下一批在这些观察身份上增加注意目标、对应画面的射线/几何查询、物体旁合法站位和执行回执，让自主意图能落到真实位置。跨高度移动紧接其后，单独验证真实支撑面、落脚与身体净空。视觉识别台阶不会自动赋予现有平地动作链上下台阶的能力。
