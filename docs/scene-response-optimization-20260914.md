# 场景回复延迟与动作后复盘（2026-09-14）

本批延续 `scene-play-priorities-20260914-evening.md` 的评估：处理正式回复链路的重复输入、无效首审及动作后复盘排队，不新增台阶、抓取或任意场景编辑能力。

## 实现

- `FormalResponseStage` 随单次请求传入。已提交空间动作后的回复保留人设、原始要求、当前事实、记忆、能力目录与未完成意图，但不再携带本轮不能执行的整套技能语法。普通对话、自由动作及唱歌请求仍使用 General 路径；阶段不会留在 provider 的共享状态中。
- 完全相同的 `objectContext` 和长范围说明可引用此前的完整定义。不同时间、不同状态、不同实体或失败原因不合并；纯 C# 回归验证展开后的事实等价。
- 发起语音结果审核前，先取得本轮有效画面。可使用已有且来源相符的新画面；否则重新采集。审核过程中发生相关事实变化仍需重新审核，最多一次重试。取消、新输入、暂停、闭眼、禁用或更换角色/模型不会让旧回调发布内容或占着新请求。
- 动作完成事件合并到最早复盘时间；普通语音收尾不会将它推迟。旧用户轮次的动作事件先失效，再接纳新事件，避免连带丢掉新提醒。
- 最后一句语音已完成合成、仅剩本地播放时，允许一次只读私人复盘。其结果暂存，不能提前发声、执行工具或修改事项/记忆。自然播放结束后，仍须当前图像与原有决策、几何检查；新输入、事件、角色绑定或音频变化会撤销旧候选。

## 测量方法

使用既有隔离项目中的原房间和实际角色提示词、Qwen、ARDY、GPT-SoVITS 配置，走生产 `SendData` → 决策/匹配 → 正式回复 → 审核 → TTS → Unity PCM 播放起点。初始站位由实际 ARDY 前进到达，没有通过传送角色创造空间。

输入是三条预先固定的已确认文本：询问眼前家具、询问小灯所在家具、看电视并后退半米。显式保留已加载 singing 技能，以复现最近 Play 日志中的上下文条件。每个请求及失败都保留，没有挑最快重试。实际场景图像为隔离原房间，不是新采集的桌面。

这项测量**不含麦克风/ASR、人工停说点或私人持久记忆图**。音源静音但确实播放 PCM，不能据此声称听感验收通过。三例每组的规模也不足以推断所有对话的平均改善。

## 测量结果

干净基线 `baseline-live-r2` 的首 PCM 为 13.758、12.438、12.531 秒；第一次后测 `after-live-r1` 为 13.055、11.444、11.402 秒。中位数 **12.531 → 11.444 秒，缩短约 8.7%**。正式请求的 prefill 每轮缩短约 0.7–0.8 秒。这不等于已经实现实时回复，也未达到原先期望的约 30% 改善。

后退样例在两侧都被原有“小幅转头范围”检查拒绝，尚未提交该次后退到 ARDY；系统播报了未完成的回退，不能算后退成功。前两例的物件查看与语音链路完成。该限制不在本批动作能力修改范围内。

主要剩余成本是决策、物件确认、正式回复与结果审核仍有多个串行模型请求。本批没有删除客观事实、放过未验证动作，或用一句无内容开场代替正式回复来制造低延迟。

最终版本的 `after-live-r3` 三条首 PCM 为 **9.759、11.255、10.994 秒**。第一条改走普通视野检查，未执行基线的物件匹配，因此不能把整组三例中位数差异直接归因于优化。后两条路径相同，分别少约 **1.18、1.54 秒**；其中后退仍是拒绝后的如实回复。正式 prefill 在这两条上分别为 2.482、2.358 秒，对应基线 3.275、3.140 秒。样本小，结论仍是小幅改善。

中间诊断 `after-live-r2` 也保留：第一条普通回复附带点头，后两条遇到 `visual-reference-not-current`，没有完成所请求的物件读取/后退。该轮的较短等待不能算作执行改善。最终测试补充等待自由动作及其回待机结束，避免测试器在上个身体动作未结束时紧接下一条固定输入；它没有修改实际用户输入时的抢占规则。

`after-live-r3` 已确认实际 Qwen/TTS 链路在最后一句播放时开始私人复盘：物件查看的 WAV 与后退拒绝回复的 PCM 均触发 `private-playback-start`，前者在播放结束前得到暂存候选。测试器随后发出下一条用户文本或结束测试，旧候选按预期取消；本轮不声称已在真实模型测试中完成后续自主动作。自然播完后重新采图并续接、事实变化时重新复查、打断撤销的完整流程由真实播放器和受控模型回归覆盖。
