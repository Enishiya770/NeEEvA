### 2. 用户移动明显快于当前常用角色步速

源码中桌面相机默认 `moveSpeed=2` 米/秒，按加速键时乘 3。房间桥接的行走速度默认 **0.65 米/秒**，并直接传给控制器；原生目标构造将速度限制在 **0.15–1.2 米/秒**，没有依据用户速度/落后距离自动调整的闭环。

日志也有实际速度差：**93329→93406 行**的 0.757 秒内，用户水平移动 **1.503 米，区间平均约1.986米/秒**，角色还在采集历史、根节点未移动。其他准备区间也出现约1.94–1.98米/秒的用户移动。播放区间 **73480→73536 行**，用户区间平均1.143米/秒，角色约0.689米/秒。

这些是事件间位移除以时间的区间平均，不是逐帧峰值，也不是整次行走的平均。日志没有直接记录 Inspector 中最终速度或按键状态，不能声称每时每刻角色都严格0.65、相机都严格2。**可以确定的是实际存在“用户持续拉开距离”的区间；单纯让目标更新更快无法消除速度上限差。** 参见 [observed-motion-intervals.json](E:/VRproject/VR20250611/NeEEvA/Server/ARDY/runtime/room-follow-speed-review-20260912/observed-motion-intervals.json)。

本轮有 11 条事实明确记录 `committed-progress-pending-latest`：仍有用的旧候选已被安全提交，最新目标继续排队。没有证据支持“只有用户停下，系统才允许生成/执行”的硬规则。

当前滚动接缝需要约 **1.5–3.5 秒**生成提前量，同时每条目标轨迹最终减速停在用户附近。用户继续走、折返或接近时，新站位可能已经落在未来接缝的减速距离以内；即便 HTTP 速度正常，也会主动停稳再发下一段。该结构与用户观察到的“走走停停、需要自己等她”相符。

### 4. 一部分停止来自有效空间约束，不应为实时性直接放宽

本轮还有3次用户进入路径身体净距而暂停，2次视点距离其下方首个实体过低而不可用，以及1次离开原同层支撑而结束跟随。例：**93543行**用户离角色仅约0.648米，守卫停止；先前用户又向角色方向移动约1.197米。快速自由相机能够穿过家具上方、降低高度、突然折返，与受房间实体约束的人形步行并不等价。

## 对下一阶段的含义

应把“实时跟随”作为持续运动控制来设计：持续估计用户水平速度与行进方向，用落后距离调节目标速度并限制加速度；生成中的轨迹保留非零行走终速，用户稳定停止时才收尾；同时提供无需等待一次完整网络生成才能起步的可用步态。ARDY可以继续承担步态和风格，但每次网络生成、站位选择和最终停稳不应共同成为根节点移动的唯一时钟。

单次低速滚动测试已证明更新机制能工作，最新房间日志则说明它还没有覆盖普通键鼠速度、连续折返和短距离反复启动。下一阶段需要分别验证首个可见位移延迟、匀速跟随距离误差、用户加减速、折返以及安全停下；不能把多种原因合成一个“模型跟不上”的分数。

仍未知：实际帧级用户速度与输入状态、各生成阶段服务端排队/计算耗时分解、每次起步中站姿/转身分别占多少、所有片段实际步速、是否按下了相机加速键。这些限制不影响以上有日志和源码支持的判断。
