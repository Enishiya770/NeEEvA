# ARDY 条件迁移与泛化验证

目标是在同一份在线 Qwen 权重上取得动作特征，通过小适配器驱动 ARDY，并逐步支持对话中的自主动作。原 Llama 教师仅用于离线蒸馏；实时运行不加载第二个语言模型。

## 当前问题的证据

初始姿态投影曾把 Hips 的世界高度设成 0，而 Core27 `joints.p` 是相对 Hips 的坐标。修复后合成站立骨架脚部落在地面，真实 VRM 对照中的一个举手样本躯干最大倾斜从 48.01° 降至 3.03°。

这没有解决动作语义遗漏。同文本、seed 和历史下，8 个举双手案例中，原教师条件有 7 个出现双腕同时过头，原适配器为 0 个。该观察只是举手的必要条件，不代表动作自然或全部细节正确；教师本身也有失败案例。

## 数据与选择规则

- 原 2,000 条、原始特征和已验收 checkpoint 保留不变。
- 新增文本是人工编写的组合模板，包含动作侧别、目标高度、方向、次数和先后关系。同一配置的 8 种表达保持在同一 split；这些句式不是独立动作能力。
- 新增描述与原宽泛动作描述有语义覆盖，因此旧 val/test 只用作能力保留检查，不能继续称为未见动作泛化。
- 独立冻结的 `generalization-eval-v1.jsonl` 有 40 个配置、80 条表达，其中 32 个配置属于当前原地上身接口，8 个用于记录接口边界。它检验保留的配置与表达，允许共享原子动作；不代表所有原子动作从未参与训练。
- 教师导出每轮先用两个原缓存控制样本做数值核验。Qwen 特征走实际在线特征接口，核验部署模型 SHA 和特征合同，不加载另一个 Qwen。

预先固定四个候选：从头训练和旧模型继续训练，各 seed 0/1；训练最多 100 epoch、patience 10。旧、新训练域各占一半损失；所有候选冻结原 checkpoint 的目标均值/标准差，保证保留指标可比。

选模只看旧、新 validation。门槛是旧域标准化 MSE 不上升超过 5%、余弦下降不超过 0.001；新域 MSE 至少下降 10%、余弦不下降，按语义配置配对 bootstrap 的 MSE 改善区间下界大于 0。特征合格仍需要实际动作验证，不能直接视为上线许可。

## 动作验证

开发动作验证预先固定每个新 val 配置的一条表达、seed 0/1、冷启动和真实捕获的 16 帧上身历史。教师、旧适配器和锁定的新候选使用相同条件；保存原生骨架、Unity clip 和逐帧观测。

几何观测包括腕部高度、躯干/头部旋转和位移。任何一帧达到高度只说明出现了必要姿态。掌向、重复次数、顺序、持续时间、穿模和自然度需要额外审阅；报告不会自动写入整体语义成功。

候选锁定后才运行独立最终审计。最终结果不得返回训练或候选选择流程。边界配置不计入上身动作成功分母。离线 ARDY 窗口耗时不等于含在线 Qwen、网络、Unity 和语音并发的端到端延迟。

## 工具入口

- `Tools/MotionAdapter/generate_generalization_corpus.py`：版本化文本与配置清单。
- `Tools/MotionAdapter/export_qwen_http.py`：真实共享 Qwen 特征导出与恢复。
- `Tools/MotionAdapter/export_teacher_full_cuda.py`：固定原教师的离线完整 CUDA 导出。
- `Tools/MotionAdapter/merge_extension_bundles.py`：校验来源与合同后合并，保留原数据字节前缀。
- `Tools/MotionAdapter/train_extension.py select`：固定候选的 validation 选模。
- `Tools/MotionAdapter/train_extension.py audit`：锁定候选的显式 test 审计。
- `Server/ARDY/evaluate_native_motion.py`：配对原生动作评价；test 需要显式一次性审计。

当前运行接口应用上身旋转，根位移和下肢不是实际执行通道，也没有单指、抓取或接触约束。走动、坐下、拿杯子等需要扩展身体状态和执行接口，不能仅靠增加文本蒸馏数据宣称已支持。

原生开发验证保存 480 段配对轨迹；实际 16 帧历史下，28 个带明确高度条件的观察中，旧适配器有 15 个达到必要高度，新候选与教师各 23 个。达标不等于掌向、动作次数、顺序或自然度正确。

同一候选又完成 4/8/16 帧初始历史对照。缩短历史没有整体加快到达目标，接缝最大旋转跳变的 P95 略高，因此本版仍固定默认 16 帧。后续窗口也保留 16 帧。该实验没有改变适配器或从最终测试反向选参。

新候选离线每个 40 帧窗口中位耗时约 109.5 ms、P95 124.6 ms。实际共享 Qwen + 候选 HTTP 的六条 validation 描述全部连续生成三窗，173 项检查通过；首窗中位约 354 ms，三窗合计中位约 598 ms。六条样本规模很小，且没有语音并发。这些是计算和传输耗时，不代表动作已经到达目标姿态，更不是完整聊天响应延迟。

## 当前部署与回退

本机已激活发布 `ardy-preview-6364a5984590a06a04ff662e`。正常的 `Server/ARDY/start_motion_service.ps1` 会校验 active manifest 及归档证据后加载该候选，默认端口 8093，连接同一共享 Qwen 8080。原教师没有驻留动作服务。

新版实际 Unity 检查使用生产代码、真实 Animator 历史和真实 HTTP：首窗约 0.97 秒，三窗约 1.48 秒，完整播放 120 帧；结束和中途取消后的 Animator 对照误差为 0°。479 项真实 ChatSample 断言与双 VRM 的流式/历史协议检查通过。该测试未运行私有聊天场景、实时麦克风或 TTS，不构成完整场景自然度验收。

发布将最终特征/动作、HTTP、Unity 报告与完成 trace 固定归档，避免八份诊断轮转导致证据丢失。selection 的 `approved_for_runtime=false` 仍保留，health 明确标识 `verified-preview` 和 `naturalnessAccepted=false`。这表示证据核验后的试用版本，不能解释为任意动作均已验收。

如果需要回到原适配器，先停止当前动作服务，再运行：

```powershell
& Server/ARDY/start_motion_service.ps1 -BaselineAdapter
```

恢复新版时，停止回退服务后使用普通启动命令即可。无需修改模型文件、已有四手势或播放器。当前实际端口和模型的验证记录见 [运行报告](../Tools/MotionAdapter/reports/generalization-preview-running-v1.json)。

## 自主动作与后续范围

Qwen 可以在合适语境下自主选动作，也可以响应明确要求；“随意做一个动作”会先落实成具体描述。描述包括侧别、方向和目标姿态，控制在一次六秒动作内。普通聊天可以不做动作，基础四手势优先使用已经验收的资源。自然交流默认小幅动作，但明确的举双手要求不会被“原地站立”误拒绝。

当前动作仍在完整回复结束后触发，并非逐 token 或与语音音节同步。本轮真实 Qwen 的 7 个合成语境通过协议验证，证明正常请求可以进入执行通道；它没有证明任意对话中的自主时机都自然。

下一轮重点应是记录真实对话失败并另建新的冻结评价集、加入更接近部署语境的动作监督，以及评价语音并发、动作时机和更长序列。复杂顺序、精确掌向和接触动作尚不能承诺；需要完整身体移动时，还必须扩展执行接口与环境约束。

用户后续的前举直臂＋手腕轻摆反馈已完成固定对照，确认持续持姿和局部动态仍不能仅靠一句文本与初始历史可靠执行。生命周期事实和组合规划规则已补充，但模型的实际约束遵循仍未解决，详见 [本轮诊断与验证](ardy-composition-diagnosis.md)。
