# 2026-09-11 说话转唱歌与复读修复

依据 [感知核查](2026-09-11-speech-to-song-perception-review.md) 与 [复读复盘](2026-09-11-singing-repetition-review.md) 实施。用户这轮是先说话、再自己唱，没有要求角色回唱。

## 已修改的行为

1. **完整听觉事实保留。** 流式草稿携带录音身份和当时覆盖时长；最终转写到达后，先检查是否仍适用，再处理模态融合。旧话题草稿、歌词回滚造成的不一致不再拥有整轮否决权。普通说话、唱歌或不确定的测量均保留完整文字、音符及音域，动作是否允许另行判断。同轮 speech/singing 判断并存会呈现冲突。
2. **用户表演与角色任务分开。** 正式输入和歌唱规则明确区分已发生的用户演唱、要求角色回唱以及角色自主选择。`sing_goal` 标记 `origin`；独立审核给出任务来源和真实用户请求引文，再核对素材身份、范围、版本。程序只能核对引文是否存在，语义是否构成请求仍由模型判断。没有请求或合规自主目标时取消误建任务；自主动作仍在既有权限内独立审核，不要求用户逐次发指令。
3. **待审核是等待。** 同轮提交目标并尝试唱歌，只登记 pending，不记失败、不遗留工具纠错、不声称后台受理。审批前一次核对素材是否存在、版本是否匹配、current 是否已选定及边界是否有效。
4. **重复失败按实际方案计数。** 相同参数、目标与素材状态再次被拒绝会停止自动续接。换台词、道歉或修改 reason 不重置计数。立即纠错与定时事项续接共享三次预算，新用户输入才重置本轮状态。停止时留下单次应用通知，不冒充角色说过的话，也不把未执行记为成功。
5. **承诺在校验后外放。** 歌唱技能生效期间，流式正文先暂存至本轮工具与目标校验结束。待审核或被拒绝的本轮台词不进入 TTS，也不记作用户已听到。代价是相关轮次的首句需等完整生成及校验，普通对话原有流式路径继续保留。取消误建任务后，如果此前没有外放回复，会给角色正常处理完整输入的机会，允许明确选择安静。
6. **纠错提示保持一致。** 通用行为提示和工具反馈均允许内部修正，不要求每轮发声。`revise` 明确表示审核已结束、需要提交修改后的目标；`next` 或 `continue` 不能代替修改。具体音高参数属于后续 sing 动作，不要求目标草案填写协议不存在的字段。

- `ChatSample.SingingGoal.cs`、`ChatSample.SelfInspection.cs`、`ChatQW.cs`：任务来源、独立审核契约与真实素材校验。
- `SenseVoiceSpeechToText.cs`：中性听觉测量保留。
