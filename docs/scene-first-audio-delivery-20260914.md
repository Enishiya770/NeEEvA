# 首句与首音链路交付：2026-09-14

本批执行 [上一轮批准的方案](scene-first-audio-assessment-20260914-late.md)：修复语音交接与内部文字误播，建立同一 Qwen 的普通对话首答路径，接入倾听阶段端点准备的严格复用。原 Unity 场景、远端模型和现有服务配置未由本批替换或重启。

**结论：普通对话的串行等待明显减少；“实际停说到有意义的声音 ≤1.5 秒”仍未达标。** 当前证据可支持交付这批改动并进入真实 Play 验证，不能宣布首音目标完成，也不能宣布所有动作测试通过。

## 已完成

- **同一 Qwen 决定首答通道。** 普通对话可在一次请求内选择 `ordinary` 并流式输出正式台词，不再固定先进行完整房间规划。涉及新图像、动作、歌唱、工具及结果核验的请求选择 `tools`，回到现有执行与审核链。程序没有用动作关键词替角色决定意图，也没有增载第二个语言模型。
- **保留人设、语言规则、完整原话及历史。** 首答只带必要运行摘要，未消费的完整观察仍保留；旧图不算当前视觉证据。真实用户记录按对象与请求代际移交，即使在工具规划期间被打断也保留；连续两轮相同原话仍分别记录。私人准备不写成已发生的对话。
- **修复缓存应声误停正式语音。** 取消和交接绑定实际 clip；旧应声不能误停新正式 clip。首音记录须看到属于本轮 clip 的 DSP 播放进度，正常补缓冲暂停也不会被当成播放结束。首答直达期间保留音源给正式台词；回退慢流程后仍可尝试原有应声。
- **收紧公开台词边界。** 首答使用明确语言、发声阶段和 `say` 边界；内部事实、执行记录、工具标签不直接交给 TTS。原流程增加记录头隔离。逐字空格与换行保留；收到正文后再失败，不盲目重跑整轮或重播已听前缀。
- **复用倾听中的端点准备。** 原有同一次草稿请求可以携带条件式 `quiet_boundary`，仅在录音、原文及修订号、活动版本、ASR 静音覆盖、置信度与新鲜度都吻合时，省去一次停话后的语义边界请求。改口、续说、歌唱、覆盖不足或过期均回退原复核；最终 ASR 仍保留，没有调低原静音门槛。

本批没有完成“所有正式答案及音频都在用户说话期间提前准备好”。新增端点复用是否能在实际说话中稳定命中，还需要真实录音统计。

## 实际系统音频核验

独立问句：`你更喜欢安静还是热闹的夜晚？请用一句话说出理由。` 使用同一真实模型和音色，同时保存该 AudioSource 的只读 DSP 参考和 Windows WASAPI 系统输出，按波形匹配确认来源。录制限定单次最多 20 秒，不使用麦克风、不修改系统音量。

最终 [回环匹配](../Server/ARDY/runtime/first-audio-delivery-20260914/loopback-delivery/match.json) 成功，归一化相关系数约 0.99999999。同源有效信号位于 WAV 样本时间轴 **1.954 秒**，信号检测区间约 1.944–1.964 秒；同期 Unity 播放进度为文本提交后 1.793 秒。设备给出的 ADC/current 时钟关系未通过检查，因此没有生成精确的“文本提交到系统输出”绝对时钟结论。这是系统输出证据，仍不等于人工听感验收或真实麦克风停说至首音。

该条 TTS 源文本还暴露了语言一致性问题：声明 `ja`，正文却是中文。格式边界合法不代表语言语义正确，不能把这条记录算作自然日语质量验收。旧路径基线也出现过中文正文混入日语声明的情况，本批没有解决这项模型输出质量问题；下一轮须单列检查，不能只看起声时间。

## 回归与保留的失败

最终 [controlled-delivery](../Server/ARDY/runtime/first-audio-delivery-20260914/controlled-delivery/report.json) 完整通过，Unity 进程退出码 0，日志无 C# 编译错误。包括公开台词边界 15,328 项、端点策略 81 项及实际入口 27 项、首答传输/历史 967 项、音频交接 21 项、真实 ChatSample 首答/取消/回退入口 71 项，以及已有场景与协议检查。系统回环工具的 10 项离线自测也通过。枚举数量含分包边界组合，不表示同等数量的真实对话。

迭代证据全部留在 [本批目录](../Server/ARDY/runtime/first-audio-delivery-20260914)，未仅保留最快结果：

- `after-live-r1` 的测试计数前置条件错误；`r2` 暴露了补缓冲被误当作结束的真实缺陷，已修复；`r3` 为编译失败；`r4` 才是四条完整运行。
- `controlled-final` 至 `r4` 保留辅助捕获脚本的 GUID、Unity 挂载位置及首次导入编译问题；最终 `controlled-delivery` 才是干净通过结果。
- `audible-final` 无有效系统语音：隔离几何场景移除了相机及 AudioListener。它不能算可听首音成功；补上隔离监听器后才重做回环。

## 视觉与动作能力检查

[vision-actions-final](../Server/ARDY/runtime/first-audio-delivery-20260914/vision-actions-final/response-latency/report.json) 中两条观察请求取得新图并完成观察，播放器首音约 12.34 / 12.56 秒。后退半米正确进入 `reposition-view`，定位与导航预审核通过，但 ARDY 返回 422，角色实际位移为零，并如实反馈未完成。约 15.00 秒的首音是失败反馈，**不是移动成功**。外层 `completed` 仅表示该对话流程收束，必须同时看 `sceneAction.lastAction.phase`。

该端点现有代码中 422 对应 `locomotion_quality_rejected`，即生成候选未通过完整窗口动作审核；本次没有保存错误响应正文，无法进一步确定高度、位移还是关节跳变项。相关动作控制代码与本批基线一致，更支持既有动作生成/审核问题；缺少同条件基线后退样本，不能完全排除时序和起始姿势差异。本批未降低质量门槛。

## 下一轮真实 Play 重点

1. 普通问答和唱后转聊天：听到的第一句是否具体相关，是否自然完整播放。不要把缓存应声计入正式首音。
2. 说到一半停顿、尾句否定及立即改口：不抢话、不丢原话、取消后不漏出旧回复。
3. 查看 `[Semantic EOU/Prepared]` 的 ready/hit/miss 原因，并关联实际最后发声、最终 ASR、首句文本与系统输出。当前纯策略测试不能证明真实命中率。
4. 单列动作/新视觉/歌唱请求：保留原执行事实与失败反馈，分别统计任务承接、正式回答、动作开始及完成。

下一步性能投入应围绕**听中准备命中率、首句实质性和 tools 误分流长尾**；目标仍是实际停说后 1.5 秒内有意义的声音，不能用这次 1.81 秒的局部链路中位数替代。
