## 静默时究竟在运行什么

当前自主循环是间歇模型推理。`StepUrge()` 每帧推进 C# 数值；到触发条件才调用 `BeginAutonomyIntentProbe()`，采图并请求 Qwen。没有这次请求时，该循环没有持续的语言模型思考。Animator、声音检测、部分记忆激活及其他引擎状态仍可运行；记忆漂移的代码选取/激活也不等于 Qwen 在不断思考。

这与“世界完全停止”不同，但模型并未逐秒观察整个等待过程。它在下一次请求中读到新的画面和状态，再作一次判断。能以功能方式提供时间推断与连续行为，不能由这些程序日志判定有人的主观时间体验。

已有时间上下文包括本地当前时间、最近发言是多久前、距用户上句、会话时长，以及最新动作的 UTC 时间戳。然而缺少直接的 `sinceArrival`、`stationaryFor`、`gazeHeldFor`、`sinceLastDecision`。模型可能从时间戳推算，但现在不能可靠地假定它知道“我在书架前已经站了几分钟”。最新 `SceneActionFact` 还会被下一次观察/拒绝覆盖，`observedUtc` 是状态更新时间，不是独立保存的到达时间。

Character Scene Vision 窗口每秒更新预览，仅是本地预览采集；不代表每秒把新图送给 Qwen。

## 45 秒如何变成 85.5 / 126 秒

`UrgeModel.SetNextIn()` 当前把模型请求乘以连续 AI 轮数形成的疲劳因子：

`目标间隔 = requested × (1 + 0.45 × consecutiveAITurns)`，随后应用上下界。

所以 45×1.9=85.5、45×2.8=126、30×2.8=84。这里的疲劳是控制连续独白的程序参数，不是测量角色的身体疲劳。

还有第二层：`proceed=false` 同时设置 `notBefore = now + wait`；在此之前 StepUrge 不推进累积。有效环境声音可清除此门，记忆/孤独等也会影响后续累积。图二中环境增益额度已经用尽，无法继续通过该渠道提前唤醒。

因此不能把 requested、EffectiveSec、实际两次请求间隔混为一谈。日志中“她排的45s→实际126s”的“实际”打印的是 EffectiveSec，根本没有测量这段实际墙钟耗时。截图的 14:28:02 至 14:29:56 约 114 秒，已经表明它不等于日志所谓的126秒；也不能断言每次固定等45+126秒。

连续 AI 轮数还包含内心内容或纯 `<silent/>` 的正式轮，下一次观察/行动统一受疲劳影响，感知文字却把它描述成“已连续说话 N 次”。提示词虽然明确允许无声行动，但新意判断仍主要参照“最近发言”。所以安静、无新话题、无探索需求这几个概念在现有框架中没有充分分离。

## 为什么没有主动环顾

模型已经被告知可以看向当前图像目标、可以自主走近。能力缺口在执行接口：当前 `look-at` 和 `approach-object` 都必须选择当前图片里的一个像素，没有“先向左看看有什么”“抬头查看上方”或原地转身的独立意图。

头部组件默认只支持左右50°、上25°、下30°；超限会拒绝，不会自动转身体。走近流程让角色停在目标附近并面向目标，后续视野自然主要仍是书架。这样很容易反复得到相近画面，再被判为没有新意，而改变未知视域的动作还不能下达。

当前相机朝向是头向视野近似，取 `HeadFrameRotation`，不是直接取双眼眼球旋转。普通眼球追踪用户不等于给模型扩展视野。

代码依据：[RoomTaskProtocol.cs](../Assets/AIChatTookit/Scripts/Chat/RoomTaskProtocol.cs) 8、15–17；[NevaSceneAttention.cs](../Assets/AIChatTookit/Scripts/Perception/NevaSceneAttention.cs) 16–18、173–175；[NevaSceneVisionCapture.cs](../Assets/AIChatTookit/Scripts/Perception/NevaSceneVisionCapture.cs) 93–101。

## 同时发现的两处事实范围错误

**物体走近错误依赖用户脚下地面。** [ArdyRoomObjectApproachPlanner.cs](../Assets/AIChatTookit/Scripts/Motion/ArdyRoomObjectApproachPlanner.cs) 50–60 在生成物体附近站位之前强制用户脚下支撑合法、与角色同层；[ArdyRoomDialogueBridge.SceneTarget.cs](../Assets/AIChatTookit/Scripts/Chat/ArdyRoomDialogueBridge.SceneTarget.cs) 144–146 每步也重复此要求。桌面相机在沙发上方，会把角色去书架的任务拒绝掉。

修复范围应限定物体接近：沿用有效用户锚点和追踪校验，以当前 XZ 提供保守身体净距，明确它是 `UserClearanceCenter`，不声称是用户真实落脚点。角色起点、路径、目标地面、碰撞仍执行全部审核；用户真正进入路线净距仍应平滑停止。接近用户/跟随用户保留其自身地面目标验证，不因为这个修复放宽走上沙发。

**纯观察台词也被用户路线变化否决。** [ChatSample.RoomTask.cs](../Assets/AIChatTookit/Scripts/Chat/ChatSample.RoomTask.cs) 301、350–359 对所有非 none 意图比较用户目标 revision，包括 inspect 和视觉动作；387–389 的 inspect 兜底正是“暂时还没有确认可以走近的路线”。322 附近还会把替代内容写回模型历史。当前样本确实被 facts-changed-during-review 拒绝，但日志没记具体变化字段，不能断言当次必然由相机移动触发。

用户相机移动1厘米或到用户的路线评估改变，都能增加该 revision（[ArdyRoomDialogueBridge.cs](../Assets/AIChatTookit/Scripts/Chat/ArdyRoomDialogueBridge.cs) 889–902、943–957）。应按意图审核相关事实：物体动作绑定 capture/action/target/result；保留 inspect 作为空间状态查询的原定义，纯图像评论走独立视觉表达范围，避免被误分为查询用户路线。用户目标变化不能自动把“书架是空的”改成移动失败。给模型的紧凑状态也须标明 assessment 是“到用户的路线”，分开追踪有效和脚下支撑有效，避免它把用户不可达理解成整个房间不可移动。

## 下一批方案：持续维护状态，按事件决策

目标是让无声观察有连续性，推理资源按需要使用。保持安静、休息和长时间关注都应是可理解的选择；不把每隔固定秒数必须动一下作为验收标准。

### A. 先补时间、节奏与行动事实

1. 用单调时钟维护活动持续时间；墙钟只负责日期/时间。显式区分 Play 暂停、应用关闭、未观测时段，恢复时不伪造中间经历。提供距上次决策、真实到达、停止移动、视向改变、有效观察的秒数。
2. 保存当前活动、目的、开始时间、预期停留及复查时刻，分开“最近完成的移动”和“最近一次失败尝试”。一次失败不能抹掉已经站在书架前的事实。无行动决定只保留简短状态/目的，不把每个内部 JSON 塞进普通聊天历史。
3. 把语音自发输出的冷却与私下观察/决策分开。无声观察不增加“连续说话”计数。复查只按一个明确截止时间排程；记录 requested、actual_elapsed、推理排队时间和 wake_reason，去掉隐藏双层等待。
4. 到达、失败、用户呼唤、视野变化成为独立事件。事件能撤销过时的长等待，但仍遵守用户讲话、身体控制和模型并发边界；忙碌时合并事件，恢复后及时处理。
5. 修复上述物体任务与用户地面、台词审核事实范围的交叉依赖。只在角色/目标真实状态改变时使该任务的决定失效。

候选初始节奏用于验证，不是人的认知频率承诺：执行结果可在服务空闲后的约1–2秒发起一次处理；主动观察阶段约5–10秒重新考虑；安静休息约20–45秒或按模型选择的更长时段。配合每分钟预算、事件合并与单个自主请求在飞限制，再根据实际延迟调整。不能保证请求发起后1–2秒已经完成Qwen推理。

时间上下文示例（将由真实状态计算，不写死这些数值）：

> 当前活动：观察书架；128秒前实际到达；127秒没有平移，82秒未改变头部视向。上次你决定继续观察30秒，现在已过32秒。期间只在列出的时刻采过图，两次采样相近；未采样期间的视觉事件未知。可选择继续看、改变视向、离开或休息，不要求说话。

### B. 补主动改变视野，再决定去哪里

1. 增加有界 `orient-view`：相对身体 yaw/pitch、观察目的和短暂保持。它不需要预先选中一个物体；只说“查看左侧未知区域”，不能声称已看见那里有什么。
2. 实际头部稳定后采新图，将采集身份与注意目标绑定。需要继续向外看或长期保持新朝向时，增加真实原地身体转向，复用同层全身执行与净距检查。不得直接旋转角色 Transform 代替步态转身。
3. 记录实际看过的方向及时间、当前注意目的、观察是否有进展。由模型选择下一步；一次探索只允许少量观察步骤，每步根据新图可提前停下，不采用固定左中右循环。
4. 保持头眼/身体控制权仲裁，避免用户注视、ARDY动作与自主环顾抢同一骨骼；停止和闭眼立即使后续旧回调失效。

## 验收和成本边界

先完成 A 的有界回归，再做 B 的真实头部/原地转向验证，随后在现有房间做一轮 Play，不创建新测试场。仍使用现有一份 Qwen 和 ARDY，不引入第二个语言模型或此时启动训练。

- 模型可根据真实状态回答“我在这里多久了”，并区分站着、观察与未观测间隔；不要求声称主观感受。
- `proceed=false`/无声观察不积累发言疲劳，模型要求45秒复查时不会被暗中乘成126秒再叠一层等待。
- 自主到达后，能选择继续看、环顾、离开或明确休息；选择环顾时得到书架以外的真实新视野，不只在原画面反复挑像素。
- 桌面相机在沙发上方、但离物体路线较远，不再拦截物体接近；移入路线净距时仍停止。已有用户呼唤、连续跟随和平滑停止不退化。
- 回执分别记观察完成、实际到达与失败，不因无关的用户路线变化生成误导性的移动失败台词。
- 视觉评论审核期间移动桌面相机，不应被改成用户路线失败；真正声称“到你身边了”时用户移走，仍须按相关事实拦截。审核日志记录实际变化字段，正常日语回复也不因无关状态变化强制变中文。
- 记录每分钟自主请求数、各阶段等待/推理延迟和新视野获得次数；用这些判断改善，避免单纯提高调用频率。

跨高度接在这两项之后。当前卡点包括观察机会与动作接口，不需要先重训 ARDY；修复后再扩展台阶，才能评估角色是否真正在依据视野选择路径。
