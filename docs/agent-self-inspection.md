# 角色自检与未完成事项续接

2026-09-10。针对角色说「ちょっと待っててね」后，被待机“没有新表达动机”判断阻断的问题。

后续歌唱日志暴露了观察交付与目标验收的缺口，已在 2026-09-11 继续修订。当前行为和验证见 [角色事项与歌唱执行闭环](agent-work-loop.md)；下文验证表保留首次实现的历史记录。

## 本次故障的依据

截图与本机 Unity 日志中，角色在用户询问预制动作后，输出的是点头和定时思考：

```text
ちょっと待っててね。<motion name="nod"/><next in="5s" focus="平静"/>
```

没有检查工具调用。`next` 只排下一次思考，不会检查数据。旧的定时预判只询问新意，又禁止自身执行工具，随后选择了继续安静。因此问题包含“没有实际检查”和“未完成事项进入闲聊筛选”两部分。播放结束仅表示这一段音频结束，不能证明原问题已经解决。

## 运行路径

1. 接受真实用户输入时，在当前会话内记录该事项及程序持有的续接预算。
2. 正式回复完成后保留有长度限制的执行通道记录。记录不代表其中承诺已执行或动作已成功。
3. 下一次空闲预判先处理尚未结束的用户事项，单独判断 `continue / waiting_tool / waiting_user / closed`。这次不同时寻找新的闲聊动机。事项关闭后再恢复普通自主意图判断。
4. `continue` 通过已有反馈续接接口回到同一角色。事实放在已完成回复之后，不在模型历史里伪造新用户发言。模型省略下一步措辞时仍可重新判断原请求；不依靠“稍等”等关键词触发预设业务操作。
5. 新增只读自检请求；程序读取后持有真实结果。等当前语音管线收尾，再由独立定时事件直接交回角色，不经过新意或疲劳筛选。
6. 角色根据结果回答、采取已支持且适当的下一步，或说明限制。下一次事项审查可确认结束；若仍没有完成，使用剩余续接预算。

主要实现是 `ChatSample.SelfInspection.cs`。现有 `ChatSample` 负责接入输入、输出、调度和反馈管线，`ArdyDialogueMotionBridge` 提供已绑定控制器的观察接口。

## 自检范围与边界

```xml
<body_inspect scope="motion"/>
<body_inspect scope="runtime"/>
```

- `motion`：通过绑定的 ARDY 控制器读取四种注册基础动作的资源存在性、解析有效性和控制器绑定状态，以及当前动作上下文。生成开关和远端服务健康状态分开；本工具不执行远端健康检查。控制器未绑定或提供者异常会返回明确的观察限制。
- `runtime`：当前对话循环、语音播放、待处理文字/音频队列、已有工具是否在运行、记忆组件是否存在。没有文件内容、密钥或任意组件反射接口。
- 只允许 `scope`，不接受文件路径或写入参数。基础资源路径来自程序注册表，不由模型选择。
- 同一真实用户事项内，每种 scope 最多执行一次。重复标签不会再次读取或制造新的结果轮次。私有文本块、代码示例、发声包装中的标签和不完整标签不会变成调用。
- 事项自动续接最多三次，由程序计数。格式无效的进度结果也消耗同一预算；用完后记录未完成，并显示独立系统错误提示（遵守用户的系统提示显示设置）。没有把这种情况标为成功。
- 检查结果在正式回复有效返回后才确认交付；构造观察、预判或仅派发请求都不消费结果。用户说话、在飞回复、实际音频输出等仍受既有保护。过期模型回调不能执行工具。新用户输入或停止会话会清除旧事项；自主自检不会重新打开已结束的用户请求。
- 此版本需要 Agent Loop 运行。关闭事项/自主预判开关时仍保留原先的闲聊轮数上限；已经完成的自检结果仍有独立交付路径。

这里是当前用户事项的会话内续接机制，不是跨重启的任务数据库，也不是通用项目文件浏览器或自修改代码系统。资源有效并不证明已经完成动作、动作自然或任意语义请求可执行。

## 验证

结果与源码摘要见 [verification.json](../Logs/agent-self-inspection-20260910/verification.json)。

| 检查 | 结果 | 范围 |
|---|---|---|
| 新增生产代码回归 | 68 项通过 | 原请求/回复资料、状态判断、预算、只读检查、去重、异常提供者、真实资源校验和过期回调 |
| 隔离 Unity Play Mode | 12 项通过 | 实际 `FireTick → 预判回调 → 正式反馈 → 自检解析 → 结果定时唤醒 → 正式反馈`；模型/TTS 为测试替身，资源读取使用生产控制器 |
| 既有动作对话回归 | 1,306 项通过 | 流式动作通道、解析、生命周期及聊天挂接 |
| 既有动作反馈回归 | 254 项通过 | 修订、预算、回调、空输出和失败提示 |
| 既有语义动作回归 | 322 项通过 | 原协议与约束传递 |
| 现有 Qwen 的公开开发用例 | 6/6 状态符合预期 | 承诺但未做、已回答、等待用户、真实工具运行、已说明限制、取消 |
| 独立中日英用例 | 4/4 状态符合预期 | 另外设计的声音队列检查、名称问答、澄清和没有真实操作的等待 |
| 公开检查请求与结果回答 | 生成合法检查标签，随后给出资源列表及未绑定限制 | 第二次输入使用真实未绑定测试实例的资源快照；模型返回的动作不实际执行 |

公开模型回放使用 Unity 导出的生产提示与固定公开上下文，没有使用私有人设、用户聊天历史或保存推理通道。十个状态用例规模很小，不能作为通用语义可靠率。留出用例中，模型有一次虽正确选择 `continue`，下一步措辞仍写成等待检查完成；实际执行层没有据此伪造任何在飞操作或结果，正式角色仍需根据工具协议选择必要操作。

较早的联合“进度+新意”提示曾分别出现过度续接和误判结束，失败输出保留在 `public-model-probe-v1/v2/v3.json`；最终改为独立事项判定。初次隔离测试的缺失 UI 装配、AudioSource 激活瞬间状态和未同步的行为资源也保留了失败记录，补齐装配后通过。

额外运行的 `SkillRoutingRegression.RunBatch` 整套旧测试在 `RunFormalAudioChoiceRegression` 中停止：它按一个参数反射调用 `TakePreparedFormalReply`，而当前代码及本次修改前的 HEAD 均要求两个参数。这一旧测试问题未在本次改动中修订；其此前执行的自主意图路由测试已经返回。不能将这次整套运行记为通过。

未在用户的私有聊天场景内重新使用麦克风、实际 TTS 和实际角色动作组合重演截图场景。加载更新后的脚本并重新进入 Play Mode 后，观察日志中的 `[Agent/未完成事项]`、`[Agent/自检]` 与 `[Agent/事项进度]`，可区分仍欠工作、实际读取结果和正常结束。
