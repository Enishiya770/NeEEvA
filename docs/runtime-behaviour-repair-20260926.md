- 素材决策与独立审核都能看到头尾文字、测得片段类型、范围及重叠事实。`clean` 是候选范围，不是已证明完美的歌声裁剪；选择素材、确认来源、审批目标与真正播放仍各自核验。

- WorkReview 的 Local 与主场景实际使用的 OpenAICompatible 后端改用与 Actor／录唱决策一致的严格 `json_schema` 请求。原 OpenAICompatible 仅请求 `json_object`，实际 vLLM 回放中曾返回表格定义本身；旧 Local 使用同级 schema 字段。这两条路径现在均使用标准 schema envelope，原 Cloud 后端保留 JSON-object 兼容路径及程序校验。
- 来源感知的待审录唱目标使用独立审核上下文：程序生成的完整审查包保留当前原话、时序历史、录音来源与范围、当前／旧目标和真实播放事实，提供方不再叠加角色人格、工具写法或角色记忆指令。普通事项和旧协议审核仍沿用原上下文。该调整避免审核员同时收到“扮演角色并提交工具”的任务。
- `none` 中的承诺线索只触发一次语义复审，不直接由关键词生成动作。复审保留完整草稿、动作类型、对象和条件；普通不涉及这些线索的回复不增加复审请求。
- Fast 重答重新使用最新兼容帧，必要时重新拍摄。新帧、视觉事实和后续规划使用同一份图片；旧输入或输出所有权失效后，迟到图像不再发请求。单次未附图不等于全局失明。
- General／Actor 未能形成有效回复时，用当前轮语言给一次事实性收口，不把系统问题归因于用户说法，也不重复双语播报。

## ASR 与外放

只读健康检查确认现有 ASR 位于 DGX `.163`，SenseVoice 使用 CUDA。该事实不能证明房间中的噪声识别准确率。

- 候选录音与角色外放重叠时继续允许严格 AEC／身份打断检测。通过后升级同一 capture，保留起点和累计 PCM，不重新打开另一段录音。
- VAD 回调核对请求序号、capture 序号和录音状态；外放混合录音禁止声纹学习，同一份续录继承该限制。
- 完整预识别已完成、覆盖最新安静尾、声音／文字活动未变化、且无歌唱保护时，普通讲话可使用既有 1.2 秒确认等待。否则保持原有等待；这是有条件的约 0.3 秒优化。
- 默认新增有界候选／确认／VAD／外放重叠／收尾事件。`asr.send` 记录实际上传 WAV 的 hash、时长、语言与学习参数，便于同一 capture 对照。
- 边界复核只取消自己的监听准备；低优先级预听发送遇到已占用辅助通道的审核时返回空准备结果，不取消原审核。发送前登记用途，覆盖传输对象尚未安装的窗口；正式用户接管仍可以取消旧任务。

c4、c6 与 c15 预览的保留 WAV 已与 Unity 上传 hash 精确匹配。c7 无效录音只有日志 hash，未找到对应 PCM。因此本轮不能声称已测得噪声拒绝率或字词准确率提升；下一次实际麦克风测试仍是必要验证。

噪声仍有可能被神经 VAD 错判为人声，或被最终 ASR 输出为非空文字后进入新轮。当前修复阻止尚未确认或最终为空的候选越权破坏旧任务，并保留定位证据；它不是已经测得有效的完整声学降噪方案。ManagedAEC 仍用于短打断探针，并不等于整段录音都经过双讲回声消除。
