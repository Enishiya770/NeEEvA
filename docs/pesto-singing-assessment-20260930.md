## 当前实际使用的方案

2026-09-30 核验 Unity 场景、运行路由、Spark HTTP health、实际进程、启动器与启动日志后，确认 ASR 为 `192.168.114.163:9881`，**当前音高支路是 CPU FFT 自相关，CREPE 未启用**。远端 ASR 虚拟环境没有安装 torchcrepe 或 pesto-pitch。不要把源码支持的可选算法写成已部署能力。

| 功能 | 当前实现与状态 |
|---|---|
| 实时音高线索 | 16 kHz 单声道，40 ms 自相关窗口、10 ms 步长，55–900 Hz；得到 F0 和周期性 |
| 旧歌唱倾向判断 | 使用持音、连续性、音域、稳定性、有声比例等启发式，并结合 ASR 文字密度等信息 |
| 可选神经音高 | 源码支持 `torchcrepe-tiny` 对完整录音细化；Spark 启动器显式 `--disable-torchcrepe`，当前关闭 |
| 新个人教学小头 | PANNs 类别分数构成 9 特征 → 小线性分类器；没有输入 F0、音程和音符时长 |
| 旋律表示 | F0 转连续 MIDI 音高、音名摘要；另有保留休止的 100 ms 时间线 |
| 歌曲检索 | 当前候选排序使用半音音符 token 对齐、重复音合并和移调枚举，并结合文本；旧 DTW 仍用于部分相似性和位置对齐 |
| 回唱变声 | RVC 使用 RMVPE 提取 F0 保留唱法，是声音转换支路，不负责划分讲话／歌唱 |

## PESTO 能提供什么

PESTO 是单音高估计器，可以输出连续音高、有声置信度和幅度等信息，官方还提供流式推理路径。它本身不输出“讲话／唱歌”的语义类别，也不直接完成节拍量化、旋律检索或 MusicXML 制谱。截图中的完整路线还需要时间建模、音符分段和后续应用层。[官方仓库](https://github.com/SonyCSLParis/pesto)

官方实现中的 confidence 用来估计有声／无声，不是歌唱概率。正常讲话也能有较高置信度的 F0，故不能用 confidence 阈值直接圈出所有歌唱。[官方 confidence 实现](https://github.com/SonyCSLParis/pesto/blob/master/pesto/model.py)

2025 论文同时评估音乐和讲话音高，并讨论流式窗口引起的延迟以及低延迟近似方法。输出步长、一次网络计算耗时、获得所需上下文的等待时间必须分开；快速离线推理不能直接证明低端到端延迟。[PESTO 论文](https://arxiv.org/html/2508.01488v1)

## 本机隔离实测

使用 `work/pesto-assessment-20260930/deps` 内的官方 `pesto-pitch 2.0.1` 和自带 `mir-1k_g7` 权重，没有更新共享 Python 环境。音频仅从上轮不可变副本读取，在本机处理。

配置为本机 CPU、2 个 PyTorch 计算线程、16 kHz、20 ms 步长。完整测量中模型初始化约 0.369 秒，Python/PyTorch/PESTO 导入另约 9.054 秒。该配置实际 VQT 最大窗口为 4096 样本，即 256 ms；整段居中计算每侧使用 128 ms 上下文，不能宣称 20 ms 判定延迟。

| 本人录音 | 音频时长 | 本次整段 PESTO 推理耗时 |
|---|---:|---:|
| 第 8 段 | 17.70 秒 | 2.456 秒 |
| 第 19 段 | 18.95 秒 | 2.523 秒 |
| 第 29 段 | 12.08 秒 | 1.775 秒 |
| 第 31 段 | 9.21 秒 | 1.404 秒 |

32 条本人原音合计 356.61 秒，PESTO 整段推理累计 49.884 秒，即每秒音频耗时约 0.140 秒。当前 FFT 核心在对应批次累计约 2.225 秒。PESTO 的额外计算并非可以忽略；它在这次 CPU 测试中比快速 FFT 昂贵，但仍快于音频的播放速度。

这些是离线单次测量，不是 Spark 基准或 Unity 首音延迟。如果等录音停止再串行运行，确实会额外等待约 1–3 秒；集成目标应是录音期间增量并行计算。

另以第 19 段进行了 CPU 流式测试，每块 20 ms，排除前 20 块后，块计算耗时中位数 6.788 ms、P95 10.370 ms、最大 66.813 ms，约 0.647% 超过 20 ms。这里没有测量 Unity 调度、网络和其他服务争用。无 mirror/refill 配置的输出对应约 128 ms 之前的窗口中心，还要与分类模型上下文区分。重置缓存后重跑同一段，F0 输出一致；每条独立音流必须管理缓存身份。

![实测音高与用户确认区间](../work/pesto-assessment-20260930/pesto-pitch-examples.png)

图中仅显示有声置信度至少 0.5 的帧，阈值用于显示，不用于歌唱判断。人工标签是讲话／歌唱类别，没有逐帧 F0 真值，不能用它证明 PESTO 音高准确率优于 FFT、CREPE 或 RMVPE。

## 固定设置下的融合对照

本次实际提取了 PANNs 原 9 特征，以及两种音高后端各自的 8 个时间统计特征。FFT 复用生产端的 DC 去除、温和增益和低能量处理，将其 10 ms 轨迹取样到 20 ms；PESTO 使用原生 20 ms 轨迹。特征包括置信度分布、有声占比、局部音域、相邻音高变化、稳定变化比例和最长有声段。

三组采用相同的按有效时长训练权重、L2=0.1、固定 0.5 分类阈值、训练集内标准化、320 ms 分类网格；没有 75/25 初始模型混合，也没有最终 RMS 规则。因此这是控制变量的诊断实验，与上次当前面板混合模型的成绩不可直接对比。

将相同原音前缀连接成 21 组，逐组留出测试。避免已知前缀伙伴同时出现在训练和测试，但仍共享会话、说话人和内容，只能视作相关数据诊断，不能视为 21 个独立采集会话。

| 特征输入 | 找回歌唱比例 | 漏唱 | 讲话误收 | 环境音误收 |
|---|---:|---:|---:|---:|
| PANNs 类别特征 | 88.02% | 22.321 秒 | 1.233 秒 | 6.028 秒 |
| PANNs + 当前 FFT 音高特征 | 92.07% | 14.774 秒 | 2.560 秒 | 4.835 秒 |
| PANNs + PESTO 音高特征 | 91.25% | 16.296 秒 | 2.280 秒 | 3.756 秒 |

这支持“显式音高结构有增益”的方向：两条音高分支都减少漏唱和环境音误收。但两者相对 PANNs 基线都增加了讲话误收，PESTO 相对 FFT 也有更少误收、更大漏唱的取舍。不能声称已经解决把讲话播出来的问题，也不能宣布 PESTO 全面优于现有 FFT。

本次 8 特征是固定的初步方案，使用居中的 1 秒上下文，是离线非因果特征；实时分类尚未实现或验证。PESTO voicing 与 FFT periodicity 都取 0.5 仅为事先固定的实验约定，两者并不具有相同校准含义。没有逐帧 F0 标签，成绩也不代表音高准确率排名。尚未实现“完整音符序列／节奏识别”，因此本结果不能排除更好的时间模型继续改善的可能。

## 推荐的融合方式与评价边界

建议保留原始样本时间线，由类别分数和音高结构共同提出歌唱区间。已完成的三组初步对照应继续作为基线，下一轮改进可聚焦真实可用的流式时间特征、歌唱句的完整性和讲话误收代价。区分“多用了音高信息”和“PESTO 提取更有帮助”，避免同时改变多个因素后直接宣布模型优胜。

PESTO 值得作为融合实验候选。工程上不宜直接拿它替换歌唱判定或复用 FFT 的周期性阈值，因为两者置信度的含义和分布不同。也不必将 FFT、CREPE、PESTO 三次完整推理串行堆叠。

具体约束：

- 讲话的声调、语气、拖音也有音高结构；需要多种证据共同分类。
- 唱歌中的辅音、换气、气声可能没有可靠 F0。不能按有声帧直接裁切，避免切掉首字辅音或尾字。
- 先保留连续音高、时间和不确定性，不把跑调、滑音强行量化成标准音符；音符摘要适合检索和角色理解，不替代原始时间线。
- 已知旋律匹配可以提供补充证据；新歌、即兴哼唱与跑调的识别不应以曲库命中为前提。
- 角色外放可以有真实音高，甚至本身就在唱。声音类别识别不能替代声源、回声与录音时机控制。
- 本批主要来自同会话并含重复前缀，任何同批训练或相关样本留出成绩都不构成新会话泛化证明。

上轮结果只能说明“9 个类别分数 + 当时训练方法”不够，不能证明音频信息本身不够。旋律也是声学信息；本次方向是在现有输入中补足音高随时间形成的结构。
