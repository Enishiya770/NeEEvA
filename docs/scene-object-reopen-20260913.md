# 关灯后重新打开：物件身份与执行反馈修复

## 日志结论

本次读取的是 19:48 前的最后一次 Play 日志（重开编辑器后保存在 `Editor-prev.log`）。精简时间线保存在 `Server/ARDY/runtime/scene-object-reopen-20260913/timeline.md`。

- 19:44:58，小灯的真实发光材质和 Light 开关关闭成功，并取得新图确认。
- 19:45:08，重新打开时的像素没有确认到稳定物件；随后几次选中了普通渲染物件，它们没有灯具控制接口。
- 19:46:08 和 19:47:23，观察操作再次找到原来的同一盏灯，状态仍为关闭。原灯身份和控制能力没有因关灯而消失。
- 19:46:48 的“没有接电源”来自绕过空间结果审核的 `work-feedback` 分支；后续另一次相同解释还被旧审核放行。日志没有电源或线路故障的证据。

原实现每次操作都重新猜像素，容易把已经关闭的小灯选成背景。当前选择又影响旧开关结果的有效性判断，使“刚才操作过的那盏灯”和“这次选中的表面”混淆。

## 改动

1. 增加 `entityTarget: { captureId, entityId }`，用于 `inspect-object` 和 `set-object-state`。角色可以引用先前真正观察过的物件；“再打开刚才那盏灯”优先延续同一身份。新物件仍需从图像识别。
2. 保留最近 16 个已确认物件的带时间档案，并在当前图像中重新查找它们。只提供当前确实可见的物件锚点，不向模型枚举未观察的房间物件。
3. 身份引用仍须通过当前截图、同一实体、新视角确认、已登记能力、距离和控制权检查。历史身份不允许隔墙操作，也不能让同名替代物继承能力。
4. 实际开关结果独立绑定原灯、环境和角色。选错背景不再抹掉原灯的执行记录；绑定变化只撤销当前有效性，不把旧结果改成另一物件的结果。
5. 同一事项的后续语音反馈先缓存，再按空间事实审核，通过后才外放和写入历史。定位失败或缺少控制接口不再被当作“灯没接电”的证据；审核不通过时使用具体、可证实的原因说明。
6. 结构化日志增加请求实体、状态、像素以及解析方式，便于下次区分模型选错目标与引擎拒绝执行。

## 验证

实体引用回归实际执行“观察原灯→关闭→选错普通表面→重新打开原灯”，并验证新图与实际组件状态。旧图、未知身份、同名替代物、遮挡、角色绑定失配均有覆盖。反馈回归使用受控错误事实和审核返回值，验证发布与历史边界；它本身不证明真实 Qwen 的语义判断准确率。

## 使用与边界

等 Unity 编译完成后重新进入 Play，可继续测试“查看这盏灯→关掉→再把刚才那盏灯打开”，也可以在中间观察其他物件。无需重新训练或重启 Qwen。

这仍是已登记灯具的运行时控制，不是角色伸手按开关。烘焙照明可能保留；关闭不等于画面必须全黑。已知身份保存在本轮场景会话中，重新进入 Play 需重新观察建立档案。
