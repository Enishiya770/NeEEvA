# 房间探索的感知、决策与行动闭环

本轮针对“角色已有感知和自言自语，但要求自己在房间里逛逛仍长期站在原地”的问题。原系统有单次看向、转身、走近用户、跟随和走近物件接口；缺少持续探索目标，以及不依赖物件识别的可见空地移动入口。扩充动作生成器本身不能补上这些调度与目标缺口。

## 行为

- `explore` 登记持续空间活动，保存原始目的、来源、用户轮次与任务 revision。收到该决定不等于已经迈步或到达。新的用户探索要求替换旧目标；自主重复登记不重置进展。
- 活动进行时，每步重新获取角色实际视角，向原空间规划器提交目的、当前位置相关事实、最近实际到达与失败。模型选择一次移动、靠近、观察、转向或休息。程序不生成随机坐标，也不按时间直接平移角色。
- `move-to-ground` 使用当前图片的 `captureId` 与归一化像素选取明确可见地板。真实三维表面、同层支撑、完整 NavMesh 路线及身体/用户净距均须通过。家具表面不会被悄悄向下投影成隐藏地板。
- 接受后的移动复用现有 ARDY 房间控制器、真实身体历史、逐帧路线检查和任务回执。到达后取得新图，再决定下一步。一个父目标可以拥有多个连续动作。
- 探索子步骤是静默空间决策，不经过额外的台词生成和 TTS。普通用户对话仍走原链路。PTT 下的明确探索委托可以独立调度，不自动开启开放麦克风或自言自语。
- 手动录音及其最终 ASR 交接期间暂停新步骤，Agent 开启时的普通自主入口和探针晋升也遵守此边界。录音拥有独立代际，过期录音回调不能解除更新一次录音的等待；空录音结束后仍保留父目标。应用暂停撤销待返回的探索步骤，恢复后以新图重新决定，不执行暂停前迟到的决定。
- 探索子步不允许变成跟随用户或设备开关。用户另行提出这些动作仍走原有接口。探索可用现有物件观察和走近能力，但不因此宣称已实现手部接触/抓取。
- 停止移动、取消整个任务和会话停止会结束探索。旧图、旧决策、旧操作回执不能重新启动它。明确停止后，普通自主轮也不能换成另一种平移动作继续走；新的明确探索请求可恢复。
- 三次连续的决定不可用、目标拒绝或执行失败会保留原因并结束本次活动。用户开口造成的正常取消不冒充执行失败，也不清空已有失败预算；准备异常把同一回执从取消升级为失败时，只补计一次失败。实际成功到达或观察才重置失败计数。

## 实现入口

- `Assets/AIChatTookit/Scripts/Chat/ChatSample.SceneExploration.cs`：父目标、进展、静默步骤和调度。
- `Assets/AIChatTookit/Scripts/Chat/ChatSample.SceneExplorationInput.cs`：手动录音、最终 ASR 与待执行探索步骤之间的所有权。
- `Assets/AIChatTookit/Scripts/Chat/RoomTaskProtocol.cs`：`explore` / `move-to-ground`，及探索子步骤限定 schema。
- `Assets/AIChatTookit/Scripts/Chat/ChatSample.SceneGroundMovement.cs`：图像落点到执行和新图回执。
- `Assets/AIChatTookit/Scripts/Motion/ArdyRoomGroundMovementPlanner.cs`：可见地面、导航和身体净距验证。
- `Assets/AIChatTookit/Scripts/Chat/ArdyRoomDialogueBridge.SceneTarget.cs`：复用既有动作所有权与 ARDY 执行。
- `Assets/AIChatTookit/Scripts/Chat/RoleDecision.cs` 与 `Scripts/LLM/FirstReplyProtocol.cs`：PTT/实时路径的完整语义路由。

## 验证与适用范围

本轮隔离工程与报告位于 `work/embodied-exploration-20260923/`。验证区分协议/状态反例、受控决策配真实 ARDY 的执行链路，以及真实模型看图选择动作。断言数不是独立动作数量；受控决策不算模型自主决策成功。

最终各项结果、保留的失败记录和复现命令见[验证报告](../work/embodied-exploration-20260923/validation-result.md)，编译时的代码/资源与程序集哈希见同目录的 `final-source-manifest.json`。

已完成的真实模型三步记录见 `registered/live-exploration/model-chosen/exploration.json`：使用角色实际 RGB、生产 RoomTask 合同与 schema、现有 DGX Qwen 和真实 ARDY。三次模型原始回复均选择 `move-to-ground`。前两步分别实际移动 4.39459229 m、4.39565 m，并各自取得新的到达后图像；第三步所选像素没有可定位的可见实体表面，执行被拒绝，位移为 0 m。三次模型决策耗时约 4.77、5.50、4.99 秒。这个结果是两次到达和一次拒绝，不是三次动作全成功，也不能代表长时间漫游成功率。测试图中地板与背景颜色接近，不能把该拒绝直接解释为普遍的地板识别问题。

真实模型实验不修改返回动作或像素，不指定巡逻点，也不通过替换角色 Transform 制造位移。累计两段位移约 8.79 m；无台词/TTS 请求。原始输入、图片、请求与完整成功/失败结果均保留，后续边缘恢复诊断和最终编译清单另见本轮验证报告。

另一个有界五步诊断保留于 `registered/live-exploration/model-chosen-5step-diagnostic/`：前两步实际移动约 3.67 m 和 3.18 m；接着两次落点因没有可定位实体表面被拒。第 4/5 步的模型输入包含前面的失败事实，第 5 步改选 `turn-in-place`（yaw = -170）。该轮复用的直线行走夹具禁用了眼控，转身被 `calibrated-attention-rig-unavailable` 拒绝，因此只证明模型能收到失败并更换动作选择，没有证明这一轮已完成转身或成功恢复长期探索。后续若有单独转身重放验证，也不改变这一原始记录。

随后在最终受控回归中启用既有的已校准眼控，仅重放上述 -170° 决定，不再请求模型：真实 ARDY 转身约 170.223°、根节点平移约 0.00588 m，得到新图且动作阶段为 `observed`。这单独确认了转身执行能力。最终回归同时通过普通 Agent 自主入口的 PTT/最终 ASR 门控、迟到探针、暂停/恢复迟到决定、显式停止与旧录音 owner 的反例；停止后的位移为 0 m。

本实现沿用已登记的同层地面和场景能力，不开放台阶、上下楼、跳跃、坐下或精细抓取。持续探索是虚拟具身系统的一项可执行活动，不能代替通用全身动作控制或任意物件交互。完整家具房间中的视觉选点质量、避障表现和角色风格仍需在原场景观察；隔离场景的位移结果不能代替原场景体验。
