代码缺口：

- `ChatQW.RecordingBoundary.cs` 的 unresolved 分支只记日志并公开回复，不把“该音源仍有待解决边界”存入材料状态。
- `ChatSample.SingingRejectionHistory.cs` 只保留独立目标审核的 `revise`；声学边界失败和 IR 重叠选源失败不属于这套历史。
- `RecordingSingingBoundary.cs` 接受 `kind=none`；粗 `clean` 的可用性检查证明有音频，不证明讲话已排除。
- 文本独审批准源和范围，不构成独立声学模式证明。现有选区检查也不能可靠发现 `clean` 内部的讲话。

因此只修 ASR 字符容错仍不够。需要材料级的“待解决边界/已核验区间”状态，恢复时保留处理要求；修选源错误不能顺便取消裁剪要求。若判断无需裁剪，需针对该问题给出明确的重新判定依据。

## 建议下一批开发范围

1. **先闭合本场可复现的状态问题。** 控制恢复保留澄清问句和目标；材料保留未解决边界；选源重试不丢裁剪要求；录音分析＋回唱直接进入音频能力；被否决的噪声输入恢复原事项进度而非默认从头规划。对应本场 c13→18、c15→16、c19→22 设置跨轮回放验收。
2. **以对话状态和决策链收敛为开发主线。** 明确当前用户目标、待回答问题、正在修正的素材/行为、已完成及待执行步骤。Fast 只携带当前需要的证据，控制完整上下文和图片进入条件；保留按需取完整档案与视觉的能力。将普通回复、音频工作、空间工作按明确能力分派，避免重复 Actor/Role/Room/General 路由。
3. **并行实现真正的在线混合音频区间。** 稳定 ASR 前缀＋快速语义候选＋声学模式/时间对齐，支持开头、末尾及内部讲话；最终播放检查消费同一份区间证明。对齐允许有证据的 ASR 异写，不以模糊文本相似度单独放行。
4. **用旁路对照决定是否换判断模型。** 保留当前 Qwen 基线，对同一批跨轮/改口/引文/中日混合输入比较精简上下文和更快判断后端，记录候选实际采用率与有效首音 P50/P95。当前证据足以确认架构损耗，尚不足以判定 Qwen 能力上限或证明换 Jev 就能解决全部问题。

验收应同时记录口语泄漏秒数、歌声误裁秒数、澄清承接与目标执行、无效恢复次数和有效首音；不把增加“正在处理”填充语算作任务提速，不把静态 parser 通过算作实际演唱正确。
