# 录唱契约、动作结果与重复规划修复

针对 `log-review-20260926-1852.md` 的已确认问题实施。生产代码已修改，统一编译及隔离 Unity 回归通过；未修改主场景、QualitySettings，未重启或重新部署服务。真实模型测试仅生成决策，不执行声音转换或角色动作。

## 录唱生成与执行契约

- source-aware 录唱提案使用程序提供的 `source_ref` / `request_ref`，不再让模型自由改写两份必须精确匹配的引文。引用按真实输入 turn/capture/clip、原文 hash 和字符范围绑定，程序回填原文。换 capture 或改变原文后旧引用失效，不能用历史引用冒充当前来源。
- 表格按决定和重唱意图约束：perform/handoff 的 `speech.text` 固定为空；repeat 的 request_ref 固定为当前 source；合法的 perform 恢复仍可引用历史原始请求。每个演唱分支保留相同完整素材和范围集合，不按 ready/current/clean 分支排序来诱导模型优先选旧素材。
- 编译器继续检查具体素材、范围、当前输入与来源关系，并输出原有 `sing_goal` / `sing` 接口。引用选中和编译通过都没有独立审核或播放权限。旧调用的自由引文协议保留严格解析兼容。
- 错误分别描述非空台词、无有效素材、来源引用失效、重唱引用不属于当前输入等条件。ChatQW 传递对应 RepairHint，ChatSample 使用录唱专用 JSON 纠错帧，不再让通用纠错要求它输出旧 XML 标签。
- 一次纠错后仍失败时，系统通知明确“提案未通过校验，尚未提交转换或播放”，不会用通用执行失败掩盖阶段。通知支持现有中/日/英显示；它是系统状态，不冒充角色已经说出的台词。

主要文件：`RecordingSingingDecision.cs`、`ChatQW.cs`、`ChatSample.cs`、`SubtitleOverlay.cs`。

## 动作结果、计划与跟随

- approach 到达使用已存在的实际用户目标回执；未找到通用台词不再被当作执行失败。后续用户位置变化时，历史到达与当前距离分开表达。
- 已有真实成功步骤之后，带正确 plan 身份的 none 可以合法结束有限规划。后续规划失败保留此前成功事实，关灯成功不会又被描述为完全没做成。
- 同一实际跟随任务以 bridge/controller/avatar/environment/user/task ID 及内部 followUser 核对身份，复用发生在旧图刷新/过期检查之前。它不提交第二次运动；改变任务、锚点或绑定则仍拒绝复用。
- follow 使用明确的计划后继类型：ongoing 是持续任务本身；parallel 保留完整尾目标并在实际运行确认后继续同计划规划；after_completion 保留依赖跟随结束的尾目标，但没有受支持的有限结束条件时不擅自执行。旧缺字段请求有界保留，不靠猜测文本把余下目标删除。
- 所有计划回执继承本轮语言；当前用户目标路线不再因遗漏语言代号直接回退日文。
- 误停提案被独立审核拒绝后，启用 Actor 的新路径最多重新请求一次 Fast 回答，保留完整用户输入与真实控制结果。普通反馈可以经 Actor 判断后正常回答；真正新的空间目标仍可交规划。旧停止承诺不发布，重复错误或传输失败中性收尾，取消/新轮会丢弃晚到回调。

主要文件：`ChatSample.ActorPlan.cs`、`ActorPlanRuntime.cs`、`ChatSample.ActorPlanReceipt.cs`、`ChatSample.ActorTask.cs`、`ChatSample.RoomTask.cs`、`RoomTaskProtocol.cs`、`ArdyRoomDialogueBridge.cs`、`ChatSample.FastTaskControlRepair.cs` 与 FastLoop 接线。

## 真实 Qwen 决策测试与保留差异

录唱固定12例由生产 Prompt/ResponseFormat 原样导出，使用受控素材事实。初版引用表格仍允许“repeat+历史request引用”冲突，首次只有4/12编译通过；保留这次结果，再补结构关联后同组12/12编译通过，平均HTTP时间2.282秒。三条最新失败原话 c15/c16/c17 均选择对应 material_15/clean，台词为空，c16没有再选开场白。

12/12仅表示编译。本组路由/有序素材/来源关系子集为11/12；加上明确重唱应使用repeat的意图检查后为10/12，仍有两项语义残余：

- “那能把第二段唱出来吗？”选到了旧的第一段。
- 已有成功播放事实时，“重唱第一段”仍选择perform及历史请求引用。没有实跑该输出对应的独立审核与已播放后门控，不能声称一定执行、一定被拒绝或正确完成重唱。

因此不把模型编译率、素材选择子集或本次约2秒的决策请求时间当作歌唱成功率/首音时间。真实新旧片段边界、独立审核、转换与播放必须在主场景一起复测。

Actor 的同一固定12例 before/final 对照保持当前用户、草稿、事实与预期相同。五段最新普通草稿从0/5直接none、5/5结构复审变为5/5直接none、0/5结构复审；这五段首次判定HTTP中位由1.853秒到1.157秒。全12例语义期望匹配为3/12到9/12，不是全面理解正确。

保留的差异包括即时转头被判已成声明（已有时间语义复审）、未知门条件产生不合法wait字段（严格复审，另有误填count_three的真实反例被运行时来源检查挡住），以及日文“不想低头”被理解为解除保持。用户此前接受过类似含糊否定与恢复姿势的分歧，本轮没有为追求测试标签一致而给所有取消另加串行模型审核。

详细固定输入、原响应、实际生产编译结果及before对照分别在 `recording-report.md`、`recording-live-final.json`、`actor-contract-analysis.md/json` 和 `actor-live-before/final`。新follow后继字段未单独做真实Qwen分类准确率测试；这里只验证协议和实际调度。
