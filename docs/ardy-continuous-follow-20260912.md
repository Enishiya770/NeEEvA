# ARDY 持续变速跟随（2026-09-12）

本轮将持续跟随改为短段连续生成：用户继续移动时更新路径和速度，播放器保留已经执行的历史，只替换尚未采用的未来。普通“到我身边”的单次移动继续使用现有路径。

## 执行方式

- Chat 桥接从实际支持地面上的用户位置估计水平速度；结合移动方向与落后距离决定角色速度。当前上限为 **1.2 米/秒**，带加减速限制。桌面相机默认 2 米/秒、加速时更快，所以本轮不承诺始终追得上相机。
- 导航约每 0.2 秒更新，速度控制约每 0.1 秒更新。它们不等于身体动作已在该时刻生效；另记录控制真正进入播放器的延迟。
- 保留一份共享 Qwen。每个连续动作会话仅首次取得文本条件，后续使用同一条件和实际已采用的动作历史。H40 每次预测 40 帧，但只采用前 8 帧（20 FPS 下 0.4 秒）。
- 用户移动时，未来路径带有预测终点及非零终速，避免每个窗口都要求角色准备停下。速度状态沿已采用的控制轨迹延续，避免把步态带来的骨盆振荡误当成新速度指令。
- 播放器始终有明确的已确认末帧，不能越界播放剩余预测。网络跟不上、房间路径不安全或动作质量检查失败时，从当前姿态平滑停止。
- 稳定停下时交回待机动画，持续跟随任务仍保留。用户重新移动后用最近实际姿态恢复；明确“停下”则结束任务，不会自行恢复。

## 质量与地形边界

角色仍由原生 ARDY 根运动驱动，未单独加速 Transform，也未靠放宽关节或碰撞阈值通过测试。同层地面、碰撞、身体净距及支撑面审核继续有效；台阶和跨层移动仍不在范围内。

后端先审核真正要采用的 8 帧（接口也支持 16 帧）：源根节点单帧位移不超过 0.1 米，髋高为源站高的 0.72–1.25 倍，实际驱动身体的关节单帧角差不超过 35°。包括脚趾；不计未映射的辅助末端关节。候选不合格时最多尝试三次原生采样，所有失败候选都不写入历史；三次失败返回 `stream_quality_rejected` 及各次原因和耗时。Unity 仍独立审核坐标基准、动作前缀及房间约束。

这些检查能拦截明显下蹲、突跳和空间风险，不能证明动作自然或脚底完全不滑。已有测试中出现过逐渐下蹲及脚趾异常；失败证据均保留，没有通过修改姿态或删除失败报告将它们算作成功。

## 模型取舍

比较过官方 Core H8 与现用 H40。六组离线 60 秒原生采样没有显示 H8 的明确速度或质量优势；该比较采用较平缓的控制轨迹，不能代表所有场景。因此保持已锁定 H40，不增加第二个语言模型、不修改 Qwen 或重新训练适配器。

原报告保留了两个夸张瞬时速度峰。独立审计定位到同一帧：采样墙钟间隔 0.000805 秒，实际动画推进 0.011791 秒，实际根位移仅 0.00893 米。按动画推进复算为 0.758 米/秒，与前后帧一致；未删除原始峰值或把脚部速度诊断当成自然度评分。保存的尾部 63 个成功响应均只用一次候选采样，但早期响应因证据容量限制已淘汰，不能声称全部 152 段均无重试。

Chat 测试保留了同一个上层任务；等待恢复时允许重新创建原生会话。首次移动用户约 0.70 米时角色实际前进约 2.04 米，随后 1.44 秒停稳交回动画；点头后用户再移动约 1.50 米，角色在该 2.51 秒窗口前进约 1.04 米。明确停止后根漂移为零。该夹具使用真实 Chat 分发和动作执行，不调用真实语音识别、语音合成或在线聊天生成。

最终代码第二轮 `runtime-final` 也通过，其独立复算见 `runtime-final/audit.md` 和 `audit.json`：主段 60.009 秒、实际根路径 36.155 米，全案例根路径 36.272 米（包含起步）；零断流、髋高最低为初始站高的 88.2%，没有低髋连续超限。实际控制延迟均值 0.549 秒、P95 0.650 秒，按动画时钟复算速度平均绝对差 0.051 米/秒。明确停止根漂移为零，约 0.414 秒完成动画交接。两次采样有差异，保留各自结果；上文详细复算表明确属于 `runtime-v10`，没有混合两个运行样本。

## 在房间内复测

本地 ARDY 8093 已重启并就绪，共享 Qwen 未重启。正常启动脚本仍启动同一服务入口，无需另开一个语言模型。让 Unity 完成脚本编译，再重新进入 Play、连接房间并说“跟着我”。连续慢走、加速、转弯、停住，再移动，最后说“停下”。

建议这次先把相机 `PlayerCameraController` 的 `Move Speed` 设为约 1 米/秒，先不按加速键，以便在当前角色速度范围内检验连续性。该建议不修改用户相机配置。默认 2 米/秒超过角色本轮上限；更快行走及慢跑需要下一轮单独验证。
