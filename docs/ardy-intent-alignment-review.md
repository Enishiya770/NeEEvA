# ARDY 自主动作意图一致性评估

评估日期：2026-09-10。材料：当天约 20:16–20:22 JST 的 Unity Editor 公开执行通道、用户语音识别记录，以及 8 份实际自由生成 motion trace。目标仍是「角色按照自己的想法，实时做出符合自己想法的动作」。

## 判断

建议进入下一开发阶段：建立从事先意图、可执行计划、真实身体运动到纠偏的闭环。当前成果说明自由生成已经有表现力和可用速度，但不能认定自主动作的语义一致性、泛化或自述能力通过验收。

本轮只分析并保存证据；未修改运行代码、模型或适配器，未启动 Unity、服务或推理，也未重新生成动作。下文的实施顺序是建议，尚未实现。

## 返回轨迹的复核

[逐条审计](../Tools/MotionAdapter/reports/intent-alignment-review-20260910/evidence.md) 与 [机器可读证据](../Tools/MotionAdapter/reports/intent-alignment-review-20260910/evidence.json) 记录了 HTTP、窗口、来源、历史和骨架测量。8 条均返回 3 个窗口，共 120 帧／6 秒；24 个窗口均 HTTP 200，客户端均记为 completed。首窗在 trace 开始后约 0.54–0.62 秒到达，全部窗口约 0.97–1.17 秒到达。这不包含完整的听话、LLM 规划、开始播放流程，也不代表语义成功。

4 条兔耳相关轨迹使用原始 Core27 返回旋转、固定源骨长进行 CPU 正向运动学。在每段「两腕同时抬得最高」的时刻，较低一腕仍分别低于 Head 关节约 67、68、68、38 厘米。这表明原始生成轨迹连双手到头两侧的目标都没有形成。不能把这一偏差完全归于 Unity 骨骼映射。

测量对象是源骨架，未使用实际渲染角色的逐帧录像；Head 是关节位置而非头皮表面。此证据不能排除同时存在的 VRM 重定向、Animator 混合或自然度问题，也不能单独定位到 Qwen 表征、adapter 或 ARDY 哪一个模块。

返回包包含 Hand、HandEnd、HandThumb1，缺少独立食指／中指链；当前 UpperBody 播放路径只驱动 13 个躯干、头部、肩臂和整手骨骼。因此独立摇食指、食指中指 V 手型在这条路径上没有执行通道，即使文字描述正确也不能实现。

三组相同描述虽都使用 seed 0，但初始身体历史不同、返回轨迹也不同。重新生成不等于重放；现有证据也不足以把全部变化单因果归于初始历史。8 份原始 trace 已逐字节归档，见 [SHA 清单](../Server/ARDY/runtime/intent-alignment-review-20260910/archive-manifest.json)。

## 为什么台词与动作会脱节

1. **台词与动作只有会话代次上的关联。** `ChatSample.cs` 4482、5042 附近先启动并流式发送语音；5072、5112 附近完整回复到达后才解析、提交动作。台词可先说出，动作随后仍可能被拒绝或与目标不符。
2. **自由生成缺少结果观测。** `ArdyLiveMotionController.DescribeMotionContext` 返回所请求的描述和生命周期；只有受约束动作带实际几何观测。源码已经注明「请求不等于成功」，但没有自由动作的独立结果供 Qwen 核对。模型在本轮把计划名称当成了实际结果。
3. **现有服务验证的是结构、来源与连续性。** `ArdyLiveProtocol` 的检查不证明身体完成了文本目标。保存轨迹显示正常返回仍可能语义失败。
4. **没有精确引用上次动作的执行接口。** 「再来一次」需要模型重新选择文本，再从新身体历史生成；目前没有贯穿计划、轨迹、执行和回忆的稳定动作 ID。

动作上下文的源码注入链路是 `ChatSample.BuildMotionRequestContext → ChatQW.RequestContext → BuildRequestJsonForMessages`。请求统计只计算历史消息，遗漏临时插入的动作上下文，因此日志中 `systemChars=21985` 恒定不能证明合同没有注入。`images=0` 表示这些请求未携带图像，但不是不存在任何其他上下文的证明。

## 下一阶段的实施顺序

### 1. 先使计划、执行和对话共享一个动作事实

- 同一份 Qwen 先输出动作意图及必要的可测目标，为它分配稳定 action ID。文本条件、台词引用、轨迹、播放状态与结果都绑定这个 ID。
- 提交前做结构、长度及执行能力检查；失效时在同一轮内部修正或明确返回失败，不能继续宣称正在完成动作。一般交流语音仍可流式发送；动作相关台词区分「我打算／正在尝试」和「已经做到」。
- 「重做刚才那个」引用保存的实际轨迹或明确的动作 ID；从当前姿态做连续过渡。需要变化时才重新生成。记录当前能力范围，不承诺不存在的独立手指通道；手指控制作为明确的能力扩展。
- 增加低敏运行审计：合同版本、开关、动作 ID、事实时间戳及哈希。无需保存私有提示词。

### 2. 让自由生成也有身体观测和纠偏

- 保存并区分三个对象：事先目标、ARDY 返回骨架、经过重定向和混合后实际施加给角色的姿态。提取手相对胸／头的位置、掌向、活动部位、周期及阶段等事实。
- 先验证可明确测量的关系和时序；输出「达成／未达成／无法判断」，不要把几个角度阈值当成任意动作语义或自然度的完整评审。
- 为实时性采用有限前瞻和分窗检查，不必等完整动作结束才发现问题。快速几何控制留在执行层；同一份 Qwen 在目标选择、阶段切换或偏差事件时修订，不承担逐帧控制。
- 保留生成器的自由表现力。通用几何与时序约束应能组合新动作，不能把所有自由请求缩回几个固定预制动作。发现偏差后要尝试使动作符合原意，不能只事后改写解释来迁就错误动作。

### 3. 用新动作和真实场景决定控制或训练投入

- 本次故障作为回归案例；另保留未调参的新组合，覆盖方向、左右、掌向、顺序、保持、途中纠正、重复、不同初始姿态与自主选择，跨多个种子评估。
- 在相同动作目标、初始历史和采样设置下，对比教师条件与 Qwen＋adapter，分别检查原始轨迹和实际角色。先定位模型条件偏差与执行映射偏差，再决定 adapter 数据补充、动作网络条件约束或训练；本次数据不能证明只重训 adapter 就能解决。
- 验收关注：有效请求提交率、事先目标达成率、自述与执行一致性、纠错与重复效果、完整对话到首动作延迟。自然度单列，由人工观察补充；不以 HTTP 200、播放 completed 或教师特征相似度代替。

这些改动可以继续采用「一份 Qwen＋小适配器＋ARDY 动作网络」。身体几何观测无需再常驻一个语言模型。复杂语义与自然度仍需独立评估、数据或控制能力支撑，不能承诺仅加入反馈就获得任意动作泛化。
