这不支持“旧私人草稿直接重播”的解释，但也揭示了快路径遗漏完整能力/工具观察
上下文的问题。有限历史、冗长听觉前缀和先前固定纠错反馈可能加重语义偏差，
其各自贡献需要保持同一输入、每次只改一项的复测才能确认，不能宣称已证明。

## ASR 与录音时机

16 轮全部以 `effective-quiet` 结束。9 次最终结果复用了覆盖完整输入的预识别，
7 次发出 full-asr；录音关闭到最终回调平均 0.184 s、中位数约 0.002 s，最长
0.931 s。接近零意味着结果提前准备好，不能说声学识别本身只用了两毫秒。
有效 ASR HTTP 客户端耗时中位数为 0.22 s，支持“当前主要等待在收句策略”的判断。

大多数声学估计停说到关麦约 1.5–1.9 s，混合唱歌轮约 2.75 s。22 次语义 EOU
请求中，6 次得到结果，但消费者均因 `input_changed` 放弃应用；其余 16 次被取消。
因此这次没有一次是语义判停真正决定关麦。废弃过期结果避免切断新话是正确的，
但这条支路没有发挥提前收束作用，仍要处理其时效与输入版本关系。

capture 6 → 7 的续说被正确合并，旧回复在首音前取消，不能把这次现象当成漏录。
本次 16 个起录事件均不在 27 段角色播放区间内部；正常新起录距前轮结束至少约
1.232 s，与当前 1.2 s 播放后保护一致。麦克风环形缓冲一直运行并保留 pre-roll，
不能把这 1.2 s 直接当成被丢弃的语音长度；它应作为“接话时机”的独立验收项。
“去现在这个回复速度”“走到5身边”等是疑似识别偏差；仅凭日志转写不能确定
原话、错误率、漏字原因或是否剪掉声学开头。应对原始录音与人工文本对齐，再
区分采集裁剪、普通话解码、中日混合及唱词解码。不能为了识别更快盲目缩短所有
静音阈值，否则会增加正常停顿被切开的风险。

## 下一步工程顺序

1. **接通真实 replan 交接。** 保留同轮用户输入、角色提案、图像与素材引用、
   generation/epoch/outputRevision，撤销未公开的草稿音频，再由单一所有者进入
   完整规划。不能先完成普通回复，因为它会关闭历史交接并清理本轮观察。复用
   同一用户历史对象、防止重复记账和递归；允许规划器执行、询问、撤回或拒绝。
2. **拆开感知领域判断与动作完成校验。** 普通“看见/听见”不直接进入头部完成门；
   明确的物理动作完成声明仍须执行事实。对领域不匹配作有界消歧，不能靠中日文
   关键词白名单或删除完成校验。以本次原句和未见同义句做真实模型回归。
3. **给快捷决策提供足够的任务/技能事实。** 区分不采纳、待确认、交接规划；
   唱歌来源冲突进入正式技能确认，不能默默变成泛泛夸赞，也不能直接跳过素材资格。
4. **独立调整录音收束与识别。** 对同一批有标注的录音回放，比较句首/句尾覆盖、
   中途停顿、续说、唱后请求、最终文本和停说到关麦时间；先测量再选择阈值或
   识别策略，避免破坏已经改善的速度。

需要保留角色的自主选择和用户可接受的含糊语义差异。验收的重点是“已经采纳的
意图能够进入可观察、可取消的真实计划”，以及“普通回答不会被无关执行模板替换”。
