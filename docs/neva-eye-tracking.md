# NEVA 眼球追踪

已在当前 `Assets/Private/SailingMoon/Scenes/NeEEvA_SailingMoon_Day_Chat.unity` 的 NEVA 场景实例上配置 `NevaEyeTracking`，注视目标是玩家的 `Camera`。

## 使用

进入 Play Mode，在 Game 窗口按住右键并用 WASD / Q、E 移动到角色面前不同位置，观察眼睛向你移动的位置转动。注视依据是摄像头的位置；站在原地只转动摄像头朝向，不会改变角色应该看向的位置。

VR 下沿用同一个玩家摄像头，摄像头接受头显的位置追踪后，角色会看向玩家的头部位置。这项效果不依赖头显的眼动传感器。PC VR 与 PICO 一体机使用同一份追踪脚本；XR 环境设置见 [玩家摄像头与 VR](player-camera-vr.md)。

该效果在运行时生效。在 Edit Mode 移动 Scene 观察视角不会驱动眼球。为其他场景配置时，在停止运行的状态下选中场景内的 VRM 角色，执行 **NeEEvA → Eyes → Configure Selected Avatar**，然后保存场景。

## 参数

参数来自 NEVA 模型内的 VRM LookAt 设置，与参考截图一致：

| 参数 | 数值 |
| --- | --- |
| 内侧眼球转动范围 | 8° |
| 外侧眼球转动范围 | 12° |
| 上、下眼球转动范围 | 各 10° |
| 各方向输入角度范围 | 90° |
| Smooth Time | 0.12 秒 |
| Minimum Target Distance | 0.15 米（随角色缩放） |

输入角度按模型设置映射为眼球角度，例如目标位于右侧 45° 时，左眼向内转约 4°，右眼向外转约 6°。这保留了 VRoid 的克制幅度，避免眼白暴露过多。Inspector 中可调整 `Neva Eye Tracking` 的参数；`Smooth Time` 越大，跟随越慢。

玩家移动到头部侧后方时，注视在 80° 至 110° 的视线夹角之间逐渐减弱。目标过近、不可用或完全在后方时，眼睛平滑回正。

## 与现有动作配合

脚本在 Animator 和头部动作完成后，依据当前头部朝向计算注视，仅写入两只眼球骨骼的旋转。眼球的中立朝向在编辑模式配置时保存，重复配置或启停不会不断累积偏转。停止该组件后，眼球交还原有 Animator。

眨眼、嘴型、身体动画和已调好的尾巴继续使用原有组件。独立眼球追踪不会创建完整 VRM Runtime；当前场景中的 `Vrm10Instance` 保持禁用。若手动启用完整 VRM 更新，该脚本会暂停写眼球并记录一条提示，避免同时控制眼球。

## 验证与预览

回归入口为 `NevaEyeTrackingRegression.RunBatch`，仅允许在隔离的 `Logs/TailSpringValidation` Unity 工程运行。使用实际 NEVA 模型和 Animator，在 Play Mode 检查方向映射、平滑、过近/后方/丢失目标、MainCamera 回退、头部转动和重复启停；同时用同步对照角色检查非眼球骨骼及表情权重。

2026-09-11 验证通过：实际运行 22.51 秒、16,405 帧、三次启停；非眼球旋转差 0°、表情权重差 0，输入方向误差最大 0.0037°。生成五张方向特写及 60 帧、约 5 秒的真实渲染预览。当前主场景已通过编辑器菜单配置并保存，摄像头及眼骨引用已核对。

实际渲染的方向图片、动态预览和报告位于 `Reports/EyeTracking/`。预览使用固定在脸前的观察摄像头，注视目标在左右和上下移动，便于看清眼球变化。

实体 PICO 的显示和延迟尚未实机验证。本次没有运行语音聊天服务或进行 Android APK 构建。
