# 增量倾听与歌唱边界纠错：实施记录

本批已把录音中的 ASR 文本接入可撤销的结构化意图准备，并打通“修改刚才实际唱出的录音”的局部边界细化路径。判断后端仍是现有 Qwen；尚未部署 Jev 或新增音频模型。服务端代码已更新到 `192.168.114.163:9881`，Unity 代码完成编译及隔离回归。尚未进行修改后的现场完整对话、实际唱歌和首音延迟测试。

## 录音中做什么

普通说话与歌唱沿用同一次倾听请求，同时返回声音类型、语义边界、意图候选、原文证据与可选语义分段。领域判断针对涉及的能力，和“用户此刻是在说还是唱”分开；语义上完整的等待指令也不等于需要角色马上接话。

候选带录音身份、输入代际、文本版本与原文位置。代码验证引文存在、分段顺序与长度，不能把历史内容或模型自己补写的词当成当前录音证据。歌唱或混合候选可提前保留已完成播放素材的只读引用及版本；本阶段不选择演唱素材、不裁剪、不执行动作。

自然心里话仍然保留，但展示要求来源文字与当前 ASR 严格一致。追加、纠正、回滚、切换录音、正式回复或过期都会撤销旧展示。未完成意图只能显示试探性的当下反应，理解型反应需要更完整的语义条件。模型仍可能错误理解含糊原话，程序并没有获得百分之百的语义判断能力。

即使文本已继续增长，同一录音中仍有效的候选可以作为未采纳假设传给正式 Fast，附上原快照、`finalMismatch`、`requiresFinalReview=true`、`executionAuthorized=false`；最终完整原话优先。旧心里话散文与提前拟好的答复不再回灌正式决策。

录音中的旧回复草稿及其预合成被停用。正式 Actor 回复的 TTS 与意图审核并行路径保留。现有条件 EOU 复用开关仍关闭，没有因预判断而新增结束录音后的串行等待。

## 如何裁掉歌中的讲话

实际播放完成后保存素材身份、版本、原始及当前 PCM 哈希、音高哈希和源范围。模型以 `boundary_edit` 指出素材、裁头/裁尾、要删的原话和紧邻要保留的歌词。模型不填写猜测秒数。

新接口 `/singing/refine-boundary` 在固定源音频上寻找局部低能间隙，再识别间隙两侧。它限制搜索和探针数量，并在短探针之间让普通最终 ASR 优先。没有可靠间隙、原文不支持、多个不同转场、超时或取消时，不返回可执行范围。相近候选只有在整个桥接仍低能时才归为同一转场，选择删除最少的切点。

Unity 核对接口回包的请求、素材、版本、WAV、来源和播放身份，再将测量范围编译为现有歌唱目标和动作，继续走独立审核。审核通过后才同时裁剪音频与音高时间线，保留原始录音。分析请求的取消身份与后续执行的输入身份分开，避免正常进入独立审核就让合法测量失效。

最近播放只提供候选，不能覆盖用户明确指定的其他歌曲。已知素材需要细化边界时，不再进入旧 `custom_range → 重新规划 → 重搜同一档案` 循环。缺少定位原文、素材版本变化、声学或服务未能定位分别说明；不以“资料不足”统一替代。

当前只支持一条素材单侧收缩。无间隙的连贯说唱、内部删段、多素材分别裁剪仍可能无法处理；文字歌词候选及局部 ASR 都不能证明整段保留内容全是歌声。

## 验证结果与失败保留

- 500 个编译输入通过 Unity 对应编译器检查；55 组隔离 Unity 检查及请求导出通过，其中包括 42 项边界执行回归、实际普通倾听回调、心里话撤回和正式 Actor TTS 路径。
- 57 项倾听纯回归、52 项服务端边界/HTTP/调度/既有混合 ASR 回归通过。
- Qwen 第一轮 15 个提前理解样本严格通过 8 个。澄清领域、句义完整性和心里话契约后，原 15 个通过 11 个，加 4 个留出输入通过 3 个，合计 **14/19**。没有改掉失败样本的预期来提高分数。
- 剩余错误主要是把完整等待、持续指令判成未完成，以及残句领域判断不足。它们仍只作为待核验候选，不能直接改变录音边界或执行动作。
- 两轮共 34 份真实模型输出交给生产解析器回放：32 份可形成候选，一份多加引号的证据被拒绝，一份超过 8 秒有效期被拒绝。所有已接收候选在文字改变后不能继续展示，也不含执行许可。这是程序边界验证，不是 34/34 语义答对。
- 另用当前生产 Fast 提示词及 schema 工厂做了两条最终消费者推演，使用合成上下文而非历史 Unity 完整请求。早期回唱候选之后，最终“先别唱了，我们只聊天”得到不唱、继续聊天的普通回复。真实提前跟随候选误判 open 之后，完整原话没有被要求继续补全，但 Fast 只答“我会一直陪着你的”，尚不能证明物理跟随意图已落实。两条均通过实际解析器；不能将其写成两条动作语义都成功。原始请求及输出在 `final-consumer-probe`。
- 四条真实生产歌唱决策请求中，裁掉第二段报幕、改唱较早的另一段、普通聊天三条语义和编译路径通过。缺定位原文的一条错误提出空锚点裁剪，被生产编译器拒绝，公开说明定位不足；结果是 **3/4 模型正确，另 1 条错误被阻断**。
- 首轮发现的新契约与旧请求完整性校验不一致已修正；另有旧预算期待与测试素材身份构造问题已纠正。首轮完整失败结果保存在 `integration/run-01`，后续没有覆盖它。

本批尚未并发其他请求的首轮提前理解中位数约 2.98 秒；第二轮没有本批请求重叠的前六条为 2.79–3.63 秒。第二轮部分请求与四条歌唱验证共享 Qwen，出现 6.7–8.3 秒响应，不能作为独占速度基准。它还不是用户说完到角色首音的测量。严格原文一致会使连续说话期间的气泡更少；有效候选仍可供最终核验。当前不能承诺这条准备路径已达到一秒，也不能量化端到端首音收益。
