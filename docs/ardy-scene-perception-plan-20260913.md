## 第一批：角色真正拥有场景视角，观察进入自主判断

建立独立离屏感知相机，位于校准后的角色眼位，使用实际头部/视线参考朝向；不复用用户相机，不添加 `MainCamera` 标签、AudioListener 或 XR 跟踪。预览可以让用户检查角色实际收到的画面，但不改变用户主视图。

处理头部、头发与第一人称自身遮挡，保留可见身体和手。VRM 已有去头网格能力，但其完整 Setup 会修改 renderer layer、添加资源；应隔离处理，不能直接启用另一套 VRM 动作运行时或隐藏用户视角里的角色。电视保持现有局部 Unity 窗口排除配置，并检查背面渲染与递归画面；进入视锥不等于屏幕正面可读。

每次观察产生不可变快照，包含 `captureId`、帧号、采集时间、场景身份、相机位姿/FOV、图像尺寸和采集状态。几何证据与角色自身状态也记录各自时间/身份。一次自主预判、空间决定与正式表达尽量复用同一快照；重新观察必须产生新身份。区分“现在看到”“上次看到”“自身状态/碰撞反馈”，闭眼或对象离开视野后不把记忆当实时视觉。

图像先送入自主预判；选择继续时传到行动决策与表达。工作审查或其他不需要视觉的轮次不必重复送图。已有用户说话、轮次身份、工作 epoch、取消与过期响应保护继续生效。视觉关联的提前规划不能在画面或目标已变化后直接复用。

Unity 连续渲染不代表每帧调用 Qwen。采用有界帧缓存与读回，按观察事件和自主检查采样、去重、限制并发，测量图片处理对对话和 ARDY 动作供给的影响后再决定频率。初版不新增另一个语言模型，也不先承诺视频级推理速度。

本批验收：

1. 在同一房间看到房间内实际物体和电视画面；图片能与角色视点对应。
2. 转头、转身、遮挡、闭眼后，当前观察随之变化；不会背对电视仍通过桌面附件读屏。
3. 没有用户说话时，新场景观察能进入自主预判，产生一次有依据的注意/观察意图，也允许决定安静停留。
4. 采集失败或旧图过期时不假装看见；日志能串起观察、预判和回应身份。
5. 与聊天、连续跟随并发时实测主线程、图像请求延迟和动作缓存，确认不破坏已经通过的基本行为。

## 第二批：根据看见的内容，自主关注并走过去

实施进度：当前协议已新增 `look-at` 和 `approach-object`，只接受本次 `captureId` 下的图像坐标与解释标签。Unity 用同帧本地深度/表面 ID 定位，转头新图确认后，沿用导航审核物体旁的同层地面。已验证两处真实表面的受控观察链、两个原生 ARDY 到达、途中显式停止及目标真实 Transform 改变中止；连续跟随交接与真实转头后的故障清理也通过。最终代码的 `production-chain-r16` 在受控的预判/空间意图下走通完整生产链：约 9.378 秒、实际移动 1.782 米、转头约 17.57°、三个采集 ID、站位误差 3.26 厘米、朝向误差 1.49°；这不是实际 Qwen 自主到达。

真实 Qwen 首轮暴露的公开台词混入私有预判问题，已由专用 `PostAutonomyIntentMsg` 在 `live-qwen-r13` 验证修复。该次预判约 1.916 秒返回主动观察“发光装置”的目的，空间决定约 1.572 秒选择 `approach-object`，但 `(0.5, 0.75)` 像素因透明/未知材质无法可靠定位，执行正确拒绝，没有行走。`live-qwen-r14` 已完成一次有界重观察：三次 HTTP 分别约 3.122、1.580、1.688 秒，模型依据原目的、失败和新图，将像素改为 `(0.53, 0.72)`，仍被透明/未知材质规则拒绝，未产生头部或根节点动作。探针运行通过与行为终态 `rejected` 分开记录，不盲选邻近像素、不放宽材质规则。同批受控回归通过 98 项检查、10 个案例及 241 项房间协议检查，包含重选成功、仍被拒绝和取消旧回调的三个案例。上限保持最多三次 HTTP、总计 60 秒，使用同一模型及原生成参数。

`live-qwen-second-view-r16` 已取得真实自主关注的成功案例：模型从新视野形成观察书架及窗外景色的目的，自主选择墙内书架 `(0.55, 0.45)` 的 `look-at`，实际转头后新 `confirmedCaptureId` 确认同一表面，终态为 `observed`。模型选择的是观察，没有走路。此前的原生偏航 -55° 转向是测试准备，实际根位移约 0.007016 米、朝向误差约 2.105°，不属于 Qwen 自主行为；复测按实际终态等待准备完成。这份证据和 `production-chain-r16` 的受控行走证据不能拼成一次真实模型自主到达。

到达后的新图仍需单独核验，r11 第二处未通过原表面点的精确再确认，不能以“已到达”替代“重新看清”。头部初版只支持有界原地转动，不包含自动转身；动态/透明目标和跨高度没有因此获得执行能力。详细证据及限制见 [第二批实施记录](scene-action-20260913.md)。

复用已有自主轮，结合新观察、上下文、当前任务和记忆，决定关注什么、是否靠近、是否继续观察。自主性不以每轮都发言或移动来衡量；目标要有持续性，完成后允许停留，场景变化或用户打断时再调整。

扩展当前空间协议，让主脑引用观察里的对象/区域与目的，例如“靠近电视看清画面”。Unity 用对应快照的相机射线、深度/碰撞查询定位，再计算物体旁的合法站位，而不是让模型直接猜世界坐标或把物体表面当目的地。TV 显示器、玻璃等纯视觉表面的定位不能依赖不存在的碰撞体，需要明确查询规则。

感知记录受实际视野和遮挡约束，区分可见对象、历史记忆与引擎测量；不能把完整场景层级名称表当成角色看见的内容。执行前重新检查对象、站位、路线和当前身体状态；画面旧了或对象动了就刷新/重新验证，不沿用旧图射线做新坐标承诺。

增加自主头部/身体观察控制，并明确与用户注视、行走转向及 ARDY 骨骼写入的优先关系。先主动观察再决定靠近，走动时持续接收真实进展，抵达之后重新观察。叙述只引用实际观察和行动事实，不要求每个动作都配语音解释。

本批验收使用现有房间，不新建测试场：用户不发“去哪里”命令，角色能基于所见选择一次关注对象、看过去、走到合法邻近位置并停留；换一处未写死的对象也能沿同一路径处理；用户说停下仍能平滑中断。行为变化通过 `captureId → intent → actionId → 实际结果 → 新观察` 追踪，而不是只验收台词合理。

## 第三批：理解地形后，补齐跨高度身体能力

视觉提供语义判断，例如“像台阶”“是沙发”“这里是落差”；Unity 提供实际几何与支撑测量，包括踏面、级高、边缘、坡度、身体净空及足底接触。这些可以作为角色的空间/身体感知，而非让图像猜厘米数。家具即使几何上够低，也不默认作为普通通行地面；视觉不确定时可以换视点，结合场景可行走属性判断。

当前集成明确按平地设计：

- `motion_service/locomotion_protocol.py` 要求路径目标 `y=0`；`Server/ARDY/locomotion.py` 构造的是 Root2D 的 XZ/朝向约束。
- `ArdyRoomStreamTrajectory.cs` 压平路线角点；导航及控制器围绕固定支撑高度审核。
- `ArdyLocomotionPlayer.cs` 保持 GameObject 起始 Y；高度质量检查也使用固定源地面参考。

上游 ARDY 表示与约束中存在三维根位置、`root_y`、全身和足部约束接口，说明跨高度有研究入口；现有权重能否可靠上下本房间的台阶尚未验证。不能仅放宽 NavMesh 的步高或抬高角色根节点就算完成。

实施先验证支撑面变化、单级台阶上/下，再做连续台阶：三维路线、世界支撑面与骨盆相对高度分离、摆动脚净空/落脚约束、竖直根运动、实际接触与碰撞守卫、历史坐标及中断恢复都需要贯通。质量门槛应相对真实支撑面定义，不能直接放宽原平地检查。根据原生 ARDY 小规模试验，决定是否需要额外接触求解、动作素材或训练。

验收看实际脚步和身体：可站稳、无穿阶、不过度滑脚、头顶和身体不碰家具，上下都能停止/恢复。识别出楼梯与能踩着楼梯上下分别验收，避免把语义识别成功误认为动作已实现。

## 顺序与成本边界

第一批已提供用户可检查的真实视野，第二批在隔离测试之外，又取得用户 Play 中的真实自主走近。当前先补两项有界能力：时间/观察节奏与正确事实反馈，然后主动改变视向/原地转身。保留中止与连续跟随回归，用现有房间验证从书架视野继续观察的能力；随后推进跨高度，不排到长时间自主活动、坐下或复杂物体交互之后。地点记忆从观察和经历逐步形成，先登记固定目的地不再是前置条件。

每批产出可见行为和性能数据后再扩大范围。步态维护继续处理明确故障并保留回归，不以消除所有自然度问题为视觉启动条件。小型发光目标定位、持续自主探索及完整 Play 体验仍需评估，整批验收尚未结束；第三批跨高度执行尚未实施。新增动作的排队延迟、实时 TV 和完整 VR 长期负载不在已通过范围内。
