# 动作身份、真实身体反馈与一次修订

2026-09-10。承接 [上轮意图一致性评估](ardy-intent-alignment-review.md)。本轮已修改运行代码，并在隔离 Unity 项目验证；没有训练或替换 Qwen、adapter、ARDY，也没有改动已验收的四个基础动作。

## 现在接通了什么

每次动作由聊天端分配 `actionId`，贯穿指令、生成窗口、身体播放、结果和后续引用。修订另外记录 `parentActionId` 与 `repairAttempt`。模型不能自行填写身份或重置重试次数。新用户输入、重新绑定角色及新的动作意图会撤销旧请求的权限；普通自主说话不会直接作废仍在播放的身体动作。

角色可以请求 `<motion name="replay" ref="last"/>`，或引用上下文提供的已保存 ID。控制器保留最近四段完整收到且自然播放结束的轨迹，重放这些轨迹时不请求重新生成。取消、提前停止和被其他播放接管的片段不进入存档，重新绑定会清空存档。存档并不要求语义成功：用户仍可重放喜欢但未达到原目标的动作。

重放复用的是保存的骨骼旋转和时间序列，进入动作时仍与当前姿态平滑混合，结束后恢复当前 Animator。因此它不等于逐像素重放原画面，头发、衣物及混合段也可能不同。

自由生成现在可以声明左右手的必要位置目标，例如：

```xml
<motion name="generate" text="Bring both hands beside the head and lower them smoothly." leftGoal="near-head" rightGoal="near-head"/>
```

可选值为 `any / down / forward / outward / near-head / above-head`。观测器在播放器与 VRM 更新之后读取角色实际 Humanoid 骨骼，按角色方向和实际臂长测量，不把生成的源骨架当成最终身体。两侧要求需要同时持续满足，默认 0.2 秒；采样不足或中断会保留未知或取消状态。

`reached` 仅表示这段动作中曾达到指定的必要手腕区域，不证明动作顺序、持续保持、掌心、手指、自然度或完整文本语义正确。例如 `forward` 允许方向误差 30°、伸展比例至少 0.55，不能据此声称“双臂完全水平伸直”。未声明目标的动作保留 `unassessed`，不自动算成功。

聊天上下文新增实际观测、最终执行结果和可重放动作记录。自由动作出现可测的 `not-reached`，或执行指令被拒绝时，会在当前回复和语音空闲后调用同一份 Qwen，允许一次修订。程序保留原目标，拒绝把目标降低为 `any` 或换成另一基本手势；无法执行时可以说明限制。第二次失败停止自动尝试。修订属于模型的再次尝试，不保证能修好。

本版的身体失败反馈在整段动作结束后汇总，随后才可能修订，不是每帧重新规划。原始语音仍可能早于末尾动作标签开始播放：已经说出的句子无法撤回；修订回复会先收集完整返回，且被拒绝轮次尚未播放的语音会丢弃。任意自然语言的自述真实性还没有得到硬性保证。

## 验证结果

所有实际 Unity 测试使用 2022.3.22f1 的隔离项目，没有加载用户私有聊天场景或操作主项目的 Play 状态。测试和失败记录均保留。

| 验证对象 | 结果 | 能说明什么 |
| --- | --- | --- |
| 重放与取消 | 通过 | 原始与重放轨迹逐项一致；外部 Stop、替换、重绑不会错误归档或夺回新动作 |
| 实际骨骼观测 | 4 组模型、缩放和朝向配置通过 | 含已保存兔耳失败轨迹、正反目标及时间覆盖检查；不代表生成成功率 |
| 聊天修订生命周期 | 61 项检查通过 | 真实 ChatSample、解析器和回调，模拟模型传输；覆盖一次预算、目标保留及过期回调 |
| 既有聊天和语义通道 | 1,306 / 322 项检查通过 | 保持已有解析、打断、流式分段和调度行为 |
| 真实 HTTP → ARDY → Unity | 通过 | 使用既有共享 Qwen 特征、adapter、ARDY 和实际 Animator；“双手到头侧”仍报告目标未达到 |
| Qwen 开发集 | 7/12 | 指令、目标字段和引用检查；未播放动作 |
| 一次性 Qwen 留出集 | 6/8 | 新公开案例，不根据结果再调合同；未播放动作 |

独立的八组实际生成测试在运行前固定了两种目标、两种初始历史与 seed 0/1，全部保留，没有挑成功样本。结果如下：

| 必要目标 | 待机历史 seed 0 | 待机历史 seed 1 | 左挥手历史 seed 0 | 左挥手历史 seed 1 |
| --- | --- | --- | --- | --- |
| 双手到头两侧 | 未达到 | 未达到 | 未达到 | 未达到 |
| 双臂前伸 | 达到区域 | 达到区域 | 未达到 | 达到区域 |

八组都正常生成和播放，3 组达到必要区域、5 组没有达到，没有基础设施错误或未知结果。这个小矩阵说明生成仍是明显瓶颈，不能外推为任意动作的成功率。自然度和完整语义均未评分。挥手历史取首次达到 0.7 秒的实际帧，实测约 0.700–0.717 秒；16 帧历史跨度 0.75 秒，最早少量帧可能仍属待机。每条历史独立实测，不能称为逐元素相同初始历史的种子对照。

最终单项 HTTP 回归的首窗约 0.89 秒、全部 120 帧约 1.40 秒返回，播放长度 6 秒。这不包含识别、主脑规划或语音链路，也不是完整修订延迟。

留出集的两项失败也保留：日语兔耳请求仍出现独立手指承诺及不支持的 generate，真实解析器将其拦住；没有身体观测的结果问答仍夹带已执行的说法，并附加未要求的摇头。这表明能力检查能拦住部分执行，但模型仍可能说错。当前没有把真实 Qwen 修订、真实 ARDY 再生成和用户完整聊天场景合成一次端到端语义验收；三部分的测试证据必须分开看。

## 在当前项目试用

等 Unity 编译完成后重新进入聊天 Play 模式，沿用此前的 ARDY 对话动作连接和自由生成开关即可。绑定时会自动接上观测和反馈，无需新增语言模型。原有实验性语义规划开关没有替用户开启。

可先观察三个行为：喜欢某个动作后说“把刚才那个动作原样再做一次”；要求双手到头侧后查看角色是否依据未达目标的反馈修订；在动作或修订过程中插入新指令，确认旧动作不会后来重新抢占。记录动作 ID 和反馈状态，有助于区分误理解、错误指令、实际未达到和错误自述。

本轮修好了证据和控制链路，尚不能宣布“角色总能按自己的想法做动作”。后续效果改进应以原目标与实际身体结果为准：验证真实聊天里的修订是否提高达成率，再决定需要改进生成条件、适配器训练还是增加明确的执行约束。

## 手指支持的接入位置

可以继续采用同一份 Qwen。当前 ARDY 输出和播放路径缺少独立手指控制，因此本轮仅增加已知不支持请求的检查，还没有实现手指执行器。它不是补上骨骼名称就能获得的能力。

下一步可让 Qwen 输出每只手的张开程度、各指弯曲、手指分开程度及节奏，由单独的手指控制器驱动角色的 Humanoid 手指链，并与 ARDY 的手臂、手腕共享动作 ID 和时间轴。张掌、握拳、V 字和单指轻摆可以由这些参数组合；观测结果也应记录实际手指角度，而不是把手臂达标算成手型达标。模型是否有完整指骨、拇指轴向以及 VRM/Animator 的覆盖顺序需要先校准。复杂接触、交叉手指和细腻自然度仍需另外验证。
