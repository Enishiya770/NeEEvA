# 角色意图与执行：验收及设计修订

日期：2026-09-25。本文保留用户对验收目标的修订，并记录已实现的头部动作最小闭环。输出意图判断层已经接入 FastLoop 的 reply 草稿；后续用户授权的主场景接入已将场景的实验开关打开，见 [主场景试跑](fast-loop-main-scene-trial.md)。它尚未接管所有旧工具、歌唱、身体移动或完整流式输出。现有独立任务、修订号、控制权及语音撤销机制继续复用。

## 正确的验收目标

允许角色误解含糊的话、主动转头、改变计划或拒绝用户。核心验收是角色采纳的意图与实际行为一致：说马上转头时必须提交对应动作，说等条件满足再动作时必须建立条件任务，说动作完成时必须有真实结果支持；执行失败时应反馈失败、调整或放弃，不能悄悄丢掉任务或虚报完成。

历史 28/32 衡量的是预设路由分类，不是言行一致率。停一下被理解为只停声音属于可接受选择；旧关注任务存在时提出新方向也可能是有效自主意图。资源冲突仍必须通过有序交接处理，不能两个控制器同时写头骨。

## 本轮实施前的缺口

1. ChatSample.FastLoop 的 reply 直接进入 CompleteFastLoopReply，没有检查输出文本中的动作承诺。
2. FastLoopProtocol 把动作证据限定为当前用户原话，尚不能承载角色主动产生的意图。
3. 当前任务只支持即时头部控制，无法承载等用户数完三、等用户唱完等有条件的计划。
4. 旧空间任务占有头部时只有交接旧规划器，没有表达角色主动替换、暂停或接续旧任务的决策。

## 输出意图判断层的设计目标

输入：角色尚未播放的完整语义片段、必要的前后文、已说内容、当前任务、可用技能候选和目标引用、真实执行反馈。角色自己写的台词是意图证据；台词中引用的歌词、他人的命令、假设和否定不是自动执行授权。

快速判断的职责：识别当前片段属于普通表达、立即行动、持续行动、条件计划、取消／改意图，还是已完成声明；从当前候选中选择技能和任务操作，判断参数是否足够、是否需慢规划、能否发布这段语音。相互有关的选择用联合候选或程序一致性校验，不能假设独立问题的答案天然协调。

执行参数与任务 ID 由程序或已有规划器生成。判断模型不能凭空创造物体引用、歌曲素材或每帧骨骼姿态。明确且已绑定的头部预设直接执行；复杂目标、缺参数的唱歌／移动等进入规划器。

拟采用的记录包含：source=actor_proposal、draftId、draftRevision、关联片段、技能候选 ID、目标引用、任务操作、触发条件及其作用域。它替代“必须引用用户动作命令”的单一证据要求，但不把角色输出中的引文直接当作新意图。

## 发布与执行顺序

- 完整语义片段先判断再公开。不能在只收到“我要……”时提前行动；同一片段内可能随后出现“不”“等一会”“开玩笑”等限定。
- 即时意图：运行时接受任务后可发布“我现在转过去”等开始表达，并让动作与发声并行。无需等待动作完成才开始说所有台词。
- 条件意图：先建立 waiting 任务及可验证的触发条件，再发布等待承诺。由实际事件唤醒任务，不反复让模型阅读“我答应过”来维持状态。触发条件需绑定当前交互实例、版本、有效范围和取消／替换规则，旧历史不能重复触发。
- 完成声明：只有 matched task/revision 的真实执行结果可以支持；检查不通过则撤销该草稿、改写或进入重新规划。不能为了让错误完成声明看起来真实而事后偷偷执行。
- 执行期监督：控制权丢失、用户修正、新观测与执行错误触发判断。机械限位及硬故障仍由本地控制器直接处理。已播放部分不能撤回，只能停止剩余输出并解释／修正。

## 对原始失败例的验收

| 草稿／情况 | 应检查的结果 |
| --- | --- |
| “了解，这就把视线移向右边。”，旧route为reply | 从草稿恢复即时转头意图，提交head.right；否则修改台词，不能只答应 |
| “等你数完三再低头。” | 建立条件任务；条件前不执行，符合范围的计数完成后执行，跨普通聊天仍保留 |
| “停一下”被角色理解为暂停说话 | 若这个范围是角色采纳的决定，正确停止声音即可，不按另一种可接受理解判架构失败 |
| 旧关注任务存在，角色决定转向另一处 | 明确保持、替换、暂停或排队；通过控制权交接执行采纳的选择 |
| “我现在唱刚才那一段。” | 绑定现有素材并启动歌唱技能，缺素材则补规划；角色不承担手写标签的责任 |
| “我已经走到你旁边了。”而移动失败 | 拦截／纠正无事实支持的完成声明，反馈真实失败，不补造成功 |

关键指标改为动作意图漏落实率、条件计划漏登记／提前触发／丢失率、同一意图重复执行率、虚假完成声明放行率、任务交接结果，以及意图片段到任务接受／动作起始／首音的延迟。语义理解质量单独评估，不与这些工程闭环指标混成单一正确率。

## 判断模型的能力依据与限制

Jev 官方接口用 state 加 Choice、Noul、Score 问题返回程序可消费的结果，并未要求 state 必须是用户输入。因此，把角色输出草稿和执行上下文作为待判内容符合接口设计；这并不证明某个现成权重已经通过本项目的中文、日文、条件计划和反讽／引文判断测试。参见 [官方简介](https://docs.typesafe.ai/introduction) 与 [问题原语](https://docs.typesafe.ai/primitives)。

Jev 类模型选择、打分或判断现有候选，不等于自动具备完整计划生成与执行能力。对于复杂条件结构和缺失目标，仍需已有 Qwen／慢规划层补齐；对于语义片段的等待成本和新增判断的实际尾延迟，应在本机／Spark 链路测量，不能直接采用其他硬件的宣传数字。

## 本轮已经实现的最小闭环

`ChatSample.ActorIntent.cs` 将 FastLoop 的完整 reply 草稿留在内部，调用可替换的 `IActorIntentBackend`。当前实现 `ChatQW.ActorIntent.cs` 使用现有 Qwen、独立请求修订号、192 token 上限、20 秒超时、关闭 thinking 和严格 JSON schema。判断器只接收自己的协议及结构化上下文，不继承角色 persona、旧动作标签或工具提示词。

| 判断结果 | 已实现的处理 |
| --- | --- |
| none | 无执行承诺的普通文本按原稿发布。引用、否定等由模型语义判断，不用关键词直接触发动作。 |
| act | 从草稿恢复有界头部意图；来源记录 actor_draft、draft ID/revision，不伪造用户原话。角色不手写动作标签、骨骼参数或 task ID。 |
| wait | 先登记 user_count_three 等待任务，再发布承诺。真实的新最终输入经独立事件判断器推进计数，条件成立只执行一次。普通聊天、重申同一等待意图不会清除进度。 |
| claim | 必须有匹配任务及版本、对应头部动作、真实 controller owner 和 settled 状态。失败则替换成更正台词；不补做动作来制造“已经完成”。 |
| cancel | 按 owner 取消等待或头部保持，包括可确认的旧持续 gaze；判定期间旧 owner 被替换后不能取消新 owner。 |
| replan | 保留角色原始提案及未执行事实，替换未经验证的承诺/完成台词。**本轮尚未自动调用慢规划器完成该提案。** |

草稿、回调、对话 generation、work epoch、输出修订号分别校验。超时、非法证据、后台不可用不会放行未经判断的草稿。已接收的用户输入只登记一次；条件探测后继续普通回复不会重复写入用户历史。

等待任务绑定当前交互的输入序号，不能使用登记时或更早的计数追溯触发；同一事件、旧 task/revision、取消后的事件都不能重做。条件目前只支持完整的一二三序列或逐条一、二、三；其他条件、部分数词组合和通用时间/视觉条件还没有通用计划表达式。重新承诺同一 action/condition 视为续等；显式取消后用新草稿建立任务，或改成不同动作，才更换任务。任务不跨应用重启持久化。

即时头部意图现在在 **真实控制器接受任务并完成旧 owner 交接后** 发布关联草稿，动作与语音可以并行；无需等 settled。完成声明、条件触发后的“已经抬头”等完成回执仍等待真实 settled 事实。控制器拒绝、绑定失效或关节已到边界时，在原稿发布前改口。达到限位后不足 0.5° 的新方向动作会失败，不能把零位移当作又转动了一次；head.hold 允许零位移。接受后执行失败或保持时失去控制权，会撤销该轮未播放语音并向后续上下文记录失败。已经播放的声音无法撤回；这不是通用的实时语义自我纠错器，也没有保证发生故障当下自动另起一句语音解释。

完整 reply 草稿会同时启动意图判断和首个可播放片段的静默 TTS 预合成。音频只存在一个私有缓存槽中；判断前不进入公开语音队列、不显示草稿字幕、不写助手历史。最终全文与语言未变且身份、版本、轮次、provider 仍匹配时，现有播放协程才领用这个句柄，不重复合成首片段。需要更正完成声明、重新规划或换台词时，丢弃原音频。用户打断、旧 generation/epoch/output revision、草稿被替换、组件失效或 25 秒超时也会撤销缓存；旧回调只能销毁自身返回的音频。

预合成是首片段优化，未改变后续流式播放及真实播放字幕/历史逻辑。provider 忙、不支持准备、存在旧队列、歌唱准备或其他不兼容门控时，自动回退原 TTS 路径。默认开启的 `Enable Actor Speech Preparation` 仅在实验 FastLoop 与 Actor Intent Compiler 已开启时生效。相关实现及测量见 [并行语音验证](actor-speech-parallel-validation.md)。

旧稳定 gaze 可以在新头部请求实际被控制器接受后交接；旧 owner 的结束处理不能释放新 owner。身体执行器占用或尚在进行的旧场景动作仍可能拒绝交接，并反馈失败。这些是能力与资源状态，不用来推翻角色本身想转头的意图。

## 复现与范围

- `Tools/ActorIntent/run-regression.ps1`：编译实际协议与纯任务运行时，检查证据来源、等待状态、版本隔离和单次执行。
- `Tools/ActorIntent/transport/Run-Checks.ps1`：编译实际 Qwen backend，使用传输替身检查 51 项返回验证、取消与替换情形。
- `Tools/ActorIntent/test-model.ps1 -OutputDirectory <新目录>`：向现有 Spark Qwen 发出协议导出的语义测试请求，不改服务配置；保存原始响应字节和请求。必须按 UTF-8 解码响应，不能使用 Windows PowerShell 默认的 `.Content` 文本解码。
- Unity `FastLoopIntegrationRegression.RunBatch`：真实 ChatSample 入口、草稿判断、等待计划与语音队列门；模型/控制器事实受控。
- Unity `FastLoopHeadPlayRegression.RunBatch`：在未保存的独立场景加载真实 VRM，执行生产协程，验证角色来源的右转/修正、等待前不动作、触发后实际抬头，以及达到边界后不虚报新动作。关闭模型、麦克风、ASR、TTS 和服务自启。
- Unity `ActorSpeechLatencyPlayRegression.RunBatch`：调用现有 Qwen 与 GPT-SoVITS 服务，比较串行与并行的草稿到已批准且缓冲可播放的时间；无 AudioSource、无麦克风，不修改服务或保存场景。该数值不是用户停话到听见首音。

实验入口需要现有 `Enable First Reply Routing`、Qwen 的 RoleDecision fast lane 支持，以及同时开启 `Enable Fast Task Loop` 与 `Enable Actor Intent Compiler`（后者默认开启）。最小闭环实现阶段没有切换主场景；后续试跑阶段已在主场景保存开关，没有部署新模型。可以从 `[ActorIntent/Decision]`、`[ActorIntent/Accepted]`、`[ActorIntent/Waiting]`、`[ActorIntent/Condition]`、`[ActorIntent/Correction]` 和 `[FastLoop/Head] ... settleSeconds=` 分辨判断、登记、实际执行、反馈及耗时。

测试中的纯状态、受控 Unity、真实骨骼和真实模型语义是分开的证据，不能合并宣称完整语音端到端成功率。实际 TTS 首音、打断途中听感、长期多轮行为、歌唱与全身移动仍需在下一阶段验收。

## 当前 Qwen 实测与验收口径

最终运行使用既有 `.175:8888` 的 `qwen3.6-35b-a3b`，顺序发送 40 条请求；没有修改服务。请求、原始 UTF-8 响应、逐条判定与汇总位于 `Logs/actor-intent-model-final/`。32 条开发案例参与了提示词修订，另外 8 条由独立测试任务追加，冻结提示词后才运行并查看题目。

| 测量 | 结果 |
| --- | --- |
| 严格返回格式与证据来源 | 40 / 40 |
| 开发案例标签符合度 | 32 / 32 |
| 新增盲测标签符合度 | 7 / 8 |
| 草稿判断，27 条：P50 / P95 | 0.840 / 0.895 秒 |
| 条件事件判断，13 条：P50 / P95 | 0.523 / 1.106 秒 |

这些是完整请求时间，包括局域网、服务排队与推理，**不是首音时间**。该轮语义测量时草稿判断、必要的动作稳定、TTS 仍串行执行；40 条小样本也不是并发、冷启动或长时稳定性测试。主场景尚未默认启用新路径。用户后续明确接受约一秒的判断耗时被 TTS 预合成并行覆盖，因此后续实现优先调整发布管线并测量额外等待成本，而非仅凭这个单独耗时更换模型。

原始盲测标签的唯一偏差是已有抬头保持时，草稿“这次我不向右转头，还是先听你说吧。”被判为 cancel/head.release，而预设为 none。用户随后明确接受它表示“放弃转头并恢复正常姿势”，因此本案例的 none 与 cancel/head.release 都在当前允许范围内，不能再以它作为拒绝接管的硬性理由。保留原始 7/8 标签符合度和原始请求/预期快照，避免把后续验收变更写成当时的独立盲测全通过；它也不代表通用语义准确率。前一轮有效 UTF-8 测量为 29/32，记录在 `actor-intent-model-utf8`；最初使用 PowerShell 错误响应解码的 `actor-intent-model-current-qwen` 不应作为模型能力测量。

用户确认的重点仍是采纳的意图得到执行、条件计划不丢失、失败如实反馈。当前 Qwen 继续作为推进框架的判断后端；其他 Jev 类模型不再是后续工作的先决条件。后续一轮已实现完整草稿同时送判定与可撤销的 TTS 预合成、播放前汇合，以及即时意图在执行器接受后发布的时序；最新测试与实测单独记录在 [并行语音验证](actor-speech-parallel-validation.md)。

并行改动前的程序回归：ActorIntent 40 个案例/255 项确定性断言，backend 51 项传输检查；原 FastLoop 48 个案例/270 项断言及 33 项传输检查继续通过。Unity 编译通过，集成验证 35 个场景/217 项检查通过。后续增加并行缓存、打断、改口、回调隔离及实际编译入口同步重入测试后，集成验证为 67 个场景/431 项检查通过。最新物理验证及实际位移以 `Logs/fast-loop/head-play.json` 的最终结果为准，不能以模型分类分数代替。

并行改动前的真实 VRM 回归通过：从实际 FastLoop 入口收到受控 reply 草稿，经 ActorIntent 回调进入真实执行协程，右转约 17.08°、稳定耗时约 0.433 秒；意图修正后向左变化约 17.06°。等待条件成立前不移动，第三个新事件后实际抬头约 11.05°，重复事件不重复动作。再把测试关节上限设为当前角度，新的抬头提案立即以 head-limit-reached 失败，没有获取新物理 owner，也没有新增抬升。根位置与根旋转变化均为 0。该历史回归使用两个内存 backend 回调、零网络请求，主动撤销语音发布以验证动作独立性，不是实际发声测试。
