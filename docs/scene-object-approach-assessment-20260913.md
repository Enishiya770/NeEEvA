## 下一批：从看见到自主走近

1. **给初次目标匹配增加纠错过程。** 让模型选择关注区域或可见候选，查看候选轮廓和局部图，再确定是否符合用户描述/自主目的；将可见几何、语义匹配和控制能力分别记录。局部图须来自同一真实观察，不能补出未见内容。
2. **允许撤销错误指代。** 用户指出“不是这个”、模型判断不匹配或引用无效时，解除该目标关联并重新选择。保留看到过某个实体的历史事实，但不再把它自动当作原意图的正确目标。无效引用不能在后续回合无变化地反复使用。
3. **把已确认实体接入接近功能。** 保留同一 entityId；从物体附近合法地面中选择适合观察的站位，保持现有地形、家具和身体净距检查。物件坐标不能直接当作脚下落点。
4. **到达后重新确认。** 分别记录“实际到达站位”和“新视角确认仍是同一物件”。看不清时可调整视向或观察位置；物件丢失、移动或路径受阻要反馈实际阶段。
5. **用户指令与自主意图共用执行过程。** 角色可以因为想看清或想了解某物而走近，不要求用户逐次发指令。

验收使用现有房间：能够自行发现初次选错并恢复；能自主选一个已见目标、走到可站位置并重新认出它；中途遮挡、用户停止、目标或路径变化不会变成错误成功回执。小灯、柜体与书架可作为不同尺度样本，不增加测试场。

## 再下一批：有限的物理触碰

先完成一只手对明确登记的静态大表面进行“靠近手部目标 → 轻触 → 收回”。例如柜面或桌面，不从抓取小灯或精确按按钮开始。

需要为物件增加可触区域、接触点/法线；按实际臂长和朝向选择站位；通过手臂、手掌路径检查与 IK 保证手到达指定位置；协调头部观察、ARDY、待机之间的控制；根据实际骨骼与接触判定产生 reaching/contact/releasing 结果。模型负责想做什么，ARDY参与自然动作，Unity负责接触约束和实测结果。

开关灯目前属于登记设备的运行时控制，没有手部接触。因此“已开灯”不能当作“已按到开关”的验收。有限触碰稳定后，再扩展按开关、抓取、搬动与放回等会改变物件状态或位置的交互。
