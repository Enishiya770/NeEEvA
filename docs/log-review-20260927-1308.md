**7. 推荐下一步与验收标准**

优先做一次有明确边界的路由与执行收敛，不继续向大提示词叠加补丁。

1. 修正未知标签反馈及编译输出/解析器契约；把已完成任务的事实作为最终状态，阻止 General 和 autonomous work-feedback 再次开启同一任务。已是结构化空间任务的提案直达空间技能，省掉无意义的通用技能路由探测。
2. 修复 Room 视线交接：在新任务接管前保留旧姿态，覆盖异步匹配期间的所有权；设备技能管理找目标、接近、检查、操作、验证，计划的剩余内容只包含未完成步骤。
3. 单独收敛录唱身份绑定和审核，稳定引用贯穿全文；用本次真实的第一段/第二段录音关系回放，而不是只测 JSON 合法性和播放器成功。
4. 在输入侧让被判 self-speech 的区间保持隔离，续录合并不能自动恢复其用户身份。清楚的角色动作承诺也不得经 non_action 静默丢弃。
5. 独立模型审核只在有实质语义不确定时触发；不要把互相依赖的判定机械并行。先删除重复决定和收尾循环，再对可并行的观测、音频预取与表达准备做分段计时。

验收使用本次真实对话序列，包括：初次看到未知灯具并关闭→停止；转头保留新视角→找同一灯并重开；走到操作距离再操作；两段录音后要求第二段→实际 PCM lineage 对应第二段；角色说“视线移过去”→存在动作或明确未提交状态；拒绝自身声音后续录→角色文本不会重新成为用户意图。必须同时核对模型选择、动作提交、实际状态和用户可听输出，报告首音与完成耗时。

此前编译、结构协议和隔离断言通过，只证明对应代码分支满足局部约束。本次实时会话证明它们不足以保证跨模型、跨任务和自动反馈的端到端正确性。新版本的运行证据存在，不能以“没加载”解释失败。

观测限度：本次结合运行路由诊断、日志中的输入/输出片段及当前请求 builder 审计；未保存全部最终 HTTP body。不能把原始大感知帧直接当成逐字发送的最终请求。下一次回放应保存去掉图像字节与凭据的最终请求，以及 prompt/schema 版本、素材 key 到 clip/revision 的映射和被截断字段清单，用于区分提示词影响与执行器错误。49 次 capture 包含续录和被拒绝的输入，并非 49 轮独立有效对话。
