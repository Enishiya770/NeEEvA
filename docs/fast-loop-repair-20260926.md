# 2026-09-26 快环交接、上下文与录音边界修复

本次依据 11:17–11:22 Unity 对话，修复已经接受的行动没有进入完整规划的问题，并减少普通视觉/听觉陈述被当成头部动作的误判。录音侧调整语义判停请求的准入，不以本次改动声称 ASR 准确率已经提高。

## 已实现

- `ChatSample.FastLoopHandoff.cs` 保存同一轮原始输入、绑定图像、临时素材上下文、generation、epoch、输出版本与历史提交状态。`ActorIntent=replan` 真正进入既有完整规划入口；私有草稿及其预合成音频不先公开，也不再以固定“尚未执行”回复结束这一轮。
- 交接拥有独立的一次进入标记。空间模型尚未返回、正式语音传输尚未开始时，重复外部入口也不能再发一个规划请求；房间规划自己的显式续接仍可进入。取消会先撤销正式代际，再取消传输；不会删除已经接受的用户输入。
- 关闭房间动作输出也会使待处理的角色提案失效。当前旧规划回调明确结束自己拥有的等待，不再留着 `inflight=true` 挂起；已经开始的新一轮不受旧回调影响。
- 当前角色提案与用户原话分别传递。房间协议新增程序绑定的 `actor_draft` 来源，核验本轮草稿 ID、修订及逐字证据；没有有效提案的请求不开放该 schema 分支。角色可以在普通用户对话轮中提出自己的行动，不必伪造用户命令或把整轮变成自主定时轮。原有自主行动停止抑制、冷却、目标/视觉/导航/设备核验继续适用。旧的仅基于用户话语的空间预取不能替代此次重新规划。
- 真实回放暴露“嗯，我听着”被升级为用户移动命令后，进一步把来源固定在程序调用路径：有当前角色提案的交接只能使用 `actor_draft/none`，schema 与 parser 都拒绝 `user/autonomous`，包括碰巧包含用户原文的证据；没有提案的原有用户/自主入口保留。
- 新增 `other_action/claim`，与提出任务的 `replan` 分开。完成声明只进入无工具标签的事实回复路径，程序只接受普通 `reply`，完全不进入通用工具/空间执行入口；返回动作路由、标签或迟到结果都不能补做动作。Room 层另有 `purpose=verify` 的只读防御，缺失目的也不能获得执行许可。
- 原生等待目前只支持数到三。只有模型先判定等待后，才检查这个有限数值是否在本轮草稿或用户原文中确有表示；没有数值来源时只解释不支持的条件，不登记另一个计数触发器。此检查不从数词推导动作，也不是通用等待条件支持。
- `ActorIntent` 意图线协议升级为 v2，显式区分 `dialogue/perception/head/other_action`；条件信号仍为 v1。普通看见、听见和倾听可以没有身体任务。已采纳的真实行动、条件计划或完成声明不能仅因尚未发生/与事实冲突而按闲聊放行。
- FastLoop 获得实际注册能力、SVC/SVS 分离状态、技能是否加载、当前工作与待审核素材摘要。完整的本轮最终话语与程序声学观测分开，包含末尾请求；历史按用户轮次与已播放回复配对。能力摘要不启动服务、不选择录音范围、不授予素材播放许可。
- 实时录音分别保存声学活动版本和文本修订版本。远端语义判停请求在可靠安静尾段中比较剩余关闭时间与已观测耗时，减少必然晚到的请求；取消仅提供耗时下界，已有有效准备仍先尝试复用，每 30 秒可恢复探测。同步准备回调不混入网络耗时估计。

保留普通静默 1.5 秒、唱歌静默 1.8 秒、播后保护 1.2 秒与预录 0.25 秒。主场景与 QualitySettings 的 SHA-256 与改动前一致，DGX 上的服务部署未变，SoulX-Singer 未启用。

## 实际 Qwen 评估与保留限制

两种后续提示词/flat schema 候选没有提高整体质量，已撤回。最终以优先级版本为基础，仅补原协议缺失的 `other_action/claim` 状态及对应非执行入口。最终 58 条草稿全部满足协议，49 条严格标签匹配；只将两条 dialogue/perception 同为 none 的差异计为行为相同后为 51/58，不能计为全部语义通过。

“等音乐结束再抬头”在最终回放已选择 replan，没有再编造数到三；已走到目标的两条声明正确进入 claim。运行时还补了不凭空生成计数参数的检查。但程序仍没有音乐结束这一类快环触发器，不能声称已支持它。

剩余实质遗漏包括：指定墙上钟的观察动作、一次唱歌承诺、“已经唱完”的声明，以及三条省略动作名称的明确承接，仍曾被判为 none。另有保持/方向表达差异。这些漏判会让新的规划/事实核验入口得不到调用，必须保留为未解决问题。

本轮对话中 6 条误拦草稿均回到不提交动作的 none，另 6 条新的普通感知对照也未误触发动作。最终判定请求中位 1.099 秒、P95 1.205 秒，这是独立判定 HTTP 耗时，不是修改后的真人首音时间。

FastLoop 最终上下文版本另测 24 场景：协议均正确，人工审核确认改善了将“回复快”理解为慢、引用词义及错误声称无回唱功能的问题，但仍出现接受歌唱/移动后选择 `reply` 的情况。明确表达出来的提案现在有真实重新规划入口；“好的，交给我”这类省略目标的承诺尚未在最终保留版本中取得可靠的全链路证据，不能称为已经解决。还存在把局部问题说成全部解决、把没有图片归因为关闭视野等理解偏差。

详见 `Logs/fast-loop-context-model-20260926-second/semantic-review.md`、`Logs/actor-intent/domain-v2-verify-claim-live-20260926/verification-review.md`，候选对比另存 `domain-v2-speechact-live-20260926/candidate-review.md`。

Room 按真实 Private 主场景 `m_Backend=2/OpenAICompatible` 的生产 wire 做六条回放。最终固定来源后，角色自主走近正确使用 actor_draft；无提案的闲聊及明确用户移动正常。verify 防御例被证据校验拒绝，用户刚停止后仍提出的自主移动由已有停止抑制拒绝；未知“5番”仍可能被模型映为当前用户，属于未解决的目标语义风险。六例严格语义为 3/6，不把拦截错误计划算作模型理解正确。最终房间请求平均 2.665 秒、范围 1.742–3.516 秒；真正进入完整规划的行动轮仍会增加规划时间。结果见 `Logs/actor-intent/room-source-scoped-live-20260926/summary.json`。
