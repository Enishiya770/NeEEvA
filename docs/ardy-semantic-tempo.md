# 动作意图、用户约束与节奏执行

本阶段延续一份共享 Qwen、现有小适配器和 ARDY 动作网络。没有训练或加载第二份语言模型，也没有修改已接受的四个基本动作资源。

**当前结论：通用节奏执行通过工程验证；新的语义规划仍属实验，默认关闭。** 默认聊天继续使用此前的动作协议。公开测试发现了真实的掌向误解与约束遗漏，不能因某一个问候样例变好就宣布泛化完成。

## 如何试用

在运行中的聊天场景打开 `Tools → NeEEvA → ARDY Dialogue Motion`，勾选“允许生成其他上身动作”和“实验：意图、约束与节奏规划”，再点击“连接对话动作”。取消实验勾选后重新连接，即恢复原协议；连接不保存场景，也不启动服务。

如果只想比较执行效果，打开 `Tools → NeEEvA → Pose and Local Motion`，勾选“按动作幅度计算节奏”，选择“缓慢 / 正常交流 / 轻快”。这一路直接验证执行器，不经过语言理解，不能算作模型自主规划成功。

## 改动及其边界

角色可通过 `plan` 选择动作目的、臂姿、掌向、活动关节，以及 `gentle / natural / brisk` 节奏、幅度和次数档位。编译器将计划转换为已有的几何控制或 ARDY 自由生成请求。`purpose` 只记录意图；编译器不按“问候”等目的选择固定动画或姿势。

用户明确要求通过 `lock + userTurn + evidence` 记录，后续 `continue` 自动继承。改变要求需要新一轮用户依据，不能靠模型重复引用原要求来撤销自身。逐字引用检查只核验来源，不证明模型理解了否定、关节归属或换目标的含义；这些仍需要规划评测。

模型自行选择姿势时省略精确肘角，由执行器保留可用自由度；用户明确要求伸直时固定为零度，不能为了可达性偷偷弯肘。显式幅度、次数和秒数有来源要求；固定秒数无法满足完整曲线边界时明确拒绝。编译失败不提交新的约束记录，几何执行失败则通过现有 Controller 反馈，均不表示动作已完成。

无新用户输入的自主 `none` 可以停止身体，但保留原用户约束；新用户轮次的停止可清除旧目标。禁用、重绑会清除旧绑定的要求，过期流式或非流式回复不能取得新绑定的权限。

## 节奏执行

新编译计划使用 `adaptive-v1`，原 `compose` 保留原有行为。局部曲线为正弦乘五次起止包络，位置、速度和加速度在端点连续。完整包络也参与速度、加速度区间上界计算，不只计算中间的正弦部分。

手腕目标频率为 gentle 0.65、natural 1.05、brisk 1.40 Hz；头部为 0.45、0.65、0.85 Hz。它们是工程调参值，不是人类动作标准。实际频率还受幅度、完整曲线边界和时长限制影响，例如 ±10°、两次挥腕的 natural 约 1.90 秒，brisk 约 1.63 秒，原慢速基线为 3.2 秒。头部不会继承手腕的快速招呼节奏。

准备阶段根据实际骨骼到目标的角距离计算时间，并在实测达标后才开始局部运动。诊断记录实际解算时长、限制原因及准备阶段信息。速度、加速度数学界限针对命令的局部角度；外部 Animator、角色根运动以及模型映射误差需要独立实测，不能把数学证明当作完整角色的自然度或物理保证。

- `Server/ARDY/runtime/semantic-tempo-v1/first-unity-pass/`：首次真实 Unity 中语义链路、聊天隔离及旧动作播放检查。
- `Tools/MotionAdapter/reports/semantic-motion-planning-v1.json`：首轮 20 个公开开发用例，仅 5 个通过原预设检查。主问候仍选慢速且没有锁定明确臂方向，不能视为可靠泛化。
- `Server/ARDY/runtime/semantic-tempo-v1/tempo-failed-v1/`：首次真实节奏检查的完整失败证据，保留实际姿态、时间戳和渲染帧。
- `Server/ARDY/runtime/semantic-tempo-v1/tempo-pass-v2/`：四个真实模型配置的 48 个时序用例，包括 40 次完成、4 次主动中断、4 次预期拒绝，共观察 6,441 个实际帧，保存 430 个原生渲染帧。原始 Qwen 标签通过实际 Chat、账本、编译器、Bridge 和 Controller 执行，未修改标签的 `end=idle`。
- 最终真实 Unity 语义回归 322 项、聊天隔离回归 1,306 项通过；旧动作播放回归通过。修复了 Inspector 切换后首次新用户来源被清空的问题，最后再跑实际 Chat 和 HTTP 回归；时序、Player、Session、ControlPlan 与完整节奏测试的哈希保持一致。
- 现有共享 Qwen → adapter → ARDY → Unity HTTP 链路通过，三窗口 120 帧。该次首窗口约 0.86 秒、全部窗口约 1.28 秒；这是动作服务请求的窗口到达时间，不是用户开口到动作发生的端到端对话延迟。

首次节奏失败来自旧测试把前臂转动计入手腕根坐标角度。独立“手相对前臂”测量证明实际没有额外挥动；修正后的验收仍严格要求 `2×cycles−1` 次内部换向，幅度容差未放宽。诊断在 `Tools/MotionAdapter/reports/tempo-execution-v1/measurement-basis-diagnosis-v1.md`。

同一配置的实际腕部频率约为：原慢速 0.625 Hz、gentle 0.650 Hz、natural 1.050 Hz、brisk 1.224 Hz。轻快档受完整曲线加速度限制，未强行执行名义 1.4 Hz。头部单周期样例不具备足够过零次数独立估计频率，报告明确留空指标，未用目标频率冒充实测。

### 规划质量与剩余失败

| 检查 | 开发集 v2 | 未参与调试的留出集 |
| --- | --- | --- |
| 预设语义字段匹配 | 13 / 20 | 4 / 6 |
| 预设必要约束的来源覆盖 | 3 / 14 | 0 / 4 |

这些是小规模公开诊断，不能外推为泛化成功率。开发集有一例正确表达“慢速摇头三次”，但所需时间超过六秒，编译器明确拒绝，不能把它算作格式错误，也不能偷偷加速以提高分数。留出集只运行一次，两个失败均涉及掌向含义。

预选双臂问候样例现在输出 natural 并锁定明确的双臂前伸目标，实际局部动作约 1.90 秒；但模型还把自行推导的掌向也锁作用户明确要求。因此它证明了原始指令到实际动作的完整链路和节奏改善，不证明来源含义判断已经正确。新功能以实验开关保留，后续应优先改善完整动作语义、约束覆盖和纠正能力，不再只围绕这一种挥手追加提示规则。

原生时序预览在 `Tools/MotionAdapter/reports/semantic-tempo-v1/previews/`：包含旧慢速、自然、轻快、较缓头部，以及原始 Qwen 标签的执行。GIF 使用记录的游戏时间，仅作 GIF 时间精度取整，没有插帧、改姿态或加速播放。

## 尚未解决的能力

这一层提高可表达约束的组合和执行一致性，不等于 ARDY 原生动作泛化已经提高。自由多部位动作仍用原 ARDY 六秒窗口，尚不保证任意语义、精细手指、接触、根腿运动或任意多阶段组合。更快的手腕运动也必须经过实际观看，不能由通过几何与时序检查直接认定自然。
