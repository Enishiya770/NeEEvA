为何新特征等了数秒、已在行走却没断流：`locomotion_stream_service.py` 的同一流式会话会继承上一段的 `feature` 和动作条件，只在新会话等没有条件的情形重新提取。因此 4090 上现有 ARDY 短段供给可以继续，并不需要每 0.4 秒向忙碌的 5090 重做特征。这不能保证重新起步、换动作或新会话也没有延迟。

实际自主预判返回 `proceed=false`，意图为“观察环境，确认设备状态”，提到了画面的发光物。单独的无图对照 `qwen-autonomy-no-image-r1/report.json` 不再描述设备，返回“安静地等待用户的到来或指令”，新意为“无”。这是一组定性对照，支持图像会改变内部观察内容；两次均未创建正式自主行动，不能写成角色已自主选择并走向物体。

这个真实样本也暴露了语义边界：模型把发光物推断为“设备指示灯”和“系统处于待机或运行中”。RGB 能支持外观发光，不能证明设备类型、运行状态或“刚亮起”的变化。应把它记为待校准的状态推断，不能将全部 JSON 内容都算正确事实。

## 结论与下一步

场景视觉传输、单图理解、带图自主预判，以及一次短程真实行走与冷角色视觉请求并发，已得到运行证据。当前可以继续小范围用户试用，同时推进下一批；不需要新增第二个语言模型。

本次使用保存图像、现有隔离行走夹具和受控跟随指令，不是 Qwen 根据图像发起了该行走；没有同时启用实时相机渲染、ASR/TTS，不能作为完整 VR 场景或长期负载保证。仍没有 live TV 读屏、自主转头、物体空间定位或跨高度执行的验收结论。本轮未改生产行为代码、用户场景或模型配置，只补充探针与证据。
