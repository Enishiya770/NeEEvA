# 短句停止、分段行走与持续跟随

这轮承接房间呼唤试用：同层短距离走近已可用，但路程容易在用户完成“停一下”的语音处理前结束。实现重点是保留明确停止指令、并行准备意图、延长同层可执行路线，以及让跟随成为持续任务。复用现有 Qwen、adapter 和 ARDY，没有增加语言模型或继续训练权重。

## 现在如何测试

退出主场景的 Play，等 Unity 编译完成，再进入已经配置好的房间聊天场景。在 **Tools → NeEEvA → ARDY Room Dialogue** 确认角色、房间和桌面相机已连接。不要同时绑定旧的点选移动窗口。

1. 说“跟着我走”，沿同层空地用桌面相机缓慢移动。角色到附近后会等待；再次拉开距离时继续跟随。
2. 行走中说“停一下”或“不用再跟着我了”。停止后继续移动相机，确认角色没有重新跟上。
3. 再发起跟随，说“不要停，继续跟着我”，检查否定是否保留。普通聊天也应保留跟随。
4. 找到同层、可达且较远的位置，说“来我身边”。较长路线现在可拆成多段，不再因超过一个 10 秒生成窗口直接失败。

ARDY 8093 与 SenseVoice 9881 已单独重载。以后重新开机仍使用 `start_all.cmd`。Qwen 未重启，主 Unity 场景未因验证被打开、修改或重新保存。

## 停止链路

日志确认原来的一次“停一下”已经被完整 ASR 识别正确，却被“短句、未知情绪、非 owner 声纹”的组合规则拒绝。此次保留原过滤，并用同一录音的稳定闭合文字及原始语音证据处理误拒，详情见 [短语音证据说明](ardy-closed-speech-recovery-20260912.md)。回声、未知拒因、不同终稿修订和过期录音不能据此恢复。

录音确认结束后，允许同一 Qwen 在完整 ASR 处理期间准备结构化空间意图。只有同录音、同原话的终稿确认后，停止才可提交。它直接作用于绑定的空间任务，不等角色组织台词及语音合成；正式回复复用该决定。无法提前确认时回到正常决策流程，普通开口不会自动取消行走。此机制缩短串行等待，并没有消除录音收束、ASR 与模型计算本身的时间。

独立任务的停止绑定执行版本；持续跟随的停止绑定父任务，允许同一个任务内部切换路段。另一个任务、外部替换执行或新的用户输入仍使旧预备失效。预备请求超期或被取消时不能永久挂住正式回复。

## 分段与跟随

每次 ARDY 请求仍最多 200 帧、20 fps。较长路线先规划连续目标时间轴，保留当前段已经审核过的停稳尾，再提前生成下一段。续段明确使用已审核的生成姿态作为历史，接缝经过根位移和关节连续性检查后追加到同一个播放器；正常续段不释放身体控制，也不插入待机。

如果续段未及时到达，角色播放当前已审核的减速尾、停稳，重新采集实际姿态再规划，最多两次。超时结果不能在旧预测姿态上接着播放。每帧障碍物检查、完整新段路径检查、终点和朝向检查继续生效；没有放宽台阶、跨层、支撑面或家具碰撞条件。连续目标时间轴目前上限 120 秒，单次 HTTP 上限仍是 10 秒。

跟随在距离拉开到期望距离加 0.45 米后准备下一次走近；用户水平移动超过 0.35 米时使旧目标失效，重新提交至少间隔 1.25 秒。`follow-waiting` 是仍在跟随、等待用户移动；`follow-paused` 是路线暂时未通过，等待新位置再检查。几何不通过不会在同一个位置无限重试；支撑面、绑定或服务失效会结束本次跟随。快速连续移动可能表现为多次停步和重新规划，目前没有预测追赶。

## 验证范围

统一证据目录：`Server/ARDY/runtime/room-stop-follow-20260912/`。最终源码与报告对应关系记录于其中的 `verification.json`。

- 隔离的实际房屋、实际 VRM/Animator 与 ARDY HTTP：连续两段抵达、第二段停止、故意错过续段期限后的实际姿态重采集，以及等待中外部停止不重启。连续抵达样本的终点误差约 2.1 厘米，源接缝位移约 1.2 厘米、最大源关节接缝约 3.2 度。
- 实际跟随：生成中用户换位置使旧段取消，产生新执行版本；明确停止后无重启；生成行走到用户附近后保持等待，普通聊天不撤销任务。
- 实际 ChatSample 入口与受控模型回调：终稿前无动作权限，匹配终稿后停止一次，否定和引用保留，旧录音、新任务与替换 provider 的结果失效；正常输入交接与超时回退另有回归。
- 同一 Qwen 的固定公开探针保留原有 14 例，并增加短句停止、否定、引用、跟随及等待台词审核。测试结果不代表任意语言或真实语音的成功率。

分段运行用合法的 0.15 米/秒测试速度在已通过的短路径上跨越生成窗口；默认速度仍为 0.65 米/秒。这验证分段与取消的生命周期，没有覆盖房间所有较长几何路线。取消瞬间的姿态自然度、持续快速跟随效果及真人语音到停步的实际延迟仍需主场景试用；本轮不将模拟语音证据当作麦克风验收。


最终记录：`integration-v2` 的 11 个既有移动场景通过，包含 77 项原闭环、48 项跟随状态及 67 项短语音交接检查；`extended-v1` 的四个实际分段场景及实际跟随回归通过。分段与跟随生产源在最终交接修正期间未改变，147 份主项目/隔离 C# 源码及最终程序集已核对。基础回归另含 57 项闭合语音、1356 项分段目标与接缝、612 项目标构造检查。

`qwen-v4` 保留全部 24 次请求：24 项运行时判断满足预期，20 项原始字段完全符合约定；4 项无空间动作输出附带了合法的用户引用，由现有严格来源检查归一化为无动作。没有将这四项计入原始格式通过。早期 `qwen-v1` 在新 ARDY 首次特征核验前退出，未发送模型请求；`qwen-v2` 暴露的是测试器漏列 follow，以及将“继续跟随”过度限定为只能 none，两种问题均已修正并保留原报告。明确继续一个已有跟随任务可以是 none 或幂等的 follow，均不能变成 stop-moving；`qwen-v3/v4` 使用相同的最终案例哈希。

补充复核还修复了两个真实衔接问题：正式用户输入重置内部工作轮次，使已准备的决定丢失；预备请求无回调时使正式回复永久等待。最终回归使用真实的“设置输入→更新用户轮次”顺序，并覆盖超时、晚回调、禁用及 provider 替换，没有用简单的 mock 直接跳过这段交接。
