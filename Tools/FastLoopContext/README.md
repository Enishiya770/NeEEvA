# FastLoop input/context and semantic regression

`run-regression.ps1` compiles the actual `FastLoopPrompt` and `FastLoopProtocol` with the project's Newtonsoft.Json DLL. It checks accepted-input separation, preservation of multiline/current-user endings, paired dialogue history, nonmutation, bounded observations/Unicode, and the production HTTP envelope parser. These deterministic checks do not measure model understanding or Unity action execution.

`test-model.ps1 -ExportOnly -OutputDirectory <path>` writes 24 semantic cases without network calls. The export uses the actual persona/language files and production prompt/schema factories, with synthetic runtime observations matching the production shape. It does not insert a second correction prompt. The current user text is preserved without truncation; historical/observation fields are bounded separately.

After coordinating a model test window, `test-model.ps1 -OutputDirectory <new-path>` sends cases sequentially to the configured existing Qwen endpoint, using 256 output tokens, temperature 0, thinking disabled and a 20-second request timeout. It decodes original response bytes as UTF-8. `summary.json` evaluates responses with the exact production envelope/protocol parser, records latency, and includes each case's semantic rubric.

Allowed-route counts are deliberately not a dialogue-quality score. A character may refuse a proposed action; a `reply` must then express a genuine refusal or necessary clarification, rather than ignore the request, pretend an unavailable capability, or claim an unexecuted action succeeded. Each result needs a separate semantic review. The fixture does not execute a skill, play audio or move an avatar. It does not test images; vision-without-attachment cases only test evidence limits.

Production integration calls `FastLoopCurrentUserText(originalPrompt)` before building context, and validates evidence against that same result. The helper binds auditory observations to the current generation/work epoch and exact accepted input snapshot. Nonmatching direct/synthetic prompts, autonomous ticks and empty continuations retain their supplied text. `EnrichFastLoopContext` projects local capability/skill/work/material state without service calls or execution authorization. Existing SenseVoice `Describe*` APIs can lazily assign an already retained recording's missing sequence ID; they do not retain a new recording, load a model, select a playable range or grant playback permission here.

The 2026-09-26 context regression additionally replays `latest-session.json`: actual final inputs and the four observed speech/singing/tail segments from captures 19–24, with synthetic in-memory clip identities. `TimeOrderedObservation` bounds the timeline to six segments, retaining beginning, ending and up to two singing candidates. `RecordingMaterials` retains at most six context rows: up to two exact active-goal references, up to two recent bound singing observations, then recent recordings. The runtime singing-observation cache has at most two entries within the existing 16-user-turn history window, and is cleared/pruned on provider/session/inventory changes. None of these operations chooses source, playback range, revision or authorization. The original complete current-user text is never shortened.

`run-regression.ps1 -ExportSession <path>` or `test-model.ps1 -LatestSession -ExportOnly -OutputDirectory <path>` exports nine controlled current-session cases, including dialogue-repair prompts. The current production prompt/schema and pure projection functions are used. The runtime facts are a controlled fixture, not an exact captured online request; the source log SHA and this limitation are retained in the export. `test-model.ps1 -ProtocolPath <export> -OutputDirectory <new-path>` can execute a separately exported cohort after obtaining a coordinated model window. `export-history-ablation.ps1` produces reproducible historical-speech-only experiments; none of those alternate history shapes is enabled in production. `-TypedQuotes` selects the last bounded experiment. The first exploratory ablation used a different top-level JSON order; the `*-ordered` artifacts include unchanged, byte-identical message controls and must be used for the controlled comparison.

`Assets/Editor/FastLoopContextRegression.cs` exposes `RunOrThrow()` and `RunBatch()`. It uses inactive actual `ChatSample`/`SenseVoiceSpeechToText` components, neutral retained synthetic WAVs and unvoiced pitch evidence to exercise real source/recording identity, generation/epoch fencing, complete endings, candidate19 retention, and absence of source/range promotion. It never opens a microphone, runs a model, plays sound, starts a service or saves a scene. A new capture with identical words must not inherit the previous capture's segment array. `RunBatch` writes `Logs/fast-loop-context-regression/unity-context.json`; the root repair runner can call `RunOrThrow` in its isolated Unity build.
