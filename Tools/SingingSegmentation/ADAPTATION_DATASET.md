# 可选的 36 段独立验收计划：歌声分段轻量适配

日常个人学习已经有[项目内采集、确认与后台训练入口](../../docs/personal-singing-learning-20260929.md)，不要求用户先在项目外完成这 36 段。本文件保留为后续需要固定训练／验证／盲测材料时的实验计划；普通用户可直接在 NeEEvA「声音学习」页积累和纠正交互录音。

目标是减少回唱中混入讲话，同时保住实际歌声。先做单用户、当前设备的离线 pilot；36 段不能证明跨用户、跨设备可靠性。
本清单不是已采集数据。不会开麦、录音、训练或自动填写人工标签。现有七份仅作 dev，用户现在无需重新标注它们。

机器可读清单：`work/singing-subsystem-20260929/segmentation/score-adaptation-20260929/collection-plan.json`。
每条 `planned_id` 只是预留槽位；真实场次、父录音、WAV 路径、`source.sha256` 和采样参数均等实际录制后填写。

## 1. 先固定内容族和 split

| split | 内容族 | 同句朗读/演唱/混合 | 难讲话控制 | 环境/声源控制 | 合计 |
|---|---|---:|---:|---:|---:|
| train | T-ZH-1、T-JA-1、T-ZH-2、T-JA-2 | 12 | 3 | 3 | **18** |
| validation | V-ZH-1、V-JA-1 | 6 | 1 | 1 | **8** |
| blind | B-ZH-1、B-JA-1 | 6 | 2 | 2 | **10** |
| 总计 | **8 个内容族** | 24 | 6 | 6 | **36** |

- ZH / JA 分别为中文 / 日语；每个 split 都同时含这两种语言的朗读和演唱。
- 用户为每族自选或自写一段短句、歌词及旋律；清单不指定任何受版权歌词。
- **同一歌曲、旋律或歌词的不同段落、重唱和朗读始终同 split。** 不用同一歌的第一段训练、第二段盲测。
- 每族 R / S / M 三份是各自开始、结束的真实录音。不要从同一长 WAV 切成三份后当独立样本。
- 父录音、拼接来源、裁剪、重采样、增强、外放用到的原素材与其衍生录音继承相同 split。
- 实际录制场次也不得跨 split；计划中的 A / B 是待落实的场次槽，不是真实 session ID。
- 同一 split 可分两次短场次完成；各 split 保持相近的日常设备与环境，不故意让训练安静、盲测全噪声。
- 若后来发现两个内容族其实同歌或同父录音，先隔离冲突；整组重新安排或补录，不挪单个片段凑计数。
- 禁止随机拆帧、相邻窗口或同源片段做训练与验证。清单分配在录制和看模型结果前固定。

## 2. 每个内容族怎么录

| 后缀 | 指令 | 参考长度 |
|---|---|---|
| R | 自然朗读同一段文字，保留正常呼吸和停顿 | 10–25 秒 |
| S | 自然唱同一段文字，可自编旋律，保留真实首尾和句中停顿 | 10–25 秒 |
| M | 普通语气说引子，直接唱，再自然说收尾；不要人为插入静音方便切分 | 15–35 秒 |

尤其需要 **没有明显静音的说→唱、唱→说**，以及唱中正常换气。无需夸张表演或故意把边界放在整数秒。
轮换各族 R / S / M 的录制先后，避免“每三段必定第三段混合”的固定顺序成为额外线索。
长度仅是采集参考，实际说唱由人听音标注；任务指令不能自动转换成真值。自然失误保留，不为了凑标签反复挑最好的一次。
如需重录，保留原件并填写 retake 的共同来源/内容族；不要把重录件放到另一个 split。

## 3. 其余 12 段怎么录

| 槽位 | 内容 |
|---|---|
| T-H-1 / V-H-1 | 分别用中文 / 日语有感情地朗读对应族短句，可有拖音和反问语调 |
| T-H-2 / B-H-1 | 分别用日语 / 中文普通讲话谈演唱、重来或纠正，可朗读族内短句 |
| T-H-3 / B-H-2 | 分别用中文 / 日语说明稍后会唱，并普通朗读文字；本段不按计划真唱 |
| T-E-1 | 本人安静，记录日常环境底噪和轻响 |
| T-E-2 | 本人安静，外放同 split 自己的中文讲话 |
| T-E-3 / B-E-1 | 本人安静，分别外放同 split 自己的日语 / 中文歌声 |
| V-E-1 | 本人中文讲话，同时外放同族自己的歌声 |
| B-E-2 | 本人日语演唱，同时外放同族自己的普通讲话 |

难讲话约 10–25 秒，声源控制约 10–25 秒；使用日常音量和麦克风位置，记录外放素材真实身份。
**外放歌声仍是声学上的 singing，不能为了防回声而标成非歌唱。** “是否用户本人正在唱、能否成为回唱素材”是独立 source gate。
E 类结果单列报告；多人声重叠、主次声源和素材授权不交给二分类头独自解决，也不能靠这几段宣布回声问题已解决。
听不清重叠区就标 uncertain；不要为了类别平衡强行决定 speech 或 singing。

## 4. 录制后的身份登记

1. 保存未经裁切的原 WAV。现有标注工具接受无压缩 PCM16；不要覆盖高精度原件，如需转换应保留原件与转换来源关系。
2. 在清单副本填写实际 `session_id`、`parent_recording_id`、录制时间、内容族和原素材关系。独立录制也应分配可追溯的根录音 ID。
3. 从文件字节计算 `source.sha256`，读取实际采样率、样本数和声道数；不能用文件名、ASR 文本或预测结果充当身份。
4. 对外放样本补 `playback_source.recording_id / sha256`，人工记录实际声源；预定的 `planned_source_condition` 不是已验证事实。
5. 检查同内容/父录音/真实场次的连通来源组是否跨 split；做完全 hash 去重并查来源重叠，不只比较文件名。
6. 仅完整登记的录音可进入导入 manifest。保留清单版本与 hash，未录制槽位继续 null，不生成占位音频。

## 5. 用现有标注工具导入

分别生成 train、validation、blind 的 JSON 数组 manifest；每项只含 `id`、`wav`、`sha256`：

```json
[{"id":"T-ZH-1-R","wav":"<真实原 WAV 绝对路径>","sha256":"<实际 source.sha256>"}]
```

尖括号只是格式示例，不可直接运行。不要把采集指令、预期标签、ASR、模型预测、旧裁剪或对话传给标注页面。
各 split 使用独立 dataset ID 和新输出路径；实际文件准备好后可运行：

```powershell
python Tools/SingingSegmentation/build_annotation_tool.py --manifest <train-manifest.json> --dataset-id singing-adaptation-pilot-36-v1-train --output <新目录/train-annotate.html>
```

validation / blind 对应替换 manifest、dataset ID 和输出名。`--dataset-id` 已支持；省略时仍保留旧七份 ID，仅用于原批次兼容。
生成器检查 WAV 字节 hash，按真实份数显示标题，生成页面及 `.manifest.json` 身份审计；不写默认标注。
本次不生成真实新录音页面，不覆盖或刷新已打开的 `annotate.html` / `annotate-v2.html`，也不创建网站服务。

人工只听原音频，用现有 speech / singing / uncertain 三类标注全部原样本，填写两端容差后逐份确认复核。
环境音不能冒充 speech；工具中可记 uncertain，若人工明确“非歌唱但不确定细类”，另存带来源坐标的确认，不擅改三类 schema。
未标空白不算非歌唱；`uncertain` 不自动作为负类。实际源身份、边界容差和未决区一起进入验收。
导出后由 `annotation_core.importDocument` 对对应页面 dataset 校验；同时检查覆盖、复核状态、原点 0 和整数半开样本坐标。
跨 dataset、manifest 或 WAV hash 的标注必须拒收；修改音频后要建新身份，不能沿用旧样本坐标。

## 6. 调参与盲测边界

- 现有七份与模型输出已经被查看，全部只作 dev；此前同源冲突及其环境音确认保留，用户无需重做七份。
- 训练只用 train。特征、标准化和拟合不得看 validation / blind；validation 可选阈值与后处理，但明确它已参与选择。
- **blind 人工标注期间禁止展示声学预测**，也不显示 ASR、对话解释或任务的预期类别；先保存人工标签及 hash。
- 盲测解封前冻结候选版本、特征、阈值、后处理和验收规则。第一次结果原样报告；不能看完盲测再调参仍称独立验收。
- 报告明确 speech 的混入时长/比例、全部已确认 non_singing 的混入、真实歌声保留率和整段拒绝率；E 类声源结果单列。
- 分别报告中/日语、无静音混合段及容差带外的首尾偏差，不能用“全部拒绝”或语言捷径换取表面高精度。
- 少量内容族只支持 pilot 结论。盲测失败后本批成为下一版回归数据，下一次验收另留新内容族和新场次。

生成器的定向验证为 `test_annotation_generator.py`：三份合成 WAV 的独立 ID/真实数量、hash 拒绝、跨身份导入拒绝及旧默认七份兼容；不播放音频、不创建真人标签。
