# Role-draft intentions and persistent waiting tasks

This suite tests a different source of intention from input routing: the character's own unpublished draft. A user can say only "嗯", while the role draft decides to turn right. Its evidence must be drawn from that draft. A separate event classifier reads accepted final user input to advance an already registered counting condition.

There are 95 semantic cases in cases.jsonl: 82 draft intentions and 13 input events. The latest 24 reproduce the 12:34 session lamp/follow/approach drafts and multilingual proposal/refusal/quotation/completion contrasts. They include the original 32 development cases, eight earlier held-out cases, seven visual-perception controls, six exact evidence excerpts from the 2026-09-26 conversation, twelve multilingual held-out contrasts, and six implicit acceptance/refusal/quotation contrasts. The original suite includes the observed drafts "了解，这就把视线移向右边。" and "我会保持现在姿势，等你数完三再低头。", false completed-action claims (head, singing and walking), quoted actions, negation, autonomous role choices, unsupported waiting conditions, Chinese/Japanese counting, and quotation of numbers. The new contrasts distinguish perception and ordinary listening from actual head position, singing, walking and recording-tool proposals. Their wording is not copied into the production prompt. Allowed alternatives identify cases where different head labels describe the same held pose; report these separately from exact cases.

Actor intention uses strict **version 3** with a required `domain` field: `dialogue`, `perception`, `head`, or `other_action`. Dialogue/perception can only be `none`; head can act, wait, claim, cancel or replan; other actions use `replan` for an adopted or future task and `claim` for an already completed or ongoing execution fact. Required `task` is none/approach/follow/other and `target` is none/current_user/other. Only a single approach or continuous follow of the current user can use those two task values, with target=current_user. Specific objects, singing and compound goals remain task=other for full planning with the original draft/evidence. Head and non-action domains require task=target=none. The latter requires `task=target=action=condition=none`, and nonempty evidence from the role draft; it authorizes only checking corresponding execution records, never performing an action to make a past claim true. Every JSON-schema alternative independently declares all fields because the production structured-output backend must not depend on inherited branch properties. Old version 1/2 intentions and wire objects missing task/target are rejected rather than inferred. Program-created DTOs default Task/Target to none for existing bounded head decisions, but other-action proposals must set an explicit task. The independent counting-event protocol remains **version 1**. Structural validation prevents contradictory domain/kind/action combinations; it cannot prove that the model chose the correct semantic domain. Real-model evaluation remains necessary.

Run deterministic protocol and lifecycle checks without a model or Unity:

    powershell -NoProfile -ExecutionPolicy Bypass -File Tools/ActorIntent/run-regression.ps1

The runner compiles the actual pure production protocol, head-task and waiting-task classes with the project's Newtonsoft DLL. It checks strict JSON, bounded fields, draft evidence instead of user evidence, replayed drafts, stale revisions, false completion claims, verification-only other-action claims that cannot create or replace head/wait tasks, source identity and a persistent wait sequence across accepted inputs: one, irrelevant dialogue, two, three. It also checks duplicate and out-of-order events, pre-registration events, wrong task callbacks, cancellation and replacement, complete counts in one utterance, and exactly one trigger. Triggered head actions retain their original role-draft identity rather than substituting the counting user's input.

A new role draft that reaffirms the same pending action must preserve the accepted count, task identity, original draft and original event boundary. A different action replaces the wait. Cancellation does not allow the old source to rearm; a fresh draft can establish a new wait for the same action. Regression checks ensure late original/reaffirming drafts and callbacks cannot take ownership back from a replacement.

The expected JSON inside these fixtures is supplied test data. Passing fixture parsing does **not** demonstrate language understanding or model accuracy. Persistent runtime checks do not demonstrate physical Unity movement, audible speech, or actual recognizer segmentation.

To explicitly perform the real model evaluation:

    powershell -NoProfile -ExecutionPolicy Bypass -File Tools/ActorIntent/test-model.ps1

Defaults match the existing Qwen service at http://192.168.114.175:8888 and model qwen3.6-35b-a3b. The runner sends all 95 cases sequentially with 192 output tokens, temperature zero, thinking disabled, and a 20-second request timeout. BaseUrl, Model, TimeoutSeconds and OutputDirectory parameters can override these settings. It does not start, stop or reconfigure services or send actions into Unity. Coordinate an exclusive model window when another agent is measuring latency or driving a live Unity fixture.

`-Scope draft` or `-Scope signal` selects a cohort and saves that exact denominator in the run's exported protocol. `-ProtocolExport <path>` explicitly tests a previously prepared candidate export without modifying production sources; `run.json` records that source. A candidate run is not evidence for production until the same prompt and schema are landed and compared with a fresh compiled export. Do not repeatedly fit the held-out cases after seeing their answers.

The model uses the production ActorIntentProtocol.SystemPrompt, SignalContract, BuildUser, and corresponding ResponseFormat factories exported by the compiled harness. There is no independent handwritten classifier prompt. Draft and event requests use their distinct production schemas and evidence sources.

Each run records the exact requests, complete response envelopes, raw model content, usage and complete request latency. Saved responses are validated for one assistant message, finish_reason=stop, no unexpected tool/function/refusal channel, and the actual production parser. Results are written to summary.json and parsed-results.jsonl, including protocol validity, exact draft domain/kind/task/target/action/condition agreement, signal agreement, and p50/p95 latency. Per-row and summary executionCompatible additionally accept harmless dialogue-versus-perception differences (both none) and target-label differences when both results are generic other_action/replan/task=other and retain the full source for planning. Known-task shortcuts, wrong head actions, invented conditions, claim/act and negation/cancel disagreements are never excused. This classifier-stage metric does not replace strict semantic accuracy or prove actual execution. Ambiguous allowed sets are reported separately from exact cases. Free evidence substrings are accepted only if the production parser verifies their proper source.

Summary bySplit separates development and heldout agreement. Summary byScope separates draft classification and input-event classification, each with its own p50/p95 request latency; bySplit also contains these scope-specific figures. Mixed overall latency remains for historical compatibility and should not replace the two operational latency figures.

Response bytes are saved per case and decoded directly as UTF-8. The runner does not use Windows PowerShell's predecoded Content string, which can corrupt Chinese when the server omits a charset. Only HTTP 200 responses qualify for protocol acceptance. Any historical run with corrupted transport decoding is invalid measurement evidence, not a model-language failure.

Evaluation reads the immutable case expectations exported for the run, so later fixture edits do not change an older run's denominator. The current parser intentionally rejects v1/v2 actor responses; compare historical results with their recorded protocol version rather than presenting a schema-version mismatch as a new model failure. To evaluate stored responses without any network calls:

    powershell -NoProfile -ExecutionPolicy Bypass -File Tools/ActorIntent/run-regression.ps1 -ModelResults Logs/actor-intent-model-YYYYMMDD-HHMMSS/responses.jsonl

This is a targeted regression suite, not a broad benchmark. Requests that informed a prompt change become development evidence for that revised prompt. Report prompt changes and evaluation cohorts rather than treating fitted examples as untouched test accuracy.
