# Generalization evaluation v1

本套件在任何特征导出、动作生成或训练结果查看之前冻结：80 条全新英文动作描述、40 个语义配置组，每组一条直接指令和一条自然叙述。它由评估代理编写，标签描述期望行为，尚不是人工确认的动作成功标注。

- `generalization-eval-v1.jsonl`：兼容现有 `read_records`，全部 `split=test`。
- `generalization-eval-v1.groups.json`：配置、规范签名、训练排除政策及指标词表。
- `generalization-eval-v1.validation.json`：仅 CPU 静态校验及文件 SHA，不含模型表现。

32 组／64 条属于本轮原地上身支持范围，覆盖左右单臂、双臂、不同高度与方向、头和躯干、同时组合、先后顺序、次数与停顿。8 组／16 条明确属于能力边界：物体操作、精细手指、准确自接触、腿部移动及物体动力学。边界组 `include_in_success_summary=false`，单独记录是否说明限制；不能把近似姿态当成功，也不能混进支持范围的失败率。

主统计单位是语义组。两种改写以及多个随机种子嵌套在同一组内，不应被当作独立能力证据。`canonical_signature_sha256` 对 `side/bodypart/action/count/target/temporal/range` 七个字段的规范 JSON 计算 SHA256。完全相同的动作配置、同义改写和翻译不得进入新训练或验证集。允许共享原子动作类，但该实验测的是保留配置与组合的泛化，不是从未见过的动作大类。旧 2000 条数据保留原样；其中泛化的原子描述可能与这些动作有宽泛语义重叠，不能声称完全没有既有先验。

训练排除须同时检查签名和人工语义。别名、默认姿势、未明确写出的次数或停顿，可能让不同签名仍然含义等价。不要只改 `semantic_group` 名称就视为无泄漏。冻结后不要根据本套件的生成结果调整训练样本、超参数或阈值；模型选择应使用独立开发集，最终审计一次，后续迭代另设新版本测试。

四条先前的 `raise-actual / explain-actual / raise-style / explain-style` 属于 **seen-diagnostic**，保持其原文件不变，且不并入本套件。训练排除这四个原句，但允许其他双臂过头及解释动作语料；该已知问题的改善只能作为回归证据。不要把上述政策误读为禁止训练整个双臂动作类别。

`assessment.machine_observations` 是明确标注的必要观察，不从自然语言猜指标。腕高使用世界 +Y 的腕关节高度减参考关节高度；肩高 ±0.12 m 与过头 +0.05 m 只是粗略骨架门槛，不证明姿势自然、手已高于实际头顶、掌向正确或事件完整。腕活动量不预设通过阈值。头部旋转相对上胸，躯干旋转相对骨盆。次数按所述完整事件／往返周期计算；未实现的事件检测应标 `manual_pending` 或 `unknown`。

每条 `automatic_semantic_pass=false`；整体语义成功在人工审查前应为空值。自然度、掌向、肘形、停顿、顺序、非目标肢体动作及穿插都需要检查。保存实际源姿态、固定种子与历史、模型／特征契约、原始输出和测量结果，避免仅凭向量余弦或腕高宣布成功。

本套件的输入层是 `motion_description`。它检验条件到动作的泛化；对话中是否恰当自主触发动作、中文意图解析、TTS 隔离和打断生命周期应另外评价，不能从这里的动作成绩推断。
